# Proposal

## Why

模块一的数据与标的基础能力即使后端和数据库设计完整，如果在若依前端没有清晰、低输入、可恢复的操作入口，普通用户仍会被接口授权、交易日历、数据质量、标的身份和 Dify 技术细节阻塞。当前前端基线已确定为 plus-ui/RuoYi-Vue-Plus，但量化页面、数据健康工作台和 Dify 研究触发入口尚未形成统一的页面设计与用户操作契约。

## What Changes

- 生成模块一用户操作界面落地设计文档（`design.md`），覆盖 plus-ui 页面结构、路由/菜单、页面信息层次、角色权限、状态卡、加载/空/错误/过期/授权/降级状态和 API 映射。
- 设计以下核心页面：
  - 量化工作台/数据健康驾驶舱；
  - 数据源与来源组管理；
  - 数据质量问题与处理；
  - 标的中心与标的详情；
  - 交易日历、交易时段与日线就绪；
  - 行情与数据日期页面；
  - 研究任务、AI 草稿、证据链和研究事件；
  - 受控研究问答/研究助手入口。
- 固化三种体验模式：引导模式、审核模式、专业模式；普通用户默认看到“结论—原因—影响—下一步”，专业配置和原始字段按权限渐进展开。
- 说明 Dify 的用户触发方式：
  - 研究任务页的“开始 AI 研究”；
  - 新闻/材料详情页的“提取事实/分析影响”；
  - 标的/日历/数据质量详情页的“用当前证据解释”；
  - 全局研究助手入口；
  - 浏览器不直接调用 Dify，所有请求先到 Spring Boot，Dify 结果显示为草稿，必须经过校验/审核。
- 设计可恢复的用户流程：数据未就绪时等待、质量问题修复后继续 GuidedTask；任务失败可查看原因并有限重试；AI 草稿和核验事实不可混淆；Paper 前置不合格时不给绕过入口。
- specs 中以可验证 WHEN/THEN 场景覆盖管理员、审核用户、引导型普通用户的关键操作路径和 Dify 触发/降级路径。
- 本 change 只生成 UI/交互设计、行为契约和实施任务，不实现 Vue 页面、API、Dify、数据库或后端代码。

## Capabilities

### New Capabilities

- `data-foundation-ui`: 数据与标的基础在 plus-ui/RuoYi 前端中的页面信息架构、导航、状态展示、权限和操作契约。
- `data-foundation-guided-journeys`: 面向引导/审核/专业用户的数据健康、质量处理、标的/日历检查、研究任务和 Paper 前置的可恢复用户旅程。
- `dify-ui-entry`: Dify 研究助手在前端中的受控触发、草稿展示、引用回源、状态轮询/降级和安全边界。

### Modified Capabilities

（无——当前仓库根 `openspec/specs/` 为空，本 change 新增 UI 行为能力。）

## Impact

- **前端**：`plus-ui/src/views/quant/*`、`plus-ui/src/api/quant/*`、路由/菜单/权限事实源、公共状态卡/证据抽屉/引导任务组件。
- **后端契约**：数据源、质量、标的、日历、行情、研究任务、Dify 草稿、研究事件和问答 API；前端不直连 Dify。
- **权限**：复用 RuoYi Sa-Token 菜单/按钮权限，增加数据管理员、研究审核、普通研究用户和专业查看权限映射。
- **用户体验**：低输入、普通语言阻断提示、渐进披露、数据日期/时区明确、Paper/真实交易隔离提示；一期只展示日线业务能力，不提供分钟/Tick 盘中交易界面。
- **安全**：Dify Key、数据库凭据、供应商 Token 不进入浏览器；AI 草稿不得被 UI 伪装成事实、信号或订单。
