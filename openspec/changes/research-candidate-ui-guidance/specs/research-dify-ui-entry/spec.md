# Spec Delta

## Purpose

定义研究型 Dify（事件影响分析、资产研究解释、研究卡说明、研究问答、复盘摘要）在前端的受控触发与展示：所有请求经 Spring Boot、浏览器不接触 Dify 或凭据，结果以草稿呈现并支持引用回源与降级。

## ADDED Requirements

### Requirement: Dify 入口经 Spring Boot 且浏览器不持凭据
系统 SHALL 通过研究任务页、材料/标的详情、研究卡页与全局研究助手触发研究型 Dify，前端只请求 Spring Boot 研究接口；不以 iframe 嵌入 Dify、不直连 Dify API、不在浏览器保存 Dify/API Key。

#### Scenario: 前端触发研究型 Dify
- **WHEN** 用户在研究卡页点击"用当前证据解释"
- **THEN** 前端向 Spring Boot 发起请求，由服务端注入凭据调用 `RESEARCH_CARD_EXPLANATION`，浏览器不接触 Dify 或 Key

### Requirement: Dify 结果以草稿呈现并区分事实/解释/未知
系统 SHALL 将 Dify 返回的事实候选、影响变量、传导链、反方问题与研究卡说明以草稿呈现，明确标注"AI 草稿/待核验/已核验事实/未知"，未经校验不得显示为事实、信号或已批准结论。

#### Scenario: 影响分析草稿待核验
- **WHEN** Dify 返回事件影响分析草稿
- **THEN** 页面标记"AI 草稿/待核验"，展示引用缺口与审核入口，不把方向候选显示为已验证方向或交易信号

### Requirement: 草稿可回源到证据
系统 SHALL 让研究型 Dify 输出中的每条事实候选/引用可回源到来源、材料版本、原文片段与时间，回源失败时明确标注，不得显示为已核验证据。

#### Scenario: 解释草稿回源
- **WHEN** 用户点开研究卡解释中的引用
- **THEN** 页面展示来源、材料版本、原文片段位置、发布时间与可见时间，无法定位时标记为待核验而非证据

### Requirement: 研究问答不绕过门禁
系统 SHALL 让研究助手先由 Spring Boot 查询授权范围内结构化结果，再交 Dify 组织带引用回答；回答必须区分事实与解释，缺少候选时明确说明原因，且不得把"可建仓"等结论绕过策略、风险或 Paper 门禁。

#### Scenario: 问答无候选
- **WHEN** 用户提问"今天有无研究候选"且当前门禁下无合格候选
- **THEN** 页面回答"当前没有满足门禁的机会"及原因，不虚构候选、不给出绕过门禁的操作建议

### Requirement: Dify 降级可见且可操作
系统 SHALL 在 Dify 不可用、限流或持续超时时显示降级状态，研究型按钮变为"稍后重试/查看结构化数据"，确定性候选、研究卡与既有结果继续展示，不伪造分析结果。

#### Scenario: Dify 不可用
- **WHEN** 研究型 Dify 服务不可用或达到降级阈值
- **THEN** 相关按钮显示"稍后重试/查看结构化数据"，页面保留确定性研究卡与数据，不显示伪造解释或空白
