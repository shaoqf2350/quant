## 1. 国内量化背景、市场环境与监管边界

### 1.1 国内量化背景与参考对象

当前市场上的量化选股和交易工具通常只解决其中一部分问题：

```text
新闻阅读
财报/研报阅读
行业研究
商品供需研究
量价分析
盘口观察
技术策略
回测
预警
复盘
组合风控
```

用户如果想独立完成完整交易流程，通常需要同时具备财务分析、行业研究、市场交易、技术分析、期货规则和风险管理能力。信息数量多、专业门槛高、时间要求高，而且人工判断容易产生确认偏误、追涨杀跌、事后解释和策略临时改变。

本系统参考观潮公开展示的“筛选、策略验证、预警、盘中研究、盘后复盘”工作流，也参考 HOLDLE 公开展示的“选好、等好、管好”方法论；同时结合股票基本面、新闻事件、商品供需、基差、期限结构、量价和期货多空交易需求，形成面向个人用户的多源信息交易研究系统。

参考对象只用于借鉴业务思想，不直接复制其指标、阈值、结论或未公开算法：

- 观潮：<https://guanchaotv.com/app/chart>；
- HOLDLE AI Assistant：<https://www.holdle.com/ai-assistant>。

### 1.2 国内市场监管与阶段边界

本系统所处的国内市场环境具有以下特点：

1. 股票、期货、现货的交易制度、可交易方向、交易时间、涨跌停/保证金、交割和数据口径不同，不能用一套无差别规则处理所有资产；
2. 国内程序化交易监管已经覆盖证券市场和期货市场，监管关注点不仅是高频交易，也包括通过计算机程序自动生成或下达交易指令的中低频程序化交易；
3. 证券市场《证券市场程序化交易管理规定（试行）》自 2024 年 10 月 8 日起施行，强调报告管理、先报告后交易、交易监测、信息系统管理和高频交易差异化管理；
4. 沪深北证券交易所已进一步细化程序化交易管理规则，相关实施细则均自 2025 年 7 月 7 日起施行；各交易所的具体报告、接入、监控和异常管理要求应以现行交易所规则为准；
5. 期货市场《期货市场程序化交易管理规定（试行）》自 2025 年 10 月 9 日起施行，明确了程序化交易报告、系统接入、风险管理、监测监控和期货公司核查等要求；
6. 证券和期货规则、交易所细则、数据授权条款和券商/期货公司接入要求可能继续调整，因此本总纲只记录当前阶段边界，不把某一日期的规则写成永久结论。

上述背景并不意味着本系统一期已经属于交易所程序化交易主体。一期可在本地平台使用模拟资金，根据确定性策略运行手动确认或受控自动 Paper 模拟交易，覆盖挂单/撤单、建仓/开仓、平仓、持仓管理和期货移仓；订单只进入平台内部 Paper 撮合，不接入交易所/券商/期货公司交易委托通道，不使用真实资金，本地模拟成交也不进入交易所撮合或结算系统。行情可由有权使用的数据源提供，但行情接入不等于交易接入。是否构成某项监管规则下的程序化交易，应以二期实际接入方式、委托链路、券商/期货公司安排和届时有效规则为准，必要时进行专业法律和合规评估。

二期如果从“研究与模拟”进入“自动实盘”，系统定位将发生实质变化：除交易策略本身外，还必须纳入交易账户接入、程序化交易报告/确认、系统测试、异常处置、日志留存、权限控制、数据和软件授权、券商/期货公司协议以及人工放行等要求。二期不是简单打开一个 LIVE 开关，而是一个需要单独立项、合规审查和安全验收的阶段。

参考依据（仅作背景索引，实际使用时以最新有效规则为准）：

- 中国证监会《证券市场程序化交易管理规定（试行）》：<https://www.csrc.gov.cn/csrc/c100028/c7480577/content.shtml>；
- 中国证监会《期货市场程序化交易管理规定（试行）》：<https://www.csrc.gov.cn/csrc/c100028/c7564353/content.shtml>；
- 深圳证券交易所《程序化交易管理实施细则》发布通知：<https://www.szse.cn/lawrules/rule/trade/current/t20250403_612770.html>；
- 上海证券交易所《程序化交易管理实施细则》：<https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml>；
- 北京证券交易所《程序化交易管理实施细则》：<https://www.bse.cn/jygl_list/200025383.html>；
- 沪深北交易所后续发布的程序化交易报告、实施细则和业务指引。

### 1.3 本系统阶段性背景结论

一期：研究辅助 + 候选筛选 + 机会提示 + 策略适配 + 平台内部模拟实盘（手动Paper/受控自动Paper） + 复盘验证

二期：在一期模拟实盘闭环基础上，另行完成独立合规、安全、数据/软件授权、券商/期货公司交易接入、报告/确认、系统测试和人工放行后，才可评估真实自动实盘；前置条件未完成前不启用真实委托

一期的成功标准不是“自动赚到钱”或“自动完成交易”，而是：用户可以在可追溯的信息和量价证据基础上，较低成本地发现候选、理解理由、等待触发、模拟执行、观察结果并复盘规则。系统应优先减少无依据交易、追涨杀跌、信息过时和策略临时改变，而不是追求交易频率。

### 1.4 本轮总纲审计结论

本轮审计确认：

- 国内量化背景、监管边界、一期模拟盘定位和二期自动实盘目标已经能够形成清晰的阶段叙事；
- 原 V3 的主要结构问题不是业务目标缺失，而是背景、业务目标、功能需求、详细技术设计和当前代码盘点混在同一目录中，容易使读者把“目标总纲”误读为“可直接实施和验收的详细设计”；
- V4 通过重新编排章节，把背景与痛点放在前面，把业务流程和功能模块放在中间，把 Java Spring Boot、Dify、数据模型和当前代码现状放在后面；
- 本轮补充的标的身份/公司行为/合约事件、数据授权与回溯、市场状态、交易容量、人工覆盖和三条业务流，属于总纲层的边界目标，不是本文件的接口或异常处理设计。

## 2. 用户痛点、行业痛点与系统要解决的问题

### 2.1 现有个人交易流程的核心痛点

个人投资者通常需要同时完成新闻阅读、政策判断、行业传导、财报和研报理解、商品供需分析、量价观察、盘口确认、策略选择、仓位控制、交易执行和复盘。目标用户中还包括团队内部人员及其授权熟悉人员：他们了解股票或期货的基本操作，但通常不是技术人员或金融分析人员，不应被假定能够独立完成专业研究、策略参数设置、仓位计算或风险建模。任何流程缺失或过度要求用户输入专业判断，都可能把一个看似合理的观点变成不可执行或风险不可控的交易。

主要痛点包括：

1. **信息分散且专业门槛高**：新闻、公告、财报、研报、库存、现货、基差、期限结构和行情数据分散在不同来源，普通用户很难逐一阅读并判断可靠性；
2. **信息时效与价格反应错位**：新闻或财报公开时，股票或期货可能已经提前上涨/下跌，事实仍然有效并不等于交易机会仍然存在；
3. **研究结论容易跳跃**：从“宏观事件”直接跳到“某只股票/某个期货合约”，中间缺少业务真实性、盈利质量、供需传导、替代标的和反方证据；
4. **股票、期货和现货规则不同**：股票一期主要研究买多，期货可以多空，现货可能只是观察价格、库存或合同敞口，不能用同一套方向和风险规则处理；
5. **量价与基本面脱节**：研究方向正确时，市场可能还没有确认；研究方向错误时，价格可能短期被情绪推高。只看新闻或只看指标都容易产生误判；
6. **策略容易被误用**：策略应当是已筛选标的的交易方式，而不是把多个策略简单投票后强行选择标的；没有适配形态时应当等待，而不是强行交易；
7. **概率常常缺乏可验证定义**：很多“成功率”没有明确预测周期、成功标签、止损、成本、样本外测试和置信区间，难以判断是真优势还是偶然；
8. **组合风险被低估**：铁矿石、钢铁股、焦煤、玻璃和纯碱等不同对象可能属于同一产业链或宏观风险簇，表面上是多个机会，实际可能是同一个观点的重复暴露；
9. **数据合规和历史回溯容易被忽视**：公开网页可见不等于可以批量抓取、长期保存、回测、再分发或商业使用；没有点时版本就无法判断当时是否真的看得到；
10. **AI 容易被误用**：AI 适合摘要、解释和提出反方问题，但不能修改事实、补造缺失数据、计算最终概率、决定仓位或绕过风控。

### 2.2 本系统要解决的问题

本系统不是替用户“预测涨跌”，而是把上述复杂流程压缩为可追溯、可解释、可等待、可验证的研究闭环：

~~~text
分散信息
→ 统一来源、时间和授权状态
→ 事实—解释—预测研究链
→ 股票/期货/现货差异化判断
→ 量价确认和市场状态过滤
→ 候选决策卡
→ 策略适配而非策略投票
→ 等待、预警和重新检查
→ Paper/Shadow 模拟验证
→ 概率校准、组合选择和复盘归因
~~~

### 2.3 不能由本系统承诺的事情

- 不承诺必涨、必跌、固定收益率或固定成功率；
- 不把研报目标价、AI 输出或单一技术指标当作事实或确定性信号；
- 不把历史回测结果直接等同于未来实盘结果；
- 不把模拟盘成交等同于真实市场成交；
- 不把年订阅、免费接口或公开网页访问自动等同于商业再分发权；
- 不在数据授权、历史回溯、时间可见性或风险条件不满足时强行生成交易机会。

### 2.4 痛点与功能的对应关系

| 痛点 | 对应功能 | 目标结果 |
|:---|:---|:---|
| 信息分散 | 数据监听、来源分层、AI 摘要 | 可追溯事实池 |
| 信息滞后 | 发布时间/可见时间/价格反应检查 | 避免把旧信息当作新机会 |
| 传导跳跃 | 事实—解释—预测链、反方证据 | 方向有依据且可证伪 |
| 资产规则不同 | 股票、期货、现货判断表 | 方向和风险表达正确 |
| 量价脱节 | 独立量价分析模块 | 判断市场是否验证研究 |
| 策略误用 | 策略适配机制和适用范围 | 已选标的使用合适交易方式 |
| 概率虚化 | 样本外、滚动、校准和成本计入 | 概率可复核 |

### 2.5 目标用户画像与使用假设

本系统一期主要服务于团队内部人员以及经过授权的其他熟悉人员。目标普通用户具备股票/期货的基本概念和基本操作经验，但不要求具备编程、数据工程、量化研究、财务分析或专业风险管理能力。系统不得把理解专业指标、填写研究表、选择策略参数或手工计算仓位作为普通用户正常使用的前置条件。

用户分层：

| 用户层 | 典型能力 | 主要职责 | 默认界面 |
|:---|:---|:---|:---|
| 引导型普通用户 | 了解基本买卖、开平仓和持仓概念；非技术/非金融专业 | 提出研究目标，查看解释，确认关注/观察或Paper模拟 | 引导模式、少字段、系统预填 |
| 业务审核用户 | 能按团队规则核验材料、研究卡或计划 | 审核事实、候选、策略版本或交易计划；不负责重算系统指标 | 审核工作台、证据和版本清晰 |
| 专业管理用户 | 具备数据、策略、风险、运维或审计职责 | 管理数据源、规则版本、权限、Dify、风险和审计 | 专业模式、专业字段按权限可见 |

普通用户以最小必要输入参与流程；系统负责采集、计算、筛选、匹配、风险检查和结果解释。人工确认是接受或拒绝系统整理后的建议，不等于要求用户重新做专业分析。专业用户只在其职责范围内维护或审批规则，不应成为每个普通用户日常使用的必要中间人。

系统不面向完全不懂股票/期货基本概念、要求保证收益或要求一期接入真实资金自动交易的用户；这类限制必须在 onboarding 和Paper说明中清晰表达。


## 3. 系统目的、最终定位、范围与阶段边界

### 3.1 系统目的

系统不预测未来，不承诺必涨或必跌，不把 AI 输出当作买卖建议。系统的目标是：

> 在当时可获得的新闻、公告、财报、研报、行业数据、商品供需、现货、基差、期限结构、行情、成交量、持仓量和风险数据基础上，经过事实核验、机会分析、量价确认、策略适配、等待验证和组合筛选，找出未来某个预先定义周期内具有相对较高条件优势、风险可计算、交易工具可执行的股票或期货候选。

### 3.2 “高概率”的准确含义

系统输出的不是绝对预测，而是条件概率和相对优势：

```text
在指定市场状态、指定资产、指定方向、指定策略和指定周期下，
满足一组历史可复现条件的标的，未来达到目标或出现方向性结果的历史比例。
```

概率必须同时显示：

```text
预测周期
成功定义
样本数量
样本外结果
置信区间
平均盈利/亏损
最大不利波动
交易成本和滑点
```

### 3.3 最终定位

QuantPF V4 定位为：

> **面向个人用户的、多源信息驱动的、多资产候选筛选与交易研究系统。**

系统核心不是自动替用户预测市场，而是把复杂、分散、专业的研究流程结构化，降低用户参与成本，并让每一次候选筛选、等待、预警、交易和复盘都可解释、可验证、可追溯。

### 3.4 最终原则

```text
研究决定方向
筛选决定是否进入候选池
量价决定市场是否正在验证
K线和成交量决定适配哪种策略
策略决定进出场方式
等待机制决定是否现在交易
组合机制决定是否加入当前账户
风险管理决定交易多少
复盘和统计决定规则是否保留
```

### 3.5 范围、时间尺度与资产边界

- **核心时间尺度**：系统面向中长期研究和持有，日线/周线以及事件、财报和产业数据是主要研究尺度；分钟线、盘口、逐笔摘要和成交量主要用于市场确认、入场等待、流动性检查和模拟执行，不把系统变成高频交易系统；
- **股票**：一期主要支持股票多头研究、候选筛选、Paper 模拟和持仓管理；股票做空不作为一期默认表达；
- **期货**：支持多头和空头研究、开平仓、保证金、涨跌停、跳空、交割和移仓风险；
- **现货**：一期主要作为供需、库存、现货价格、合同或产业敞口的研究输入。没有真实现货库存、合同或可验证敞口时，不生成无依据的现货空单；现货交易/套保/价差属于后续扩展；
- **一期运行模式**：只允许本地 SIM、PAPER_MANUAL、经用户预授权和逐笔确定性风控的 PAPER_AUTO、SHADOW、READ_ONLY；PAPER_AUTO 是平台内部模拟资金的策略驱动模拟执行，不是真实自动实盘；
- **二期目标**：在合规、数据授权、交易接入、安全、回测和模拟盘门禁通过后，建设并启用自动实盘；门禁未通过前不得提交真实委托。

### 3.6 第一阶段非目标

- 不做超高频、微秒级交易、低延迟抢单、做市或高报撤单；
- 不把 Dify 或任何大模型作为最终概率、仓位、风控放行或真实下单主体；
- 不把公开网页、个人账号、年度订阅或免费额度自动扩展为团队共享、商业服务或数据再分发授权；
- 不在总纲中固化具体接口字段、数据库表、异常码、页面像素和验收脚本；
- 不把完整多周期看图、自由画线、多图联动、高级订单流图作为一期刚需。

### 3.7 二期量价主导机会发现与多资产扩展

二期新增一条独立的“量价主导机会发现流”。它不以近期新闻、财报或研报为启动前提，而是首先从价格行为、成交量、成交额、持仓量、波动、相对强弱、市场状态和跨市场关系中发现交易机会，再用因子、结构化研究数据和大模型进行过滤、解释、提出假设和补充反方问题。

二期覆盖范围必须预留并逐步支持：

~~~text
A股、港股、美股
期货具体合约和连续合约研究映射
外汇及海外经纪商品品种
必要时的跨市场相对强弱、联动和风险传导
~~~

机会发现的优先级：

~~~text
第一层：量价/价格行为/市场状态发现机会
第二层：确定性因子和跨资产特征过滤、排序、分组验证
第三层：大模型解释量价状态、提出研究假设和反方问题
第四层：新闻、财报、供需、基差、期限结构等作为可选上下文增强
第五层：策略适配、等待、风险检查和Paper/Shadow验证
~~~

新闻不是二期机会发现的必需入口。没有近期新闻时，系统仍可以基于量价和因子形成候选；有新闻时，新闻只作为对量价机会的解释或增强证据，不能覆盖量价事实、因子计算或风险门禁。

二期不允许大模型直接从自然语言生成交易信号、仓位或订单。Spring Boot负责特征、因子、状态、信号候选、回放、验证和风险交接；Dify负责解释、假设、反方问题和用户问答；所有候选仍须经过策略、风险和Paper流程。


## 4. 总体业务模块与模块目标

### 4.1 总体业务闭环

```text
数据监听与获取
  → 数据质量和时间可见性检查
  → 市场状态与制度状态检查
  → 多入口候选发现
  → 事实—解释—预测研究链
  → 资产方向判断
  → 质量/机会/量价/风险筛选
  → 候选研究决策卡
  → 市场状态与策略适配
  → 等待、预警与重新检查
  → 概率验证
  → 组合选择与风险预算
  → Paper/Shadow 交易
  → 持仓管理、止损、止盈、移仓
  → 复盘、归因、概率校准和规则迭代
```

| 模块 | 目标 | 主要输出 |
|:---|:---|:---|
| 数据监听与来源管理 | 自动获取多源信息，并记录来源、时间、版本和质量 | 可追溯的事实数据 |

| 数据采购与供应商管理 | 管理数据服务的采购方式、年度订阅、接口范围、授权、费用、延迟、覆盖率和替代来源 | 可用且授权清晰的数据服务目录 |
| 数据质量与时间治理 | 防止过期、冲突、修订和未来数据进入决策 | 数据质量状态 |

| 候选筛选 | 将大量对象压缩为少量高质量候选 | 候选池和淘汰原因 |

| 策略适配 | 根据已选标的的形态选择适合的交易方式 | 适配策略和等待条件 |
| 筛选与观察池 | 管理候选、等待、触发、过期和失效 | 观察池状态 |
| 预警 | 在条件发生时提醒重新检查 | 预警事件 |

| 交易计划与执行 | 将研究结论转换成可执行的方向、仓位和退出计划 | 交易计划、订单和成交 |

### 4.3 模块之间的职责边界

各模块不得越权：

```text
新闻模块不能直接下单
基本面模块不能决定具体入场价格
量价模块不能替代财报和供需事实
策略模块不能决定标的是否有基本面价值
概率模块不能覆盖硬风控
组合模块不能改变研究方向，只能决定是否纳入和分配风险
AI 模块不能修改事实或绕过风控
```

### 4.4 用户参与压缩与低输入目标

系统自动承担：

```text
数据采集和来源校验、去重、分类、摘要、事实/引用候选提取
结构化指标计算、候选初筛、排序、策略匹配、等待条件、预警
交易计划字段生成、仓位/资金/风险计算、回测、复盘草稿
```

普通用户主要参与：

```text
提出研究目标或选择快捷任务
选择关注对象/周期/资产范围（能自动推断时作为可选确认）
查看系统结论、依据和风险
确认/拒绝/延期、加入观察池
对系统生成的Paper计划进行二次确认
```

### 强制用户体验原则

1. 系统能够基于已授权数据、规则和版本确定的内容，不得要求普通用户重复填写或自行判断。
2. 优先使用默认值、自动识别、快捷选项和自然语言输入；自由文本仅用于确有必要的补充说明。
3. 复杂参数由Spring Boot按版本化规则计算，Dify只负责解释，不让普通用户配置策略表达式、指标周期、仓位公式、风险预算或成交模型。
4. 普通界面先展示“结论、原因、风险、状态、下一步”；指标、来源、公式、版本和技术字段渐进展开。
5. 人工确认用于确认是否接受系统给出的内容，不代表用户必须重新完成专业研究或风控计算。
6. 系统不得用简化界面隐藏风险；Paper二次确认、风险提示、授权审批和审计门禁必须保留。

普通用户目标操作量（验收基线）：创建常用研究任务核心输入不超过3项；加入/关闭观察不超过2个明确动作；接受系统Paper计划不超过3个确认步骤；普通用户日常流程不得要求专业自由文本、策略公式或风险参数输入。因合规/安全必须额外确认时，须说明具体原因并单独测量，不得用降低安全门禁换取步骤数。

在原有模块基础上，V4 将以下能力明确为目标级业务模块或横向约束：

| 补充模块/能力 | 目标 |
|:---|:---|

## 5. 数据监听、获取、授权、回溯与用户辅助体系

### 5.1 数据源优先级

#### A 级：事实确认来源

股票：监管机构、交易所、巨潮资讯、上市公司公告、年报、半年报、业绩预告、问询函和回复、审计报告。

期货：各期货交易所的合约规则、行情、结算价、持仓量、仓单、交割和交易日历。

宏观产业：政府统计部门、海关、行业协会、正式统计和公开产业数据。

#### B 级：行业和事件来源

主流财经媒体、权威通讯社、行业协会、期货公司产业报告、正式产业调研。

#### C 级：结构化计算来源

Wind、CSMAR、Choice、iFinD、Tushare Pro、AkShare、授权行情和产业数据库。Tushare Pro 可以按年度订阅/购买具体服务，但订阅期限不等于所有接口、字段、历史范围、调用额度、保存权或商业再分发权；具体权限以所购套餐和服务条款为准，C 级数据用于批量计算时仍必须保留原始引用和质量标记。

#### D 级：线索和观点来源

券商研报、论坛、自媒体、社交媒体、公开讨论。D 级内容可用于发现线索、情绪和反方观点，不能单独产生事实或交易信号。

### 5.1.1 Tushare Pro 年度订阅的业务边界

本系统一期将 Tushare Pro 作为结构化数据来源之一，年度订阅可以作为数据采购和预算管理方式。年度订阅只表示服务购买周期，不代表所有数据接口自动开通，也不代表全部字段、历史范围、分钟/盘口频率、调用额度、并发、保存、内部共享或商业再分发权限均已获得。

在数据采购确认阶段，系统必须按具体年度套餐建立“接口—字段—历史范围—更新频率—延迟—调用额度—保存范围—使用范围—费用—到期日”清单，并在实际使用前标记：

- 哪些接口已经开通，哪些接口需要额外积分、权限或单独购买；
- 哪些数据适合日线研究、回测和 Paper，哪些数据不具备足够历史或稳定性；
- 哪些数据可以个人本地研究，哪些数据不能用于团队共享、对外展示、商业服务或再分发；
- 年度订阅到期、额度不足、接口变更或数据延迟异常时，候选筛选、回测和 Paper 是否降级、暂停或切换备源。

因此，Tushare Pro 的年度订阅是本系统的数据采购方案之一，不是“所有结构化数据已经合法、完整、无延迟可用”的证明。实际数据权限以当期购买的具体产品、账号类型、服务条款和供应商确认结果为准。

### 5.1.2 权威来源组与 2～3 个主来源原则

一期业务目标是为每类关键研究材料配置 2～3 个可核验的主来源，而不是依赖单一网站或单一智能体搜索结果。来源数量是业务冗余目标，具体来源必须在数据采购和授权确认后配置。

建议按资料类型建立来源组：

| 来源组 | 主来源目标 | 业务用途 | 交叉核验要求 |
|:---|:---|:---|:---|
| 新闻/政策来源组 | 2～3 个权威新闻、政府或监管信息来源 | 发现重大事件、政策和宏观变化 | 重大事件至少核对来源发布时间、原文事实和是否为转载/评论 |
| 公司公告/财报来源组 | 2～3 个正式披露或授权结构化来源 | 确认公告、财报、业绩预告、问询回复和 ST/退市风险 | 正式披露来源优先，结构化数据与原文不一致时转人工复核 |
| 研报/行业报告来源组 | 2～3 个合法授权的券商、期货公司或行业报告来源 | 比较市场预期、观点分歧和反方证据 | 研报属于观点材料，不能把多份相同转载当成多个独立证据 |
| 行情/量价来源组 | 1 个主行情源 + 1 个可用备源 | K 线、成交量、持仓量、盘口和资金数据 | 对关键价格、成交量、交易日和合约身份进行一致性检查 |

来源组必须记录主源、备源、优先级、授权状态、覆盖范围、更新时间、延迟、历史回溯能力和失效替代规则。2～3 个来源是交叉核验和可用性目标，不代表任何网站天然权威，也不代表免费网页可以自动抓取或商业使用。

当来源组只有一个可用来源、来源之间冲突、来源时间不一致或授权状态不明确时，系统可以继续保存研究线索，但应降低研究状态，原则上不得直接生成可执行的新开仓机会。

### 5.2 面向非技术、非金融用户的三层解释

系统不要求普通用户自己阅读和计算全部专业指标。每个重要结论和阻断状态按三层展示：

```text
第一层：普通语言结论、当前状态、建议下一步
第二层：关键指标/规则的简明含义、主要支持和反方、风险影响
第三层：原始数据、来源、市场日期/时区、计算口径、规则/模型版本和审计
```

第一层默认展示；第二层按对象详情展开；第三层只对有权限或主动查看的用户开放。页面不得用单独分数、红绿灯或“AI推荐”替代解释。

示例：

```text
结论：公司与该事件的直接业务关系较弱，系统不建议仅因为这个概念加入观察。
为什么：当前可核验资料没有显示该事件会明显影响公司的主要收入或成本。
主要风险：新闻提及公司所在行业，不等于公司直接受益。
下一步：可查看证据，或选择“不再提醒”。
详细依据：相关业务收入占比、年报分部收入、公告和材料可见时间。
```

术语首次出现时应提供一句话解释、在当前对象中的含义和对用户操作的影响。系统阻断必须使用普通语言说明“为什么不能操作、系统已经做了什么、用户可采取什么下一步”。

### 5.3 信息监听流程

```text
来源组配置（每类 2～3 个主来源）
→ 定时/实时采集
→ 原文保存
→ 内容哈希与事件去重
→ 发布时间和可见时间识别
→ 来源交叉核验和冲突标记
→ 事实/观点/预测分类
→ 资产和行业映射
→ 数据质量评级
→ 进入研究队列
```

### 5.3.1 新闻分析结果的业务归属与落地边界

新闻处理应拆成“数据基础”和“研究事件”两段，不把 Dify 的模型输出直接当作事实或交易信号：

```text
Spring Boot 监控和采集新闻
→ 保存原文、来源、发布时间、可见时间和内容哈希
→ 去重、质量、授权和初步标的/行业映射
→ 创建 Dify 研究任务
→ Dify 调用大模型生成摘要、重大程度候选、影响范围、行业/个股关联候选和利多/利空候选
→ Spring Boot 校验 Schema、引用、时间、来源、授权、对象身份和冲突
→ 保存研究事件、证据和分析版本
→ Spring Boot 发布研究事件
→ 触发后续研究、候选发现、风险复核或查询流程
```

其中：

- 新闻原文、来源、时间、去重、授权和数据质量属于数据监听与标的基础；
- Dify 的摘要、事件分类、影响变量、行业/个股关联和方向判断属于研究辅助草稿；
- 研究事件的最终状态、结构化保存、版本、通知和查询由 Spring Boot 负责；
- `重大新闻`、`利多`、`利空`均须区分模型候选结果、核验结果和当前交易机会，不得直接转换为订单；
- 后续 Dify Workflow 应由 Spring Boot 发布的研究事件触发，而不是由 Dify 私自修改业务状态或直接调用交易执行接口。

### 5.4 新闻、财报和研报的用户辅助

系统自动回答：

```text
发生了什么？
信息是否正式确认？
市场此前可能预期什么？
新增信息是什么？
影响哪一个变量？
可能影响哪些行业、股票或商品？
影响方向和周期是什么？
信息是否已经被价格反映？
需要哪些后续数据确认？
有哪些反方证据？
```

### 5.4.1 消息有效性、价格反应与建仓机会判断

系统必须把“消息是否仍然有效”和“当前是否仍有建仓机会”分成两个不同结论。新闻、公告、财报或研报发布后，系统结合对应标的/合约的 K 线、成交量、成交额、持仓量、盘口摘要、波动率、价格位置、基差/期限结构和市场状态进行二次判断。

业务判断至少输出以下状态之一：

```text
FACT_VALID_ACTIONABLE：事实仍有效，价格尚未充分反映，满足方向和风险条件
FACT_VALID_OPPORTUNITY_PASSED：事实仍有效，但价格已经运行，当前赔率不足
FACT_VALID_WAIT_PULLBACK：事实仍有效，等待回调、反弹失败或重新确认
FACT_VALID_WAIT_BREAKOUT：事实仍有效，等待突破/破位和量价确认
FACT_WEAKENED：事实影响减弱、被后续信息修正或传导链未兑现
FACT_INVALIDATED：事实被更高等级来源否定或关键假设失效
DATA_INSUFFICIENT：数据、来源或时间口径不足，不能判断
```

系统至少检查：

1. 消息从发布到系统可见的时间差，以及标的在消息前后的价格、成交量和波动变化；
2. 消息发布后是否已经出现大幅跳空、连续上涨/下跌、放量冲高、放量破位或快速回到原区间；
3. 当前价格是否接近前高、前低、重要支撑阻力、估值极端或期货涨跌停/交割风险区域；
4. 量价是否支持消息方向，是否出现放量但价格推进不足、缩量回调、突破失败或量价背离；
5. 股票基本面、商品供需、基差、期限结构和市场状态是否仍支持原方向；
6. 按预先定义的预测周期、止损距离、目标空间、交易成本和组合风险，当前是否仍具有可接受的条件优势。

输出不能只写“消息利好/利空”，而应形成：

```text
消息结论：事实是否成立、影响方向和影响期限
价格结论：市场已经反映了多少
量价结论：市场是否继续确认
机会结论：可建仓 / 等待 / 机会已过 / 仅观察 / 禁止开仓
下一步：需要等待或重新检查的具体条件
```

“机会已过”是有效业务结果，不应为了满足用户寻找机会的需求而强行生成交易计划。

### 5.5 数据缺失时的业务动作

| 数据状态 | 研究动作 | 新开仓动作 |
|:---|:---|:---|
| 正常 | 正常研究 | 允许进入后续流程 |
| 延迟 | 降低置信度并等待更新 | 原则上不生成新信号 |
| 冲突 | 展示冲突来源和差异 | 禁止方向性新开仓 |
| 过期 | 仅允许查看历史 | 禁止使用过期数据生成信号 |
| 不可用 | 记录异常并转人工 | 禁止新开仓，持仓按退出规则管理 |

### 5.6 数据获取的总原则：可见、可获取、可存储、可使用不是一回事

本系统必须把数据使用拆成四个层次，不得因为某条信息可以在网页上看到，就默认它可以被系统批量抓取、长期保存、用于回测、对外展示或商业化使用：

~~~text
网页可见
  ≠ 可以自动抓取
  ≠ 可以长期保存原文
  ≠ 可以批量计算和再分发
  ≠ 可以用于商业产品或交易服务
~~~

系统的数据来源和使用规则遵循以下原则：

1. 优先使用监管机构、交易所、上市公司、政府统计部门、海关、行业协会和有明确授权的结构化数据服务；
2. 使用第三方网站、接口、研报或行情服务前，确认服务条款、授权范围、调用频率、历史数据权限、保存期限、衍生数据使用权和商业/个人使用限制；
3. 不绕过登录、验证码、访问控制、付费墙、技术限制或反爬措施，不把搜索引擎摘要当作原始事实；
4. 每份数据记录来源、原始链接或来源标识、采集时间、公布时间、可见时间、有效时间、版本、授权状态和允许用途；
5. 原始数据、结构化指标、AI 摘要、研究结论和交易决策必须分层保存，不能把 AI 生成内容伪装成数据源原文；
6. 不能确认授权范围时，数据可以作为人工研究线索，但不得进入自动排序、回测、模拟交易或对外展示链路，直至完成确认。

### 5.7 数据类别、来源、回溯和使用边界

| 数据类别 | 优先获取来源 | 历史回溯目标 | 稳定接口情况 | 一期允许的系统用途 | 人工查看/备注要求 |
|:---|:---|:---|:---|:---|:---|
| 新闻与政策信息 | 政府网站、监管机构、交易所、主流媒体和有授权的新闻服务 | 保存原文元数据、发布时间、可见时间和版本；原文是否可长期保存以授权为准 | 官方 RSS/API、授权接口较稳定；智能体搜索不等于稳定接口 | 事件发现、事实抽取、影响变量和过时检查 | 重大事件、来源冲突、方向性结论必须人工确认并备注 |
| 公司公告与财报 | 监管机构、交易所、上市公司公告、巨潮等正式披露渠道 | 财报期次、公告版本、修订记录和可见时间必须可回溯 | 官方披露页面和授权财务接口优先；页面搜索不作为唯一接口 | 基本面、业务真实性、盈利质量、预期差和事件研究 | 重大会计判断、重组、问询回复和异常经营事项需人工阅读/备注 |
| 券商研报与行业报告 | 券商、期货公司、行业协会和合法授权报告服务 | 记录报告标题、机构、发布日期、版本、观点和引用位置；是否存全文以许可为准 | 授权数据库可能稳定；免费网页和搜索结果不保证稳定 | 观点对比、预期差、反方证据和研究线索 | 研报属于观点材料，重要结论需人工查看原文并记录，不可只用 AI 摘要 |
| 股票 K 线、成交量、成交额 | 交易所、券商、授权行情服务、合规第三方数据服务 | 日线/分钟线按授权范围保存；必须支持复权口径、停牌、除权除息和修订回溯 | 授权行情 API、Tushare Pro 等第三方服务；Tushare Pro 可按年度订阅，具体接口、字段、历史范围、延迟、调用额度、保存范围和商业使用以所购套餐及服务条款为准 | 量价分析、回测、策略适配、模拟成交 | 关键突破、异常成交和数据缺口需人工查看并备注 |
| 资金流向、盘口、逐笔摘要 | 券商/交易所/授权行情服务 | 历史深度、逐笔和盘口保存期限取决于数据产品；不可默认全部可回溯 | 稳定性和权限差异最大，免费接口可能限频、延迟或缺字段 | 量价确认、流动性检查、模拟执行和预警 | 盘中关键异常需人工确认；不能把盘口摘要当作唯一建仓理由 |
| 期货行情、成交量、持仓量 | 各期货交易所、期货公司、授权行情服务 | 主力连续、具体合约、结算价、持仓量和交易日历必须区分保存 | 交易所/期货公司/授权服务优先；接口覆盖和历史长度需逐项核实 | 期货多空、合约选择、移仓、流动性和风险研究 | 合约切换、交割月、夜盘和异常行情需人工确认 |
| 商品供需、库存、现货和基差 | 政府统计、海关、交易所、行业协会、产业机构和授权数据库 | 记录统计口径、发布日期、修订、样本范围和可见时间 | 部分数据有公开接口，部分需要授权或人工整理 | 供需判断、基差/期限结构研究、方向与价差候选 | 口径变化、估算数据、区域差异和数据冲突必须人工备注 |
| AI 分析结果 | 系统基于已保存来源调用 Dify/模型生成 | 保存输入数据版本、提示词版本、模型版本、生成时间和人工修订 | 不作为原始数据接口 | 摘要、解释、反方问题、研究卡草稿和复盘辅助 | AI 结果只能人工审核后进入研究结论，不能替代原始来源 |

这里的“历史回溯目标”不是承诺所有数据天然可获得，而是要求系统对实际取得且被授权保存的数据建立点时归档。若某来源只提供当前快照、没有历史接口或禁止保存原文，系统必须标记为“不可完整回溯”，不得在回测中假装拥有完整历史数据。

### 5.8 新闻、财报、研报与行情的获取方式边界

用户不懂金融和财务时，系统可以使用智能体搜索、网页检索和来源聚合降低阅读门槛，但职责应分为三层：

~~~text
智能体搜索：发现来源、定位材料、提取摘要和待核问题
权威/授权来源：确认事实、保存可引用的时间和版本
用户人工查看：确认重大结论、冲突信息和是否接受进入研究链
~~~

因此：

- 新闻、财报和研报可以由智能体帮助发现和整理，但最终事实必须回到可核验的原始或授权来源；
- K 线、成交量、资金流向和盘口数据应优先通过交易所、券商或授权第三方结构化接口获取；免费网页或第三方量化网站可以作为补充，但必须显示数据源、延迟、覆盖范围和许可状态；
- Tushare Pro、AkShare 等工具只能作为具体数据产品和授权条款允许范围内的数据服务；Tushare 的年度订阅只说明服务购买周期，不代表全部数据权限，也不应在总纲中承诺某个接口永久免费、完整、无延迟或允许商业再分发；
- AI 对新闻、财报、研报和行情的解释必须保留“原文/原始数据 → AI 分析 → 用户备注”的链路，用户确认前只属于研究草稿；
- “人工查看”是重大结论的审核要求，不等于所有数据都必须由用户手工录入。系统仍应尽量自动采集和计算，以降低用户负担。

### 5.9 个人系统与商业系统的数据使用区别

本总纲默认一期是单用户或小团队的个人研究与本地模拟盘系统，但“个人使用”不等于自动拥有免费、无限制的数据权利；商业使用也不只是“是否收费”这么简单。最终应以数据提供商、交易所、券商、媒体和报告服务的合同及有效条款为准。

| 场景 | 典型范围 | 主要数据要求 | 典型限制 |
|:---|:---|:---|:---|
| 个人研究系统 | 用户为自己研究，在个人设备或受控环境中使用 | 可使用明确允许个人研究、非公开展示和非商业用途的数据 | 不得转售、公开广播、为他人提供数据服务、共享账号或绕过调用限制 |
| 个人模拟交易 | 用户本人使用 Paper/Shadow 账户，不提交真实订单 | 模拟行情和研究数据仍需遵守来源授权；模拟不改变数据版权和接口条款 | 不得因为是模拟盘，就把禁止商用或禁止存储的数据用于公开产品 |
| 小团队内部研究 | 同一组织内部有限用户使用 | 需要确认并发用户、内部共享、存储和历史回溯权限 | 个人许可通常不能自然扩展为团队或公司许可 |
| 商业系统 | 收费软件、SaaS、投顾/研究服务、面向客户的应用或对外提供数据/信号 | 通常需要商业数据许可、再分发/衍生数据许可、服务级别和合规审查 | 原始数据展示、接口代理、研报全文、行情转发和客户化信号通常需要明确授权 |
| 商业机构内部系统 | 公司自身投研、风控、交易或运营使用 | 可能需要企业/机构许可，即使不直接向客户收费 | 不能把个人账号、免费额度或个人授权当作机构授权 |

系统应为每个数据源记录 usage_scope，至少区分 PERSONAL_RESEARCH、TEAM_INTERNAL、COMMERCIAL_SERVICE、NO_REDISTRIBUTION 等状态。授权不明确时，默认按最严格限制处理，不进入对外展示、自动交易或商业服务链路。上述分类是业务边界，不构成对具体数据合同或法律责任的判断。

### 5.10 数据延迟、过时和有效性的分层处理

不同数据的“延迟”来源不同，系统不能只记录一个更新时间：

| 延迟类型 | 例子 | 业务含义 | 总纲级处理原则 |
|:---|:---|:---|:---|
| 发布延迟 | 财报、库存、政策和产业数据在统计期结束后才公布 | 数据描述的是过去，市场可能已经提前交易 | 明确 published_at、effective_at，检查价格是否已反映 |
| 传输延迟 | 新闻源、行情接口或搜索服务晚于原始发布 | 系统看到的时间晚于市场可见时间 | 记录 available_at 和来源延迟，不能把晚到信息当作新信息 |
| 处理延迟 | 采集、清洗、指标计算或 AI 分析尚未完成 | 系统内部结论落后于原始数据 | 显示数据新鲜度，未完成处理不生成新候选信号 |
| 行情延迟 | 免费行情、盘口或资金流接口为实时、准实时或盘后 | 价格和交易行为可能已经变化 | 显示实时/准实时/盘后标签，延迟不明时只作观察 |
| 修订延迟 | 统计数据、财报口径或历史行情后续修订 | 事后数据可能改变历史结论 | 保存版本，回测必须使用当时可见版本，不能静默覆盖 |
| 市场反应延迟 | 新闻发布后个股/期货已经快速上涨或下跌 | 信息本身可能仍有效，但交易机会的赔率已改变 | 将“事实有效”与“是否仍可交易”分开判断，必要时仅用于解释或复盘 |

系统至少需要维护以下时间字段：published_at、available_at、effective_at、observed_at、revised_at。当新闻、财报或研报发布后标的已经运行一轮，系统不应简单认为信息无效，也不应自动追买；应把“事件仍然成立”和“价格是否已经充分反映”分别显示，并重新执行量价、估值、风险和等待条件检查。

### 5.11 数据授权和历史回溯的目标状态

一期目标不是建立一个对外出售行情的数据库，而是建立个人研究和本地模拟盘所需的、来源清晰且在授权范围内的历史档案：

~~~text
可获得的数据 → 记录来源和授权 → 保存点时版本 → 生成指标和研究结论
→ 进入候选/回测/模拟盘 → 保留当时可见快照 → 支持复盘和审计
~~~

对于新闻、财报、研报、K 线、成交量、盘口摘要、资金流向、持仓量、库存、基差和期限结构，系统都应尽量支持历史回看；但回溯完整性必须显示为“完整、部分、不可用”三种状态。任何缺少历史、延迟不明、版本丢失或授权不明的数据，不得被包装成完整样本并用于证明策略概率。

## 6. 多入口候选发现流程

### 6.1 入口 A：新闻/公告事件驱动

```text
新闻/公告
→ 事实核验
→ 影响变量
→ 行业/商品映射
→ 多空假设
→ 直接暴露标的
→ 预期差和价格已反应检查
→ K 线/量价/市场状态联合判断
→ 消息有效性与建仓机会分类
→ 候选池或等待池
```

### 6.2 入口 B：股票基本面和预期差

```text
全市场股票
→ ST/停牌/流动性/数据硬过滤
→ 行业内质量排名
→ 同行比较
→ 五年财务趋势
→ 盈利预期修正
→ 估值分位
→ 事件敏感度
→ 量价确认
→ 股票买多候选
```

### 6.3 入口 C：商品供需和产业链

```text
品种池
→ 供应/需求/库存/利润
→ 现货强弱
→ 基差
→ 期限结构
→ 宏观和季节性
→ 量价和持仓量
→ 期货多头/空头候选
```

适用品种包括但不限于：

```text
铁矿石、原油、纯碱、玻璃、尿素、鸡蛋、生猪、纸浆
```

### 6.4 入口 D：价格、量价和策略形态

```text
全市场行情
→ 趋势/动量/波动率
→ 量价结构
→ 股票或期货相对强弱
→ 基本面/供需复核
→ 候选池
```

该入口用于发现没有明显新闻，但价格和交易参与已经出现结构变化的对象。

### 6.5 初筛与深筛

初筛目标是“不漏掉明显机会”，允许较宽；深筛目标是“减少错误候选”，使用更严格的事实、机会、量价、风险和组合规则。

```text
全市场/全品种
→ 初筛候选
→ 研究候选
→ 观察候选
→ 交易就绪候选
```

每次淘汰必须记录原因：

```text
数据不足、业务不真实、预期已反映、供需矛盾、量价失败、风险过高、流动性不足、组合重复、策略无匹配
```

---

### 6.5 二期量价主导机会发现入口

二期增加第五类候选入口：量价主导机会发现。其流程为：

~~~text
多市场/多资产价格和量价数据
→ 量价特征和市场状态计算
→ 机会扫描、异常/形态识别和跨资产比较
→ 因子过滤、排序和历史条件验证
→ 大模型解释与反方问题
→ 可选关联新闻/基本面/供需/制度事件
→ 形成机会候选或等待对象
→ 策略适配和风险流程
~~~

该入口优先关注“市场正在发生什么”，而不是先问“最近有什么新闻”。新闻、财报、供需和研报属于解释和增强层；当它们缺失、延迟或授权不满足时，不得阻断已经具备足够量价证据的研究候选，但必须降低证据完整性或标记未知项。


## 7. 量价分析业务模块

### 7.1 模块目标

量价分析模块的目标不是用成交量单独预测涨跌，而是回答：

```text
交易参与是否增加？
参与是否真正推动了价格？
价格运动是否获得后续确认？
当前是趋势启动、趋势延续、趋势衰竭、吸收、派发还是流动性冲击？
量价结构是否支持基本面/供需研究方向？
```

量价模块作为：

```text
候选发现工具
方向确认工具
策略适配工具
风险预警工具
执行质量工具
复盘归因工具
```

不作为唯一的基本面判断工具。

### 7.2 量价分析理论组合

V4 采用组合式量价框架：

```text
市场阶段和供需结构：借鉴威科夫思想
K线、成交量和收盘位置：借鉴 VSA 类分析
批量计算：RVOL、成交量Z分数、OBV、VWAP、MFI、CMF、量价背离
期货参与结构：成交量 + 持仓量
产业验证：库存、现货、基差、期限结构和利润
短周期执行：盘口和逐笔成交
```

任何理论必须转成可计算、可回测的条件，不能只保存“疑似吸筹”“主力派发”等不可验证标签。

### 7.3 量价数据字段

#### 股票

```text
open / high / low / close
volume / turnover
turnover_rate
adjusted_price
relative_volume
volume_zscore
atr
close_location_value
body_ratio / upper_shadow_ratio / lower_shadow_ratio
obv / vwap / mfi / cmf
price_position_percentile
industry_relative_strength
index_relative_strength
bid_ask_spread / market_depth
```

#### 期货

```text
open / high / low / close / settlement
volume / open_interest
volume_change / open_interest_change
relative_volume / volume_zscore
atr / volatility
close_location_value
basis / basis_change
term_structure / calendar_spread
bid_ask_spread / market_depth
contract_remaining_days
limit_distance
```

### 7.4 量价状态

```text
ACCUMULATION_CANDIDATE：低位承接候选
BREAKOUT_CONFIRM：突破确认
BREAKOUT_WEAK：突破但参与不足
TREND_FOLLOW：趋势延续
PULLBACK_HEALTHY：回调健康
DISTRIBUTION_CANDIDATE：高位派发候选
BREAKDOWN_CONFIRM：破位确认
SELLING_EXHAUSTION：下跌衰竭候选
DIVERGENCE：量价背离
LIQUIDITY_RISK：流动性风险
NO_SIGNAL：无明确状态
```

这些状态不是直接订单信号，必须与研究方向、市场状态和策略适配共同使用。

### 7.5 股票量价规则

#### 低位承接候选

```text
价格位于过去120日低位区域
波动率下降
成交量逐步收缩
下跌幅度缩小
低点不再明显下移
出现强势收盘或放量上涨
```

输出：进入看多研究对象的观察池，不直接买入。

#### 上涨放量、回调缩量

```text
上涨阶段成交量增加
回调阶段成交量下降
回调不破关键结构
再次上涨时成交量重新放大
```

适合匹配趋势回调或低位整理突破策略。

#### 放量突破

```text
收盘价突破过去N日高点
relative_volume 达到阈值
收盘位置偏强
突破幅度不过度极端
行业相对强度不弱
后续没有快速跌回突破位
```

#### 高位放量滞涨

```text
价格处于阶段高位
成交量明显增加
价格涨幅有限
收盘位置转弱
后续无法继续创新高
```

输出：提高风险等级或进入多头退出观察，不直接认定为顶部。

#### 放量下跌

股票一期主要用于：

```text
禁止新买入
减仓候选
止损候选
提高风险等级
```

### 7.6 期货量价持仓规则

| 价格 | 成交量 | 持仓量 | 业务解释 |
|:---|:---|:---|:---|
| 上涨 | 增加 | 增加 | 新参与增加，趋势可能延续 |
| 上涨 | 增加 | 减少 | 可能是空头回补，持续性需谨慎 |
| 下跌 | 增加 | 增加 | 空头参与可能增加，需检查拥挤度 |
| 下跌 | 增加 | 减少 | 可能是多头平仓，趋势未必延续 |
| 横盘 | 减少 | 减少 | 参与者退出，等待方向 |
| 横盘 | 增加 | 增加 | 多空分歧扩大，等待突破 |
| 上涨 | 减少 | 增加 | 价格推进但参与不足，趋势质量偏弱 |
| 下跌 | 减少 | 增加 | 价格走弱但参与不足，需要谨慎 |

成交量和持仓量只能提供结构解释，不能单独证明多头开仓或空头开仓。

### 7.7 期货多空量价组合

#### 多头候选

```text
基本面/供需偏多
价格趋势向上
成交量相对放大
持仓量配合
基差不走弱
期限结构不冲突
未出现极端拥挤
```

#### 空头候选

```text
基本面/供需偏空
价格趋势向下或反弹失败
破位时成交量放大
持仓量配合
基差走弱
期限结构偏空
没有明显逼空或交割风险
```

### 7.8 盘口和逐笔的阶段边界

一期使用盘口/逐笔数据的目标是：

```text
流动性过滤
价差检查
盘口深度检查
成交延迟检查
策略触发时执行质量确认
止损无法成交风险提示
```

完整订单流、撤单行为、成交速度和深度图属于后续增强能力，主要用于盘中执行和预警，不作为一期中长期选股的唯一依据。

### 7.9 量价验证规则

每个量价规则必须先定义：

```text
信号条件
成交时点
观察周期
目标和止损
成功/失败定义
交易成本
基准策略
市场状态分组
```

必须比较：

```text
只用价格
价格 + 成交量
价格 + 成交量 + 基本面/供需
完整研究流程
```

如果加入成交量没有改善样本外期望、回撤或稳定性，则该量价字段不应获得更高业务权重。

### 7.10 量价关系优化发现交易时机（二期能力）

二期规划增加“通过量价关系研究优化发现交易时机”的能力，用于在研究方向已经形成后，进一步判断市场何时完成确认、何时进入等待、何时机会已经过去。该能力不是一期新增交易入口，也不能把量价优化结果直接转换为真实委托。

二期重点研究：

```text
价格位置与结构
成交量放大/收缩
成交量与价格推进效率
突破/破位后的持续性
回调/反弹的量能变化
量价背离和趋势衰竭
盘口深度、价差和成交质量
期货成交量与持仓量组合
不同市场状态下的时机差异
```

一期必须预留：

- 多周期 K 线、成交量、成交额、持仓量和盘口摘要的标准化存储；
- 量价特征、观察窗口、信号时间、市场状态和策略版本字段；
- 量价规则版本、样本标签、回测结果和二期特征扩展接口；
- “消息有效但机会已过 / 等待回调 / 等待突破 / 量价未确认”等状态；
- 量价时机结果与研究卡、观察池、预警和交易计划的关联关系；
- 二期完整盘口、逐笔、订单流和图表工作台的扩展边界。

一期只实现量价状态计算、结构化展示、观察和预警所需的基础能力，不实施依赖高级订单流或模型自动择时的交易闭环。

### 7.11 二期量价分析的多资产适用范围

二期量价分析不局限于A股和期货。适用对象包括：

| 资产 | 重点量价输入 | 必须特别处理 |
|:---|:---|:---|
| A股 | OHLCV、成交额、复权价格、相对强弱、涨跌停状态 | 复权、停牌、T+1、涨跌停和交易日历 |
| 港股 | OHLCV、成交额、流动性、相对强弱、市场状态 | 港股交易日历、港币口径、停牌/流动性和公司行为 |
| 美股 | OHLCV、成交额、盘前/盘后可用性、相对强弱 | 美东时区、公司行为、复权、市场日历和美元口径 |
| 期货 | OHLCV、成交额、持仓量、基差、期限结构、合约价差 | 具体合约、连续合约映射、换月、交割、保证金和夜盘归属 |
| 外汇/海外经纪商品 | Bid/Ask OHLC、点差、Tick数量或成交代理量、波动和交易时段 | 经纪商品种、报价方向、时区、休市/断档、点差和杠杆规则 |

不同资产不共享未经标准化的绝对价格、成交量或阈值。跨资产研究应使用收益率、波动调整值、分位数、相对强弱、标准化成交量和市场状态等可比特征，并保存单位、时区、币种、数据源和算法版本。


## 8. 事实—解释—预测研究链

### 8.1 事实层

事实层只描述已经发生并且能够追溯到来源的内容：

```text
某交易所库存本周增加 8%
某公司公告预计净利润增长 30%
某品种开工率从 75% 上升至 82%
某股票相关业务收入占比 72%
某期货合约价格跌破过去60日低点
```

事实层不允许直接写成：

```text
所以股价一定上涨
所以期货一定下跌
所以应该立即买入/卖出
```

### 8.2 解释层

解释层将事实连接到经济变量：

```text
库存上升
→ 供应暂时大于需求
→ 现货压力增加
→ 基差可能走弱
→ 期货远月压力增加
```

或者：

```text
产品价格上涨
→ 销售单价提高
→ 成本没有同比上升
→ 毛利率改善
→ 盈利预期可能上修
```

解释必须写明：

```text
影响变量
传导方向
影响强度
影响期限
直接受益者和受损者
可能的反向传导
需要验证的后续数据
```

### 8.3 预测层

预测层才允许输出方向和概率，但必须是条件式：

```text
预测方向：SHORT
预测周期：未来20个交易日
成立条件：库存继续增加、基差不转强、价格反弹失败
失效条件：库存连续下降、现货重新上涨、价格收复关键阻力
历史相似样本：86
条件下跌概率：62%
扣成本后期望值：正/负/不足
```

### 8.4 反方研究

每个研究对象必须同时生成：

```text
支持证据
反方证据
最重要的未知信息
最可能的错误环节
关键证伪条件
替代标的或替代工具
```

### 8.5 事实、解释和预测的版本要求

后续事实更新时，系统必须标记哪些解释和预测需要重新计算。历史研究不能被最新数据静默覆盖，必须保留当时可见版本。

## 9. 股票、期货与现货判断流程

### 9.1 股票买多

```text
业务真实性
→ 盈利质量
→ 行业地位和同行比较
→ 盈利预期和估值/预期差
→ 事件敏感度
→ 量价状态
→ 市场状态
→ 进入观察池
→ 等待策略适配和触发
→ 股票买入 Paper 计划
```

股票候选必须回答：

```text
公司是否真的在做相关业务？
业务是否产生真实收入和利润？
利润能否转化为现金？
事件是否能影响利润或估值？
市场是否已经充分定价？
量价是否正在验证？
如果现在不买，等待什么？
```

### 9.2 期货做多

```text
供应收缩/需求改善/库存去化/利润改善
→ 现货和基差确认
→ 期限结构确认
→ 价格、成交量、持仓量确认
→ 交割和移仓检查
→ 等待策略适配
→ BUY_OPEN Paper 计划
```

### 9.3 期货做空

```text
供应恢复/需求走弱/库存累积/利润恶化
→ 现货和基差转弱
→ 期限结构偏空
→ 价格破位或反弹失败
→ 持仓拥挤和逼空风险检查
→ 交割、涨停和跳空压力测试
→ 等待策略适配
→ SELL_OPEN Paper 计划
```

### 9.4 现货研究和套保

现货业务必须先区分：

```text
现货价格观察
现货库存管理
采购合同风险
销售合同风险
期货套保
期现套利
```

没有库存或贸易合同敞口时，现货看空只能映射为期货空头研究、回避多头或观察信号，不能生成无依据的现货空单。

## 10. 候选决策卡与策略适配机制

### 10.1 策略职责原则

策略不是建仓筛选条件，不参与决定“什么资产值得研究”。策略只负责：

```text
已选标的当前适合什么交易方式
什么条件下进场
止损和退出如何设置
```

错误逻辑：

```text
爆点看多 + 缠论看空 + 趋势看多
→ 2票对1票
→ 买入
```

正确逻辑：

```text
研究决定方向
→ 候选筛选通过
→ 分析K线、成交量、持仓量和价格位置
→ 匹配适用策略
→ 等待策略触发
```

### 10.2 策略适配状态

```text
MATCHED：已匹配策略但尚未触发
TRIGGERED：策略条件已触发
WAITING：方向成立但形态未完成
NO_MATCH：当前没有合适的交易方式
EXPIRED：策略等待超时
INVALIDATED：策略前提失效
```

`NO_MATCH` 不代表研究方向错误，只表示当前没有合适的交易方式。

### 10.3 策略适用范围卡

每种策略必须附带：

```text
策略名称
适用资产
适用方向
适用周期
适用市场状态
适用价格位置
适用K线形态
适用成交量/持仓量形态
必要确认条件
禁止使用条件
入场条件
止损条件
退出条件
历史样本与期望值
策略有效期
```

### 10.3.1 智能体问答中的操作建议与多周期预期

当用户询问“能否买入”“是否可以建仓”“看多还是看空”或“现在有没有机会”时，智能体回答的最后必须形成一份**条件式操作建议**，不能只给新闻摘要、方向判断或单一概率数字。

操作建议至少包括：

```text
当前建议：可建仓 / 等待 / 减仓 / 平仓 / 机会已过 / 禁止开仓
交易方向：股票买多 / 期货多头 / 期货空头 / 套保 / 价差 / 不参与
操作因子：触发建议的基本面、供需、量价、估值、基差、期限结构和风险因素
适配形态：爆点/放量突破、缠论一买/二买/三买、趋势回调、反弹失败、区间边界或基差/期限结构形态
入场条件：达到哪些条件后才可进入 Paper 交易计划
等待条件：尚未满足条件时应等待什么
失效条件：出现什么情况后取消建议
止损和风险边界：以交易计划和确定性风控结果为准
```

策略必须根据已筛选标的的 K 线、成交量、持仓量、价格位置和市场状态适配。没有匹配策略或触发条件时，应回答“等待”或“机会已过”，不能强行推荐爆点、缠论或其他策略。操作建议是研究/Paper 建议，不是无条件买卖指令，也不直接触发真实委托。

每个相关问答还必须分别说明三个研究时间范围：

| 研究范围 | 目标 | 回答重点 |
|:---|:---|:---|
| 短期：约 2 周 | 判断当前入场触发、回调、突破/破位和短期风险 | 触发条件、预期路径、止损/失效条件、成本和事件风险 |
| 中期：约 3 个月～1 年 | 判断盈利、行业景气、商品供需、基差/期限结构和趋势的持续性 | 中期核心假设、后续跟踪数据、移仓/换月及组合风险 |
| 长期：约半年～3 年 | 判断产业结构、公司竞争力、供需周期和长期逻辑 | 长期假设、估值/周期风险及重大证伪条件；不得把短期 K 线信号外推为长期结论 |

上述周期存在重叠，分别表示不同研究视角，不代表保证持有期限或收益目标。对期货，中长期预期针对商品/产业逻辑或滚动合约表达，必须提示具体合约到期、换月/移仓和期限结构影响，不暗示可长期持有同一合约。

### 10.4 核心策略适用范围

| 策略 | 适用形态 | 方向 | 禁用情形 |
|:---|:---|:---|:---|
| 低位横盘突破 | 低位整理、波动收缩、卖压减弱、放量上破 | 多头 | 无量突破、基本面恶化、快速跌回区间 |
| 高位震荡反弹失败 | 高位震荡、高点降低、反弹缩量、跌破后反抽失败 | 空头 | 持续创新高、强承接、逼空风险 |
| 趋势回调 | 明确趋势、回调/反弹不破主结构、量能收缩 | 顺趋势 | 趋势不明、震荡中部、结构破坏 |
| 放量突破/破位 | 关键区间突破或破位并获得后续确认 | 双向 | 单日异常量、消息最后冲高、恐慌性假破位 |
| 区间边界 | 趋势弱、上下边界多次验证 | 边界双向 | 重大事件、单边趋势、波动率突变 |
| 基差/期限结构 | 现货、基差、期限结构和合约价格协调 | 双向/价差 | 数据口径不一致、交割风险、双腿流动性不足 |

## 11. 筛选、等待、预警与复盘闭环

### 11.1 筛选模块目标

筛选模块的目标是把全市场/全品种压缩为少量可研究对象，并说明为什么入选、为什么淘汰。筛选结果不是买卖指令。

筛选任务必须保存：

```text
筛选入口
筛选范围
筛选条件
数据时间
规则版本
候选结果
淘汰结果
淘汰原因
```

### 11.2 等待模块目标

等待模块的目标是防止“研究正确但交易时点错误”。每个观察对象必须明确缺少什么条件。

等待卡：

```text
观察原因
已满足条件
尚未满足条件
触发条件
触发后复核项
失效条件
最长等待时间
下次复核时间
```

状态流转：

```text
CANDIDATE
→ WATCHLIST
→ WAITING_TRIGGER
→ NEAR_TRIGGER
→ TRADE_READY
→ PAPER_ACTIVE
```

异常流转：

```text
DATA_CONFLICT
THESIS_CONFLICT
EXPIRED
INVALIDATED
BLOCKED
```

### 11.3 预警模块目标

预警的目标是提醒系统或用户重新检查，而不是自动把提醒转换成订单。

预警类型：

```text
价格预警
技术结构预警
量价异动预警
新闻/公告预警
财报和盈利预期预警
库存/供需预警
基差预警
期限结构预警
策略触发预警
风险簇集中度预警
```

每个预警必须包含：

```text
对象
条件
有效期
触发时间
触发时数据快照
触发后的复核问题
允许动作
```

### 11.4 预警触发后的重新检查

触发后必须重新检查：

```text
新闻是否更新
财报/供需是否有新数据
市场是否已经过度反应
量价结构是否继续确认
策略是否仍然适配
止损和风险收益比是否仍然合理
组合是否仍然允许加入
```

### 11.5 复盘模块目标

复盘的目标不是记录盈亏，而是区分：

```text
研究错误
数据错误
传导错误
量价判断错误
策略适配错误
执行错误
仓位错误
组合错误
偶然结果
```

复盘必须同时记录已交易和未交易信号：

```text
实际交易对象
达到条件但未交易对象
进入观察池但未触发对象
被淘汰但后来大幅上涨/下跌对象
替代标的表现
```

### 11.6 复盘输出

```text
原研究方向是否正确
事实是否真实和及时
传导链哪一环正确/错误
量价状态是否正确
策略是否适配
操作因子和触发依据
适配的K线/成交量/持仓量形态
建议操作：可建仓 / 等待 / 减仓 / 平仓 / 机会已过 / 禁止开仓
短期（约2周）操作预期
中期（约3个月～1年）研究预期
长期（约半年～3年）研究预期
是否按等待条件交易
执行偏差和成本
组合边际风险是否合理
需要修改的唯一规则
```

## 12. 概率验证机制

### 12.1 概率定义

系统至少分别计算：

```text
P_up(H)：未来周期 H 上涨概率
P_down(H)：未来周期 H 下跌概率
P_target_before_stop：先达到目标而不是先达到止损的概率
```

股票、期货多头、期货空头、套保和价差不能混合统计。

### 12.2 成功标签

每类信号必须提前定义成功和失败：

```text
入场规则
成交价格
观察周期
目标收益
止损幅度
交易成本
滑点
移仓成本
超时结算规则
```

示例：

```text
期货空头
观察期：20个交易日
成功：先达到扣成本后+6%的目标
失败：先达到扣成本后-3%的止损
超时：按20日结束价格结算
```

### 12.3 验证阶段

```text
冻结信号规则
→ 历史回放
→ 成本和滑点模拟
→ 时间样本外
→ 滚动验证
→ 纸面/Shadow 前瞻
→ 概率校准
→ 规则版本发布
```

### 12.4 概率必须与基准比较

股票至少比较：

```text
市场指数
行业指数
行业中位数
简单动量
简单趋势
随机同行样本
```

期货至少比较：

```text
对应品种基准
简单均线趋势
简单突破
买入/卖出并持有基准
不含供需数据的价格策略
```

### 12.5 概率校准

系统显示的 60% 概率，长期实际结果应接近 60%。每个概率结果必须显示：

```text
概率值
有效样本数
置信区间
样本外概率
最近样本表现
最大不利波动
```

样本不足时不显示伪精确概率，而显示：

```text
样本不足，无法验证
```

### 12.6 消融实验

必须比较：

```text
价格-only
价格 + 成交量
价格 + 基本面
价格 + 新闻
价格 + 商品供需
完整系统
```

如果增加某类信息没有改善样本外期望、回撤或稳定性，则不应继续增加该信息的业务权重。

### 12.7 策略和概率漂移

按最近20次、50次、100次以及滚动年度监测：

```text
胜率
期望收益
盈亏比
最大回撤
滑点
信号数量
概率校准误差
```

状态：

```text
NORMAL
DOWNWEIGHT
REVIEW
PAUSED
REVALIDATION_REQUIRED
```

## 13. 组合选择与风险预算机制

### 13.1 组合选择目标

组合模块的目标不是选择分数最高的几个对象，而是选择加入当前组合后能够改善整体风险收益结构的表达工具。

### 13.2 个体硬过滤

以下任一项不通过，不能进入组合：

```text
数据质量不合格
研究逻辑无法解释
没有清晰触发和失效条件
概率样本严重不足
预期净收益不足
止损不可执行
流动性不合格
期货交割/移仓风险不可控
保证金压力测试失败
风险簇已经超限
```

### 13.3 风险簇

每个候选必须标记：

```text
行业
产业链
商品因子
宏观因子
政策因子
利率/汇率暴露
多头/空头方向
共同事件
```

铁矿石多头、钢铁股多头、焦煤多头可能都属于同一黑色产业链风险簇，不能简单视为三个独立机会。

### 13.4 最佳表达工具

同一个研究观点需要比较不同表达：

```text
预期净收益
单位风险收益
流动性
交易成本
波动率
最大回撤
保证金压力
相关性
执行难度
```

输出：

```text
主表达工具
备选表达工具
不采用的表达工具
不采用理由
```

### 13.5 组合选择流程

```text
个体硬过滤
→ 预期净收益排序
→ 风险簇标记
→ 合并共同暴露
→ 删除重复表达
→ 压力测试
→ 计算加入组合后的边际风险
→ 分配风险预算
→ 生成 Paper 组合
```

### 13.6 风险预算初始原则

初始 Paper 阶段可使用保守起点：

```text
单笔账户风险：0.25%~0.50%
单一风险簇：设置总风险上限
期货保证金：保留安全缓冲
单一方向：设置总风险上限
日/周/月：设置最大损失上限
```

具体数值必须通过回测、样本外和 Paper 验证，不作为永久参数。

### 13.7 组合再平衡

```text
每日：退出、止损、数据和风险检查
每周：观察池、候选和风险簇重算
事件后：重新评估方向和组合暴露
财报/库存发布后：更新质量和机会评分
月度：复核概率、策略和风险预算
```

### 13.8 组合级停止新增风险

系统必须区分：

```text
禁止开新仓
允许减仓
允许平仓
允许移仓
允许套保
```

重大风险事件不应简单地把所有持仓动作全部锁死。

## 14. 人机协同、可解释性与二期边界

### 14.1 一期用户体验目标

用户不懂财务、行业和量价专业术语时，系统仍应能够使用。每个候选以“结论—证据—风险—下一步”展示：

```text
结论：暂不交易，进入观察池
证据：库存高、基差走弱、价格尚未破位
风险：空头拥挤、交割月临近
下一步：等待反弹失败并重新检查库存数据
```

### 14.2 AI 助手业务角色

#### 新闻研究助手

```text
提取事实
识别影响变量
列出受益/受损行业
检查信息是否过时
生成反方问题
```

#### 股票研究助手

```text
解释主营业务
解释盈利质量
进行同行对比
解释五年趋势
分析事件敏感度和预期差
```

#### 商品研究助手

```text
解释库存、供应、需求、利润
解释现货、基差和期限结构
生成多空传导链
识别数据冲突和风险
```

#### 量价助手

```text
翻译量价状态
识别突破、破位、回调和背离
说明量价是否与研究方向一致
提示量价信号的历史表现
```

#### 交易计划助手

```text
整理入场、止损、目标和等待条件
计算风险金额和仓位建议
检查组合风险
```

#### 复盘助手

```text
区分研究错、时机错、策略错、执行错和组合错
比较未交易候选
提出一项规则改进建议
```

#### 智能体问答助手

智能体应支持面向业务数据的自然语言问答。用户可以用普通语言提问，系统先识别问题中的时间范围、资产类型、标的/商品、方向、研究任务和“机会”含义，再调用 Spring Boot 的结构化查询和规则结果，由 Dify 生成带证据的解释。

一期至少支持以下问答类型：

| 用户问题类型 | 系统应完成的业务查询 | 回答必须包含 |
|:---|:---|:---|
| “今天有没有建仓机会？股票/期货分别如何？” | 查询当日通过数据、研究、量价、等待、风险和组合门禁的候选 | 股票/期货分组、方向、具体标的、触发条件、风险和没有机会时的原因 |
| “今天有没有关于原油方向的机会？有没有原油重大新闻？” | 查询原油新闻/政策/供需/库存和相关标的，并判断价格是否已经反映 | 重大新闻列表、来源时间、原油期货与相关股票候选、机会状态和反方证据 |
| “如果今天买入宁德时代，能大概率上涨吗？” | 查询当前股票研究卡、最新财报、估值/预期差、量价状态、市场状态和历史条件概率 | 条件概率或“样本不足”、预测周期、成功定义、价格是否已反映、止损/失效条件和不确定性 |
| “立讯精密财报研报怎么样？有 ST 风险吗？最近能入手吗？” | 查询业务真实性、财报质量、研报观点分歧、ST/退市风险、价格和量价状态 | 普通语言结论、来源和时间、风险核验、当前机会状态、等待条件和不构成保证的说明 |
| “最近纯碱行情怎么样？看多还是看空？有机会建仓吗？” | 查询纯碱供需、库存、现货、基差、期限结构、期货量价持仓和合约风险 | 多空传导链、当前状态、适合的具体合约、量价确认、交割/移仓风险、可建仓/等待/机会已过结论 |

智能体回答必须遵守：

```text
先给结论，再给证据、时间和来源
区分事实、解释、条件判断和未知信息
区分“消息仍有效”与“当前仍可建仓”
有足够样本才显示条件概率，否则明确显示样本不足
没有候选时明确回答“当前没有满足门禁的机会”及原因
回答股票、期货和现货时使用不同的判断规则
回答结尾必须给出当前操作建议、操作因子、适配的K线/量价形态和入场/等待/失效条件
回答结尾必须分别给出短期约2周、中期约3个月～1年、长期约半年～3年的条件式研究预期
三种时间范围必须分别说明，不得用短期技术信号直接替代中长期基本面判断
期货中长期预期必须说明具体合约、换月/移仓和期限结构影响
操作建议只允许进入研究计划或Paper/Shadow流程，不直接生成真实委托
回答最后给出等待条件、风险条件和下一步检查项
```

智能体只能查询、解释和组织已有结构化结果，不能因为用户追问“能不能买”就绕过数据质量、量价确认、风险门禁或人工确认，也不能直接生成真实订单。

AI 不能：

```text
修改原始事实
伪造缺失数据
把预测写成事实
绕过数据质量
绕过风险控制
直接生成真实订单
自动把利空转换为 SELL_OPEN
```

```text

复盘和归因
```

### 14.4 二期功能：完整看图工作台

按用户确认，以下功能列为二期，不作为一期刚需：

```text
完整多周期图表工作台
自由画线和标注
多图联动
图表内 AI 操作
图表脚本编辑器
```

其中，一期对量价数据和特征接口进行预留，二期再基于历史样本、市场状态和成本模型优化交易时机；一期不把“量价优化”宣传为已具备的自动择时能力。


### 14.6 当前阶段的人工确认与二期实盘边界

一期坚持“系统自动整理，用户在关键节点确认”的人机协同方式。用户不需要手工阅读和计算所有数据，但以下事项不得仅凭 AI 摘要或自动评分直接推进：

- 重大新闻、战争、政策、监管处罚、重大重组、财报异常和来源冲突；
- 新闻、财报或研报发布后，价格已经明显运行，仍然需要判断是否已经反映；
- 股票进入最终候选、期货确定多空方向、现货数据用于表达交易观点；
- 候选从观察池进入 Paper/Shadow 交易计划；
- 数据授权不清、数据延迟不明、历史回溯不完整或 AI 与原始来源不一致；
- 研究规则、概率口径、策略适用范围和风险参数的修改。

人工确认的结果必须保留为研究备注或决策记录，并与当时可见的数据版本关联。普通的日常数据刷新、指标计算、候选排序和重复性预警可以自动完成，但自动化不应绕过上述关键确认点。

人工决策至少区分以下结果：

```text
CONFIRMED：接受当前研究结论或交易计划
REJECTED：否决当前候选或方向，并记录原因
DEFERRED：暂不处理，等待指定数据或事件
OVERRIDDEN：用户在说明理由、有效期和风险影响后覆盖系统/AI 草稿
EXPIRED：超过有效期，必须重新检查，不能沿用旧确认
```

人工覆盖只能改变研究状态、排序或备注，不能绕过数据授权、交易工具权限、确定性风控和 Paper/Shadow 门禁。

一期本地模拟盘的本质是研究验证工具：订单、成交、资金、持仓和盈亏均在本地模拟环境中闭环，不代表真实成交能力，不代表未来实盘收益，也不等于取得了真实交易数据或软件的商业授权。

未来二期自动实盘是独立阶段，至少需要重新确认：

~~~text
实际接入链路与交易权限
→ 证券/期货公司和交易所适用规则
→ 程序化交易报告及账户要求
→ 行情、研报、新闻和软件授权
→ 密钥、权限、审计、异常处置和人工熔断
→ 模拟盘前瞻验证和小规模灰度
→ 独立合规与安全放行
~~~

在上述条件完成前，系统不得把一期的 Paper 信号、模拟订单或本地策略适配结果直接转换为真实委托。

## 16. 核心业务流程（目标态完整业务闭环）

### 16.1 主闭环

```
数据采集 → 标的筛选 → 策略信号 → 风控校验 → 交易执行 → 回测评估 → 绩效监控
```

**铁律**：Paper 下单决策必须来自“确定性策略 + 确定性风控闸门”。一期可采用逐笔人工确认，或在用户预授权范围内采用自动 Paper；自动 Paper 的每笔动作仍须逐笔通过最新确定性风控。Dify 编排的 LLM输出只能作为研究参考，不得直接决定买卖、生成订单或绕过门禁。

### 16.2 数据采集流程

```
WebSocket 实时行情 → MarketDataCacheWriter → Redis(最新) + 时序库(批量落盘)
HTTP 历史 K 线 → 复权处理 → qs_kline_bar
新闻源轮询（财联社/新浪） → 去重 → qn_news_raw → 发布 NewsCrawledEvent
财报源（Tushare/东方财富） → qf_financial_statement
```

- K 线导入模式：FULL（清空重导）/ INCREMENTAL（按 `(symbol, period, bar_time)` 去重）；
- 校验：OHLC 合理性（high≥low、high≥open/close、low≤open/close）、时间连续性；
- 数据源可切换与自动降级（财联社/新浪/雪球为非官方接口，需可用性监控）。

### 16.3 策略引擎流程

- `StrategyEngineService.runAll(data, type)`：运行品种全部策略，返回候选（按置信度降序）；
- `runScreening(kline, type)`：盘后标的池单标的筛选；
- 内置策略：爆点形态 `breakout`（放量突破 20 日高点）、缠论买点 `chanlun`（一/二/三买）、期货趋势跟踪 `futures_trend`（均线金叉做多/死叉做空）；
- 指标层：MA / ATR / RSI / MACD / 成交量均线；
- 策略参数统一读 `qs_strategy_param_config` 激活版本，支持多版本与热更新。

### 16.4 风控流程

风控分层（确定性硬闸门）：

| 层级 | 规则示例 |
|:---|:---|
| 账户级 | 单日最大亏损、最大委托频率、保证金使用率上限 |
| 策略级 | 单信号最大仓位、每日最大交易次数 |
| 标的级 | ST/停牌黑名单、财务健康度黑名单、单票仓位上限 |
| 品种级 | 期货：保证金/强平/到期/夜盘；现货：价差/流动性 |

- `checkRisk`：统一风控入口；`checkBeforeTrade`：下单前同步强一致校验；`emergencyHalt`：紧急熔断；
- 关键熔断（Kill Switch）：`/risk/halt` 一键熔断，停止所有新订单 + 告警，需授权。

### 16.5 交易执行流程

一期交易执行限定为本平台内部 Paper 模拟执行。执行模式分为逐笔人工确认的 `PAPER_MANUAL` 和经用户预先授权的确定性策略自动 Paper `PAPER_AUTO`；另有不改变账户和资金状态的 `SHADOW` 跟踪模式。`PAPER_AUTO` 是模拟资金的自动化模拟执行，不是自动实盘，不得连接真实交易网关。

#### 16.5.1 订单生命周期状态机（目标态）

```
PENDING → SUBMITTED → PARTIAL_FILL → FILLED
                  ↘ CANCELLED / REJECTED / EXPIRED
```

一期通过内部 `PaperBrokerAdapter` 和 Paper 撮合服务处理模拟委托、撤单和成交，不配置交易所、券商或期货公司委托通道。面向未来真实交易的 `BrokerAdapter`/外部网关属于二期独立范围，不得被 Paper 模式复用或暗中启用。

#### 16.5.2 仓位计算（比例 → 金额 → 数量 → 按手取整）

```text
positionRatio = min(confidence × 0.5, maxPositionRatio)
targetAmount  = totalCapital × positionRatio
rawQty        = targetAmount / price
finalQty      = floor(rawQty / lotSize) × lotSize
```

股票 lotSize=100（1 手）；期货 lotSize=合约最小交易单位。

#### 16.5.3 交易主循环（时段闸门 + 幂等）

```text
1. 交易日/交易时段闸门（股票 9:30-11:30, 13:00-15:00；期货夜盘另配）
2. 拉取最新行情 MarketDataDTO
3. 全局风控 checkRisk（不通过则 return）
4. 遍历 runAll 信号：
   - 当日已执行跳过（幂等去重）
   - checkBeforeTrade 硬闸门
   - executeTrade 执行
   - 执行成功 markExecuted(信号)
```

PAPER_MANUAL 需要用户逐笔确认后进入内部 Paper 风控；PAPER_AUTO 仅在用户已授权账户、策略版本、品种、订单动作、运行时段、资金/风险限额和有效期范围内，由确定性策略信号生成内部模拟委托。每笔开仓、平仓、撤单和移仓步骤仍须重新执行最新行情、账户/组合风险、资金/保证金、时段、标的/合约和幂等检查；失败则拒绝、告警或暂停自动模式。两种模式均不调用真实交易通道。

幂等：`qt_trade_signal` 唯一键 `uk_signal_dedup(symbol, strategy_name, signal_type, trade_date)`，或 Redis `SETNX`。

Paper 自动模式必须在账户/策略/资产范围、最大风险、最大资金/保证金、允许动作、有效期和暂停条件均经用户授权后启用。启用后可以由确定性策略信号发起平台内部模拟委托，不要求每笔新开仓再人工点击；但每笔开仓、平仓和移仓步骤均必须逐笔通过最新行情、账户/组合风险、资金/保证金、交易时段、合约状态和幂等检查。任一检查失败则拒绝或暂停并告警。手动模式仍逐笔确认。模式配置变更、策略版本变更、风险限额变更和自动模式恢复均须重新授权或确认。两种模式都不能绕过 Paper 风控，且都不产生真实委托。

#### 16.5.4 移仓换月（期货）

`ContractRolloverService.rollover(accountId, oldContract, newContract)`，按 Saga / 补偿事务：创建移仓计划 → 平旧提交 → 确认平旧成交 → 开新提交 → 确认开新成交；外部交易异常进入 `NEEDS_RECONCILIATION`。

### 16.6 回测引擎流程（bar+1 成交模型，防前视偏差）

| 规则 | 说明 |
|:---|:---|
| bar+1 成交 | 信号在 K 线 N 收盘后生成，委托在 K 线 N+1 才允许成交（N+1 开盘价或触及价） |
| 复权口径 | `adjust_flag` 记录，默认前复权 FORWARD |
| 年化折算 | 按 `KlinePeriod.annualFactor()` 折算，不一律 ×√252 |
| 手续费/滑点 | 开平仓分别计手续费；滑点仅开仓计入 |
| 涨跌停约束 | 买入价不高于涨停价、卖出价不低于跌停价（A 股） |

`executeBacktest`（异步提交，写一条 PENDING 并在事务外执行）→ `PerformanceAnalyzer.analyze`（收益率、最大回撤、胜率、盈亏比、夏普、年化波动率）。

### 16.7 一期模拟实盘与 Paper 撮合引擎流程

“模拟实盘”指策略可使用盘中/最新行情在本平台模拟账户中按策略运行，不代表真实资金实盘或交易所接入。模拟交易范围包括限价/市价等经产品和执行子详设批准的模拟委托、撤单、部分/全部成交、建仓/开仓、平仓、持仓监控和期货移仓。仅允许已配置并授权的模拟账户及内部模拟适配器。

```text
PAPER_MANUAL：策略信号/计划 → 用户确认 → Paper风险闸门 → 内部委托/撮合
PAPER_AUTO：已授权策略信号 → 逐笔Paper风险闸门 → 内部委托/撮合
SHADOW：跟踪行情和策略结果，不创建Paper账户委托、资金流水或持仓
BACKTEST：历史点时数据回放，不访问实时Paper账户状态
```

`PAPER_AUTO` 必须具有账户级总开关和策略/品种级授权、资金及风险限额、订单动作白名单、运行时段、单日损失上限、最大委托频率、异常暂停条件和审计；Kill Switch 或风险熔断始终优先。自动退出、止损和移仓仅在相应规则经过明确授权并逐步通过风险校验时执行。订单只进入本地模拟撮合，禁止调用真实交易通道。

MVP 简化撮合：

- 成交价：按委托价 / 最新行情价撮合（限制价约束）；
- 手续费：佣金（万 2.5，最低 5 元）+ 印花税（卖出万 5）+ 过户费（万 0.1）；
- T+1：A 股 T+1，当日买入次日可卖；
- 涨跌停约束：默认 10%；
- 做空保证金率：默认全额（1.0）。

## 17. 核心业务规则与策略

### 17.1 账户与资金冻结/解冻/结算规则

| 操作 | 规则 |
|:---|:---|
| 冻结（freezeCash） | 可用资金 ≥ 冻结金额，否则 `QPF-CASH-001`；可用资金 −，冻结资金 ＋ |
| 解冻（releaseCash） | 冻结资金 ≥ 解冻金额，否则 `QPF-CASH-001`；冻结资金 −，可用资金 ＋ |
| 结算（settleFrozenCash） | 冻结资金 ≥ 成交金额，扣减冻结资金（真实消耗） |
| 持仓冻结（freeze） | 可用数量 ≥ 冻结数量，否则 `QPF-POSITION-001` |
| 持仓释放（release） | 冻结数量 ≥ 释放数量 |
| 卖出结算（settleSell） | 冻结/总数量 ≥ 卖出量；扣减数量，`realizedPnl += (价格 − 均价) × 数量` |
| 买入结算（settleBuy / addBought） | 数量增加，均价按买价均摊 |

资金流水采用复式记账：`quantpf_cash_ledger` 记录 `ledger_type / amount（正负）/ balance_after / reference / idempotency_key`，余额后置可审计。

### 17.2 订单状态机规则（已落地）

```
NEW ──► ACCEPTED ──► PARTIALLY_FILLED ──► FILLED
 │          │              │
 │          ├──► CANCEL_REQUESTED ──► CANCELED
 │          └──► REJECTED
 └──► REJECTED
```

- 终态：FILLED / CANCELED / REJECTED；
- 非法迁移抛 `QPF-ORDER-001`；
- 终态订单不可撤（`QPF-ORDER-003`）；
- 成交数量不得超过剩余可成交数量（`QPF-ORDER-002`）。

### 17.3 风控闸门规则（已落地）

`PaperRiskGate.evaluate(RiskContext)` 按顺序判定：

1. 全局熔断 → 拒 `QPF-RISK-002`；
2. 目标账户熔断 → 拒 `QPF-RISK-002`；
3. 市场未开盘（marketOpen=false）→ 拒 `QPF-RISK-003`；
4. 行情数据为空或超过 stale 窗口（默认 60 秒）→ 拒 `QPF-MARKET-001`；
5. 数量非正 → 拒 `QPF-REQ-001`；
6. 名义金额非正 → 拒 `QPF-REQ-001`；
7. 全部通过 → 接受。

### 17.4 幂等规则

| 场景 | 幂等键 | 唯一约束 |
|:---|:---|:---|
| 委托下单 | Idempotency-Key（请求头）+ client_order_id | `UNIQUE(idempotency_key)`、`UNIQUE(account_id, client_order_id)` |
| 成交 | execution_id + idempotency_key | `UNIQUE(execution_id)`、`UNIQUE(idempotency_key)` |
| 资金流水 | ledger idempotency_key | `UNIQUE(idempotency_key)` |
| 跟盘开始 | start_request_id | `UNIQUE(start_request_id)` |
| 跟盘停止 | stop_request_id | `UNIQUE(stop_request_id)` |

重复请求返回原结果（幂等命中），不重复执行副作用；幂等键与原始参数不一致时抛 `QPF-IDEMP-001`。

### 17.5 交易/手续费规则（模拟盘配置目标）

| 项 | 默认值 |
|:---|:---|
| 佣金率 | 0.00025（万 2.5），最低 5 元 |
| 印花税 | 卖出 0.0005（万 5） |
| 过户费 | 0.00001（万 0.1） |
| T+1 | 启用（A 股） |
| 涨跌停 | 启用（默认 10%） |
| 做空保证金率 | 1.0（全额） |

### 17.6 策略与回测规则（目标态要点）

- 确定性策略为主线，LLM 仅辅助；
- bar+1 成交模型（禁止同根 K 线成交，防前视偏差）；
- 复权口径默认前复权 FORWARD；
- 年化按 `KlinePeriod.annualFactor()` 折算；
- 仓位换算：比例 → 金额 → 数量 → 按手取整。

## 18. 交易流程状态机与决策规则

### 18.1 研究与交易状态机

```text
EVENT_NEW
  → EVENT_VERIFIED
  → THESIS_DRAFTED
  → INDUSTRY_MAPPED
  → CANDIDATES_SCREENED
  → FUNDAMENTALS_CHECKED
  → TECHNICAL_CONFIRMED
  → PLAN_APPROVED
  → PAPER_EXECUTED
  → MONITORED
  → EXITED
  → REVIEWED
```

任何节点均可以转为 `REJECTED`、`EXPIRED` 或 `HALTED`。状态转换必须保存操作者、时间、数据版本和理由。未经 `EVENT_VERIFIED` 的新闻不得生成 `PLAN_APPROVED`；缺少交易计划的信号不得进入模拟下单。

### 18.2 硬否决规则

以下规则不参与加权平均，任何一项触发即拒绝新仓位：

- 全局或账户熔断；
- 行情、财报、合约规则或交易日历数据过期；
- 事件仅有低可信度单一来源；
- 无法解释标的与事件之间的经济暴露；
- 预估成本使盈亏比不足；
- 止损不明确，或止损金额超过账户风险预算；
- 股票停牌、ST、涨跌停不可执行，或期货交割/强平风险不可控；
- 组合已有高度相关的同方向暴露；
- 交易计划依赖未来才能知道的信息。

### 18.3 候选评分卡

通过硬否决后，再使用 100 分评分卡排序。初始权重是待验证参数，不应永久固定：

| 维度 | 权重 | 评分要点 |
|:---|---:|:---|
| 事件可信度与新颖性 | 15 | 正式来源、独立交叉验证、未充分定价 |
| 行业传导链 | 20 | 直接暴露、影响强度、持续期、可证伪 |
| 标的质量/供需质量 | 20 | 股票财务质量，或商品供需和基差结构 |
| 估值/预期差 | 15 | 估值分位、一致预期、盈利弹性、库存周期 |
| 策略匹配 | 15 | 与爆点、禅道、趋势策略的规则匹配程度 |
| 执行和流动性 | 5 | 深度、滑点、交易时段、T+1/夜盘 |
| 风险收益比 | 10 | 预期收益、止损距离、相关性和尾部风险 |

建议初始门槛为 70 分进入观察、80 分以上才允许生成 Paper 交易计划；但任何分数都不能覆盖硬否决规则。系统应保存各维度的证据和理由，防止事后为达到分数而补写论据。评分不是收益预测。

### 18.4 新闻冲击和多头平仓规则

“重大利空直接多头平仓”应细化为分级处置，避免把不同事件一概而论：

| 等级 | 典型情形 | 建议动作 |
|:---|:---|:---|
| L0 | 普通噪声、重复报道、短期观点 | 不改变仓位 |
| L1 | 基本面轻微恶化、影响可证伪 | 暂停加仓，等待确认 |
| L2 | 事实确认并影响利润或供需，但非生存性 | 按规则减仓，重算止损和风险预算 |
| L3 | 重大监管、信用、战争升级、流动性或强平风险 | 停止新开仓，按组合计划快速去风险 |
| L4 | 账户、市场或交易通道失控 | 触发 Kill Switch，停止新订单并人工处置 |

L3 不等于无条件市价清空。股票可能涨跌停无法成交，期货可能连续涨跌停或流动性枯竭。系统应优先执行可行的减风险动作，同步记录未成交部分及后续处理。是否全平应结合事件类型、持仓方向、可执行性、保证金和组合相关性决定。

### 18.5 反确认偏误机制

每份交易计划必须增加：至少两个反方观点；一项出现即必须承认假设错误的关键反证；替代标的比较；新闻与价格方向不一致时的处理规则；在不知道最终结果时重新阅读原始材料的盲测复核。

LLM 可辅助生成反方问题和矛盾清单，但事实来源、评分、交易规则和风控结论必须由结构化规则和人工确认共同完成。

## 19. 股票、期货与现货差异化规则

### 19.1 股票规则

股票中长期交易主要研究盈利、现金流、估值、行业景气和风险偏好：

- 以日线和周线为主，盘口用于入场质量和流动性判断；
- 使用明确的复权口径，财务数据按报告期和真实披露时间管理；
- 财报发布日期、业绩预告和公告使用真实可见时间，不能用报告期结束时间代替发布时间；
- 将 T+1、涨跌停、停牌、ST、减持和流动性折价纳入回测；
- 不能因为“白马”而忽略估值过高、盈利下修和行业集中风险；
- 同一行业 2~3 只股票应作为一个风险簇合并计算，不能假定彼此独立。

### 19.2 期货规则

期货研究和执行至少增加以下字段：

```text
underlying / contract / exchange
contract_multiplier / tick_size / tick_value / margin_rate
trading_session / delivery_month / roll_rule
position_direction / open_close_flag / settlement_price
```

期货必须区分：方向判断正确但合约选择错误；现货逻辑正确但基差和期限结构不支持；杠杆、保证金和波动率导致提前止损；主力收益与连续合约回测收益不一致；研究周期与合约生命周期不匹配。

趋势策略建议加入 ATR 或波动率标准化，以便比较不同商品每手风险。移仓应记录旧合约平仓、新合约开仓、价差、手续费、滑点和保证金变化；不得用简单连续价格拼接代替可交易合约收益。临近交割且没有交割计划时，必须禁止继续持有。

### 19.3 共同框架与主要差异

共同框架是“事实 → 变量 → 传导 → 预期差 → 价格确认 → 风险预算”。

| 项目 | 股票 | 期货 |
|:---|:---|:---|
| 核心锚 | 盈利、现金流、估值 | 现货供需、库存、基差、期限结构 |
| 持有风险 | 公司治理、财报、停牌 | 保证金、强平、交割、移仓 |
| 价格表达 | 股价和成交量 | 合约价格、基差和期限结构 |
| 仓位单位 | 股数/金额 | 手数/保证金/每跳价值 |
| 退出约束 | T+1、涨跌停 | 夜盘、涨跌停、交割月、追加保证金 |
| 主要错误 | 把题材当盈利 | 把方向判断当成完整交易 |

## 21. 股票多头业务需求

### 21.1 股票多头业务定位

股票业务默认只支持买多，不把股票融券卖空纳入 Stage 1 的自动执行范围。股票多头交易的研究顺序为：

```text
事件/行业发现
→ 业务真实性核验
→ 盈利质量分析
→ 事件敏感度计算
→ 估值/预期差分析
→ 行业和价格确认
→ 股票买入交易计划
→ Paper 执行与复盘
```

### 21.2 业务真实性指标

系统应从年报、半年报、公告和产业数据提取或计算：

```text
core_revenue_ratio
core_profit_ratio
segment_gross_margin
capacity_or_project_evidence
customer_concentration
supplier_concentration
related_party_risk
audit_opinion_flag
regulatory_risk_flag
business_evidence_score
```

基本规则：

| 条件 | 处理 |
|:---|:---|
| 相关业务存在实际收入和利润 | 允许进入基本面研究 |
| 只有概念、没有收入或产能证据 | 标记 `CONCEPT_ONLY`，不得进入交易候选 |
| 收入存在但利润贡献无法确认 | 降低真实性和事件敏感度评分 |
| 重大关联交易或客户集中且无法解释 | 进入人工复核 |
| 审计意见、监管处罚或公告矛盾 | 触发硬风险或直接淘汰 |

### 21.3 盈利质量指标

系统至少计算以下指标，并保留指标版本：

```text
revenue_growth_1y / revenue_growth_3y
net_profit_growth_1y / net_profit_growth_3y
non_recurring_profit_ratio
operating_cashflow_to_net_income
receivable_growth_minus_revenue_growth
inventory_days
gross_margin_stability
roic / roe
net_debt_to_ebitda
goodwill_to_equity
cash_conversion_score
profit_quality_score
```

指标不能机械地单独决定交易。例如 `operating_cashflow_to_net_income` 偏低时，系统应进一步检查行业账期、项目周期、应收账款和存货，而不是自动认定为财务造假。

### 21.4 事件敏感度计算

股票事件敏感度以“事件变量变化对利润或 EPS 的影响”为核心：

```text
business_exposure = event_related_revenue_or_cost / total_revenue_or_cost
profit_elasticity = profit_change_rate / event_variable_change_rate
eps_sensitivity = estimated_eps_change / event_variable_change_rate
event_sensitivity_score = exposure × elasticity × duration × confidence
```

系统支持三种计算方式：

1. 公司披露的敏感性数据；
2. 分部收入、成本和历史价格数据的情景测算；
3. 行业可比公司和历史样本的回归或横截面估算。

每个敏感度结果必须标记 `MODELLED`、`DISCLOSED` 或 `INFERRED`，模型推导结果不能冒充公司正式披露。

### 21.5 估值与预期差指标

系统应保存点时估值和预期：

```text
pe_ttm / pe_forward / pb / ev_ebitda / fcf_yield
valuation_percentile_3y / valuation_percentile_5y
eps_estimate_current / eps_estimate_30d_ago / eps_estimate_90d_ago
earnings_revision_7d / earnings_revision_30d / earnings_revision_90d
guidance_vs_consensus
scenario_fair_value
expected_return_after_cost
```

建议使用三种情景估值：

```text
weighted_fair_value = bear_value × bear_probability
                   + base_value × base_probability
                   + bull_value × bull_probability
expected_return = weighted_fair_value / current_price - 1 - expected_cost
```

估值指标只用于判断预期差，不直接生成买入信号。即使预期收益为正，如果技术价格确认失败、行业趋势转弱或组合风险超限，也不得下单。

### 21.6 股票候选评分和买入条件

建议初始权重：

| 维度 | 权重 |
|:---|---:|
| 业务真实性 | 20 |
| 盈利质量 | 25 |
| 事件敏感度 | 30 |
| 估值/预期差 | 25 |

股票多头进入交易计划必须同时满足：

```text
硬否决规则全部通过
基本面总分达到门槛
事件方向明确或存在可验证的盈利变化
行业相对强度不明显走弱
breakout/chanlun/趋势条件至少一个触发
单笔风险、行业风险和组合风险通过
```

### 21.7 股票退出规则

股票多头必须区分：

- 基本面失效：事件没有兑现、盈利预测下修、业务真实性被证伪；
- 技术失效：结构破坏、趋势反转、突破失败；
- 风险退出：停牌、ST、重大监管、流动性枯竭、组合熔断；
- 目标兑现：估值达到目标、事件充分定价、移动止损触发。

股票不能因为“仍然看好”而无限期推迟止损，也不能用同一套退出阈值处理短期事件交易和中长期价值交易。

## 22. 期货/现货多空业务需求

### 22.1 期货和现货业务定位

期货/现货业务以商品产业链为研究对象，以期货、现货、远期、套保或价差工具表达观点。系统必须把以下三件事分开：

```text
产业判断：商品供需和利润方向
价格判断：期货、现货、基差和期限结构方向
交易表达：具体合约、方向、开平仓、保证金和移仓
```

### 22.2 商品研究数据到交易结论

| 研究数据 | 看多含义 | 看空含义 |
|:---|:---|:---|
| 库存 | 去库、库存低于季节性、库存拐点向下 | 累库、库存高于季节性、去库失败 |
| 供应 | 检修、减产、进口收缩、供应受限 | 复产、产量上升、进口增加、供应宽松 |
| 需求 | 开工率上升、订单改善、消费旺季 | 开工率下降、订单走弱、淡季延长 |
| 现货价格 | 现货强、成交改善、涨价传导 | 现货弱、降价、成交清淡 |
| 基差 | 基差走强或高于历史中枢 | 基差走弱或低于历史中枢 |
| 期限结构 | 近月强、正向紧张结构或结构改善 | 远月升水扩大、结构转弱或库存压力延长 |
| 生产利润 | 利润改善推动价格和产能行为 | 利润压缩、减产或产业链亏损 |
| 持仓结构 | 增仓上涨且趋势持续 | 增仓下跌且趋势持续，但要防拥挤 |

单项数据不能直接作为开仓条件。系统至少要求一项供需确认和一项价格确认共同成立。

### 22.3 期货多头规则

期货多头候选必须满足：

```text
供需或成本变量偏多
库存/基差/期限结构至少一项支持
期货价格趋势或突破确认
主力合约和流动性合格
距离交割和移仓窗口可控
保证金使用率和极端波动压力测试通过
```

交易动作：

```text
研究方向 = LONG
订单动作 = BUY_OPEN
退出动作 = SELL_CLOSE
```

### 22.4 期货空头规则

期货空头候选必须满足：

```text
供应恢复、库存上升、需求走弱、利润恶化或现货转弱中的至少一项
基差或期限结构没有与看空逻辑明显冲突
价格跌破关键结构或反弹失败
空头拥挤度、涨停风险和逼空风险可接受
合约流动性、保证金和止损可执行
```

交易动作：

```text
研究方向 = SHORT
订单动作 = SELL_OPEN
退出动作 = BUY_CLOSE
```

期货空头不能只因为价格已经下跌就开仓。价格快速下跌可能意味着利空已经充分反映，也可能存在技术性反弹、空头回补或逼仓风险。

### 22.5 现货看多和看空规则

现货方向研究结果定义如下：

| 现货观点 | 有库存/贸易敞口 | 无库存/贸易敞口 |
|:---|:---|:---|
| 看多 | 可研究买入、补库、期货多头或买入套保 | 只能通过期货/远期等可执行工具表达 |
| 看空 | 可研究去库、销售库存、期货空头或卖出套保 | 不生成无券现货空单，转为期货空头观察或回避 |
| 价差观点 | 可研究期现套利、跨品种或跨月组合 | 必须先确认双腿流动性、资金和交割条件 |

现货研究必须记录：

- 是否持有现货；
- 是否有采购或销售合同；
- 现货价格是否可成交；
- 期货合约是否可用于对冲；
- 基差风险是否可承受；
- 交割、仓储、运输和资金成本如何处理。

### 22.6 期货仓位和压力测试

期货仓位以止损金额、每跳价值和极端跳空为核心：

```text
per_contract_risk = stop_ticks × tick_value
                  + expected_slippage
                  + commission
                  + overnight_gap_buffer
contracts = floor(account_risk_budget / per_contract_risk)
```

还必须执行压力测试：

| 场景 | 测试内容 |
|:---|:---|
| 正常波动 | 近一年或近三年历史 ATR |
| 高波动 | 历史极端日、涨跌停附近波动 |
| 流动性下降 | 成交量下降、盘口变薄、滑点扩大 |
| 隔夜跳空 | 下一交易时段不利方向跳空 |
| 连续涨跌停 | 止损无法成交的连续日 |
| 移仓 | 旧合约和新合约价差、手续费、保证金变化 |
| 相关性冲击 | 同产业链多个合约同时同向波动 |

压力测试未通过时，系统不得因为保证金余额仍然充足而放行开仓。

### 22.7 期货合约生命周期

每个期货交易计划必须明确：

```text
主交易合约
备用合约
最后交易日
交割月规则
移仓触发日期或条件
移仓价差上限
连续合约回测映射方法
```

连续合约只用于分析和筛选，真实交易和回测执行必须回到具体合约。移仓动作应拆成两笔或多笔真实订单，分别记录成交价、成交量、手续费、滑点和价差。

## 23. 研究到交易的完整业务流程

### 23.1 端到端流程

```text
数据源配置
  → 数据采集
  → 去重、清洗、时间对齐
  → 数据质量评级
  → 数据授权与供应商可用性检查
  → 市场状态与制度状态检查
  → 事件/行业/商品研究
  → 多空假设
  → 候选标的/合约池
  → 基本面/供需评分
  → 价格和策略确认
  → 工具权限检查
  → 交易计划
  → 组合风险检查
  → Paper/Shadow 下单
  → 撮合、成交、持仓和保证金
  → 监控、退出和复盘
```

### 23.2 研究事件状态

```text
NEW
→ VERIFIED
→ VARIABLE_MAPPED
→ THESIS_LONG / THESIS_SHORT / THESIS_NEUTRAL
→ CANDIDATE_READY
→ EXPIRED / DISMISSED / REVIEWED
```

事件进入 `THESIS_SHORT` 不代表已经允许开空，仍需经过价格确认和工具权限检查。

### 23.3 交易计划状态

```text
DRAFT
→ FUNDAMENTAL_APPROVED
→ PRICE_CONFIRMED
→ INSTRUMENT_VALIDATED
→ RISK_APPROVED
→ PAPER_PENDING
→ PAPER_OPENED
→ MONITORED
→ PARTIAL_CLOSED / CLOSED
→ REVIEW_PENDING
→ REVIEWED
```

失败状态包括：

```text
REJECTED_DATA
REJECTED_FUNDAMENTAL
REJECTED_PRICE
REJECTED_TOOL
REJECTED_RISK
EXPIRED
HALTED
```

### 23.4 下单前检查顺序

```text
1. 交易日和交易时段
2. 数据质量和最新行情
3. 产品和合约状态
4. 方向与订单动作一致性
5. 股票买入/期货开平仓权限
6. 价格、数量和最小变动单位
7. 止损距离和单笔风险金额
8. 组合相关性和行业/商品簇暴露
9. 保证金、可用资金和压力测试
10. Kill Switch、账户熔断和幂等键
11. Paper/Shadow 模拟撮合
12. 写入订单、审计和信号执行记录
```

### 23.5 交易方向与订单动作校验

| 研究方向 | 订单动作 | 允许条件 |
|:---|:---|:---|
| `LONG` | `BUY_OPEN` | 期货合约可交易、风险通过 |
| `LONG` | 股票买入 | 股票状态正常、资金和涨跌停检查通过 |
| `SHORT` | `SELL_OPEN` | 期货可交易，或股票具备合规空头权限 |
| `LONG` 期货持仓退出 | `SELL_CLOSE` | 存在可用多头持仓 |
| `SHORT` 期货持仓退出 | `BUY_CLOSE` | 存在可用空头持仓 |
| `HEDGE_SHORT` | `SELL_OPEN` | 存在现货风险、套保比例和基差规则 |
| `SPREAD` | 多腿组合订单 | 所有腿均通过流动性和保证金检查 |

任何“开仓方向”和“开平仓标志”不一致的请求必须拒绝，并写入审计日志。

### 23.6 研究流、交易流与验证流的分离

~~~text
研究流：数据监听 → 事实核验 → 解释/预测 → 候选决策卡 → 进入/退出观察池
交易流：触发预警 → 重新检查 → 策略适配 → 交易计划 → Paper/Shadow 模拟成交 → 持仓管理
验证流：保存当时可见快照 → 生成成功/失败标签 → 计算成本后绩效 → 样本外/滚动/校准 → 规则迭代
~~~

三条流可以共享数据和标的身份，但不得互相越权：研究流不能直接生成真实委托，交易流不能静默修改研究事实，验证流不能用未来数据重写当时的研究结论。

## 24. 业务成功标准、绩效评价与迭代路线（总纲层）

> 本章只定义总纲层的成功方向、评价维度和迭代门槛，不替代详细技术验收、测试用例或合规审查。

### 24.1 数据与业务成功标准

```text
所有事实可追溯到来源
所有数据有可见时间
修订数据不会覆盖历史版本
所有数据记录来源、授权状态、允许用途和数据延迟
历史数据标记完整、部分或不可用，不把缺失历史伪装成完整样本
智能体搜索结果能回到原始/授权来源，重大结论有人工确认记录
个人使用、团队内部使用和商业使用的边界不混用
数据冲突能阻止新开仓
现货数据区分观察价格和可交易工具
量价字段口径一致
期货持仓量、基差和期限结构可回放
```

### 24.2 候选筛选成功标准

```text
股票可生成业务真实性、盈利质量、事件敏感度和估值/预期差结果
期货可生成供应、需求、库存、现货、基差和期限结构结果
量价可生成明确状态
每个候选有支持证据和反方证据
每个淘汰对象有淘汰原因
候选不直接等于交易指令
```

### 24.3 策略适配成功标准

```text
策略不参与第一阶段标的价值筛选
每个策略有适用范围和禁用条件
策略匹配基于K线、成交量、持仓量、波动率和市场状态
没有匹配策略时进入观察而不是强行交易
策略触发前必须重新检查研究假设
```

### 24.4 概率验证成功标准

```text
信号成功定义提前冻结
历史回放不使用未来数据
有样本外和滚动验证
概率显示样本数和置信区间
概率和实际结果可校准
有价格-only和完整流程对照
有未交易信号记录
```

### 24.5 组合选择成功标准

```text
候选具备风险簇标签
同一观点的不同表达可比较
加入组合后的边际风险可计算
期货有保证金、跳空、涨跌停和移仓压力测试
组合可禁止新增风险但允许减仓和平仓
```

### 24.6 绩效评价

不只看收益率和胜率，还要看：

```text
净期望收益
最大回撤
回撤持续时间
平均盈利/亏损
最大不利波动
样本外表现
概率校准
滑点和手续费
收益集中度
风险簇贡献
基准超额收益
未交易候选对照
```

### 24.7 实施路线

```text
V4-P0：数据来源、事实链和时间可见性
V4-P1：四条候选发现通道
V4-P2：股票基本面和期货供需判断
V4-P3：量价分析模块
V4-P4：观察池、等待和预警
V4-P5：概率验证和基准/消融实验
V4-P6：策略适配和Paper交易
V4-P7：组合选择、压力测试和复盘归因
V4-P8：二期量价主导机会发现、因子增强、跨资产交易时机研究、完整看图和高级订单流
V4-P9：二期自动实盘上线前的合规、数据授权、接入安全和人工放行门禁（当前不实施）
```

### 24.8 V4 最终业务定义

> QuantPF 是一个以多源、可追溯、点时数据为基础，以量价/价格行为、因子和市场状态为二期主导机会输入，以新闻、财报、研报、商品供需、现货、基差、期限结构为可选解释和增强输入，覆盖A股、港股、美股、期货和外汇/海外经纪商品，以股票买多、期货多空、现货套保/价差为交易表达，以候选筛选、策略适配、等待预警、条件概率、组合选择、Paper/Shadow 和复盘归因为核心闭环的个人多资产交易研究系统。

> 系统不预测未来，不承诺必涨或必跌；系统只在当时可见信息基础上，筛选具有相对条件优势、明确触发条件、可执行交易工具和可计算风险的候选对象。任何真实交易能力仍须独立审批、安全审查和放行，Stage 1 继续只允许 SIM/PAPER/SHADOW/READ_ONLY。

### 24.9 详细设计阶段仍需确认的事项

以下事项不是 V4 总纲缺失，而是进入详细设计、数据采购和实施验收前需要固化的配置或合同内容：

- Tushare Pro 年度订阅的具体产品、接口字段、历史范围、调用额度、延迟、保存和商业使用权限；
- 股票、期货品种范围，以及新闻、财报、研报、行情和商品数据的最终供应商与授权合同；
- 每类资产和每类策略的预测周期、成功/失败标签、止损止盈和超时规则；
- 市场状态、量价状态、评分卡、风险簇和组合风险预算的具体阈值与校准方法；
- Paper/Shadow 的成交、滑点、涨跌停、跳空、移仓和成本模拟口径；
- 二期自动实盘的监管适用性、券商/期货公司接入、程序化交易报告、权限隔离和人工放行方案。

这些内容应在详细设计、数据授权确认和测试方案中单独固化，不应为了让总纲看起来“完整”而提前虚构固定参数。

## 25. Java Spring Boot + Dify 智能体的实现可行性与职责边界

### 25.1 总体结论

本系统用 Java Spring Boot + Dify 智能体实现是可行的，尤其适合一期“多源研究、候选筛选、策略适配、Paper/Shadow 和复盘”的目标。主要难点不在于框架能否调用，而在于数据授权、历史回溯、点时数据、指标口径、回测无前视、期货规则、AI 输出审计和未来实盘合规。

### 25.2 Spring Boot 负责确定性业务和交易研究底座

Spring Boot 侧应负责：

~~~text
数据源适配与采集
数据清洗、标准化、去重和版本管理
标的/合约/现货身份与交易日历
K线、成交量、成交额、持仓量、基差、期限结构和量价指标计算
新闻/财报/研报/产业数据的时间可见性与授权状态
候选筛选、硬过滤、市场状态和风险簇
概率标签、历史回放、样本外、滚动验证和校准
策略适配、交易计划、等待状态和预警
组合选择、仓位、保证金、压力测试和 Paper/Shadow
模拟订单、成交、持仓、止损、止盈、移仓和复盘归因
审计、权限、幂等、熔断、监控和数据质量
新闻原文、研究任务、AI草稿校验、研究事件持久化、版本和下游通知
一期量价特征基础、状态和二期交易时机接口预留
~~~

这些内容必须可重复、可测试、可回放，不应依赖模型每次自由生成的文本。

### 25.3 Dify 智能体负责研究辅助和语言交互

Dify 适合承担：

~~~text
新闻、公告、财报、研报和产业材料的检索编排
原文事实提取和来源引用
事件分类、影响变量识别和产业链传导链草稿
支持证据、反方证据和关键证伪条件整理
专业术语转普通语言
研究决策卡草稿和复盘摘要
根据结构化数据生成用户可读的解释和待确认问题
面向“今日机会、行业/品种机会、个股研究、期货多空和消息是否过时”的自然语言问答
辅助解释一期量价状态和二期量价时机研究结果，但不负责量价指标、交易时机统计或订单决策
~~~

Dify 不得负责：

~~~text
修改原始事实或补造缺失数据
最终概率、收益、回撤和仓位计算
替代确定性量价指标和回测引擎
绕过数据质量、授权、风控或人工确认
直接提交真实股票/期货委托
~~~

### 25.4 推荐的协作链路

~~~text
Spring Boot 采集与保存原始/结构化数据
→ 生成点时快照、来源和授权元数据
→ 创建研究任务并调用 Dify Workflow/Agent
→ Dify 返回带来源引用的新闻/研究结构化草稿
→ Spring Boot 校验并保存研究事件和分析版本
→ Spring Boot 发布研究事件并触发后续研究流程
→ Spring Boot 计算筛选、量价、概率、策略和风险结果
→ 用户查看结论—证据—风险—下一步并确认
→ Paper/Shadow 模拟交易
→ Spring Boot 保存结果并由 Dify 辅助复盘
~~~

Dify 与 Spring Boot 之间应使用明确的输入输出契约、模型/提示词版本、超时、重试、幂等、人工审核状态和完整审计链。Dify 暂时不可用时，确定性行情、筛选、Paper 和风控链路应能够降级运行；研究解释可以标记为待补充，不得因此伪造结论。

### 25.5 实现可行性分级

| 能力 | Spring Boot + Dify 可行性 | 说明 |
|:---|:---|:---|
| 新闻/财报/研报整理 | 高 | Dify 做检索和摘要，Spring Boot 保存来源与版本 |
| 股票基本面筛选 | 高 | 结构化财报和规则计算由 Spring Boot 完成 |
| 商品供需/基差研究 | 中高 | 关键在数据供应和口径统一，不是模型调用本身 |
| 量价分析 | 高 | 指标和状态由确定性代码计算，Dify 负责解释 |
| 二期量价关系优化与交易时机研究 | 中高 | 一期先完成数据、特征、状态、标签和回放预留；二期由 Spring Boot 负责统计验证和时机状态，Dify 负责解释 |
| 候选卡和预警 | 高 | 规则引擎负责状态，Dify 负责可读说明 |
| 自然语言机会问答 | 高 | Spring Boot 提供结构化查询和门禁结果，Dify 负责意图理解、组织证据和生成可读回答 |
| 历史回测和概率验证 | 高 | 必须点时数据、无前视和成本模型完整 |
| 组合与风险预算 | 高 | 确定性计算和硬闸门，不交给 Dify |
| 本地模拟盘 | 高 | Java 订单状态机和撮合边界可独立运行 |
| 二期自动实盘 | 技术上可行但门槛高 | 还需数据/软件授权、券商/期货公司接入、程序化交易规则、安全和人工放行 |

### 25.6 可行性结论

一期建议坚持“Spring Boot 为确定性主系统，Dify 为研究智能体和解释层”的架构。只要不把 Dify 当作交易主引擎，不把第三方数据的年订阅误当成无限授权，并且建立点时历史和 Paper 验证链路，系统的目标功能具有较高实现可行性。

### 二、产品设计文档

**目录：** `D:\我的文档\私人\量化\产品设计文档\`

**作用：** 详细说明各功能界面的信息组织、核心操作、交互状态、用户确认点、异常提示和验收方式，并为 Dify 与 Spring Boot 各部分提供可指导 AI 落地代码仓的详细实现方案。产品设计文档既描述用户如何完成业务操作，也要把界面交互与后端 API、Workflow、领域状态及权限门禁对应起来。

每份产品设计文档应至少说明：

- 面向用户的功能目标、页面入口、角色和权限；
- 目标用户能力层级、引导/审核/专业模式、系统预填字段与用户必填字段责任矩阵；
- 普通用户低输入流程、渐进式信息披露、术语解释、普通语言错误/阻断说明及操作步数验收；
- 页面信息结构、核心操作流程、状态变化和审核/覆盖操作；
- 加载、空数据、错误、超时、数据过期、授权不足和降级状态；
- Vue 页面与 Spring Boot API、领域状态、Dify Workflow 的对应关系；
- Dify 输入输出、Spring Boot 校验和确定性处理边界；
- 可供 AI 按步骤施工代码仓的组件/服务映射、契约、测试与验收标准。

产品设计文档应以总纲和详设文档为业务及架构基线，不得仅凭原型推导交易规则；也不得让 Dify 的交互结果绕过 Spring Boot 的数据核验、人工确认、风险控制和 Paper 门禁。

### 三、文档层级关系与维护规则

```text
《量化交易系统完整设计方案说明书_V4.md》
  业务目标、原则、范围和总纲级流程
        ↓

        ↓

  整体流程及各功能模块的程序架构和详细落地方案
        ↓

  用户界面、核心操作及 Dify/Spring Boot 逐功能代码落地指导
        ↓
代码仓实现、自动化测试和落地进度更新
```

文档维护要求：

1. 新增、改名或废弃详设/产品设计文档时，更新本索引中的编号、路径、作用和状态。
2. 业务原则变化先更新总纲；模块架构或契约变化同步技术分册和对应详设；界面及操作变化同步产品设计文档。
3. 文档中的“已落地”状态以《总体业务架构及记录落地功能进度.md》为准；方案文档不得替代落地台账。
4. AI 生成或修改代码时，应以对应详设和产品设计文档为任务依据，并遵守总纲及代码仓正式契约、测试和施工门禁。
