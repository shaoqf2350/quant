## 26. 总体业务架构

### 26.1 逻辑架构

```
┌──────────────────────────────────────────────────────────────┐
│              前端 Vue3 + Element Plus + ECharts（plus-ui）      │
│  驾驶舱 | 标的 | 行情 | 新闻 | 财报 | 标的池 | 策略 | 回测      │
│         | 账户 | 持仓 | 订单 | 成交 | 风控 | 接入 | 运维        │
└───────────────────────────────┬──────────────────────────────┘
                                │ HTTP REST
┌───────────────────────────────▼──────────────────────────────┐
│              单体 Spring Boot（ruoyi-admin 入口）              │
│  quantpf-marketdata ─► quantpf-strategy ─► quantpf-risk       │
│        │                                    ▲  │              │
│  quantpf-research / quantpf-finance ─────────┘  │              │
│                              ┌─────────────────┘              │
│                              ▼                                │
│                        quantpf-execution                      │
│  quantpf-backtest ──────────────────────► quantpf-execution   │
│  任务调度：XXL-JOB；通信：Spring Events + 服务直调 + Redis     │
└───────────────┬───────────────────────────────────────────────┘
                │
   ┌────────────┼──────────────┬──────────────────┐
   ▼            ▼              ▼                  ▼
 MySQL        Redis        时序库/可选DuckDB   对象存储/可选
(交易/研究)  (缓存/锁)     (行情高频数据)       (原始快照/附件)
```

### 26.2 后端模块划分与职责

| 模块 | 设计职责 | 当前落地状态 |
|:---|:---|:---|
| `quantpf-common` | 实体、Mapper、枚举、共享 DTO/VO、工具、异常、公共配置、交易日历基础服务 | 空骨架（pom 占位） |
| `quantpf-data` / `marketdata` | 历史 K 线、实时行情（WS）、新闻多源抓取、原始快照、数据质量、时间版本、财报数据源适配、行情缓存 | 空骨架（pom 占位） |
| `quantpf-research` | 研究任务、Dify适配、AI草稿校验、研究事件、证据链、版本和下游事件通知 | 空骨架（pom 占位） |
| `quantpf-strategy` | 策略引擎、技术指标、量价状态、形态识别、标的池筛选和二期交易时机预留 | 空骨架（pom 占位） |
| `quantpf-risk` | 确定性风控闸门、新闻情绪、黑名单、熔断 | **已实现**（PaperRiskGate / 内存 + 持久化） |
| `quantpf-finance` | 财报解读、基本面因子、财报日历、账务 / 台账 | **已实现**（模拟盘账务与台账） |
| `quantpf-execution` | 订单、券商适配、回报、持仓、移仓、模拟盘撮合 | **已实现**（Paper 订单 / 撮合 / 状态机） |
| `quantpf-backtest` | 回测引擎边界 | 仅接口占位（BacktestExecutionBoundary） |
| `quantpf-job` | QuantPF XXL-JOB Handler 入口 | 仅接口占位（PaperApplicationServicePort） |
| `quantpf-domain` | 领域模型（实体 / 枚举 / 值对象 / 仓储） | **已实现** |

> 说明：实际代码中 `quantpf-common / marketdata / research / strategy` 仅有 `pom.xml` 而无 `src`，为后续业务施工预留的骨架模块；`domain / execution / finance / risk` 为核心并已落地，`backtest / job` 为接口占位。

### 26.3 数据分层存储架构

```
第 1 层 基础信息（MySQL）   qm_stock_basic / qs_strategy_config / qs_broker_config
第 2 层 行情数据（时序库）   qs_kline_bar / qs_order_book / qs_tick_data
第 3 层 业务数据（MySQL）    qt_trade_order / qt_trade_signal / qt_position / qt_trade_record
第 4 层 分析数据（MySQL）    qn_news_* / qn_research_event_* / qf_financial_* / qs_backtest_* / qs_stock_pool*
缓存层（Redis）             最新盘口 / 最新 K 线 / 最新 Tick / 持仓快照 / 基础信息缓存
```

| 数据类型 | 方向 | 频率 | 方式 |
|:---|:---|:---|:---|
| 基础信息 | 数据源 → MySQL | 日级 | XXL-JOB |
| K 线 | 数据源 → MySQL/DuckDB | 分钟 ~ 日级 | 增量（bar_time 去重） |
| 盘口 | QMT/CTP → Redis → DuckDB | 秒级 | 实时写 Redis，异步落盘 |
| Tick | QMT/CTP → Redis → DuckDB | 毫秒级 | 实时写 Redis，批量落盘 |
| 持仓 | 经纪商 → MySQL | 秒级(盘中)/日级(盘后) | 接口同步 |

### 26.4 关键架构决策（ADR 摘要）

| 编号 | 决策 | 选择 | 理由 |
|:---|:---|:---|:---|
| ADR-1 | 部署形态 | 单体 + Maven 多模块 | 事务一致、调试链路短、运维成本低，按模块预留拆分点 |
| ADR-2 | 交易主引擎 | 确定性 Java 策略 | 可回测、可复现、可审计 |
| ADR-3 | LLM 角色 | 仅辅助（情绪 / 财报 / 点评） | 避免幻觉直接下单 |
| ADR-4 | 风控 | 确定性硬闸门 | 资金安全不依赖概率模型 |
| ADR-5 | 调度 | XXL-JOB（3.1.0） | 可视化、重试、单节点防重 |
| ADR-6 | 多品种 | `product_type` + 策略 / 适配器模式 | 一套代码覆盖多品种 |
| ADR-7 | 行情存储 | 时序库（DuckDB / TSDB） | 高频数据不适合 MySQL |
| ADR-8 | 执行 | 独立网关进程（CTP JNI 网关、QMT xtquant 网关） | Java 不直接调 C++ / Python 底座 |

## 27. 业务领域模型

### 27.1 产品 / 品种

| 枚举 | 值 | 说明 |
|:---|:---|:---|
| ProductType | STOCK / FUTURE / SPOT | SPOT 为未来扩展，Stage 1 只受理 STOCK 与 FUTURE |

多品种统一通过核心表上的 `product_type` 字段 + 策略 / 适配器模式实现一套代码覆盖。期货特有：保证金、强平、到期、移仓、夜盘、开平仓方向（BUY_OPEN / SELL_OPEN / BUY_CLOSE / SELL_CLOSE）。

### 27.2 核心领域对象总表

| 领域对象 | 表（已落地 Flyway） | 说明 |
|:---|:---|:---|
| 标的 / 合约 | `quantpf_instrument` | 股票 / 期货合约基础信息（代码、品种、交易所、最小变动价位、手数等） |
| 交易日历 | `quantpf_trading_calendar` | 各市场交易日与开收盘时段 |
| 行情 K 线 | `quantpf_market_bar` | 统一 K 线（OHLCV、成交额、复权口径、来源） |
| 新闻 | `quantpf_research_news` | 原始新闻（去重按 external_id+source、content_hash） |
| 财报 | `quantpf_financial_statement` | 三大报表原始数据（按(标的,报告期,报表类型,源)唯一） |
| 策略信号 | `quantpf_strategy_signal` | 策略产生的交易信号 |
| 策略 | `quantpf_strategy` | 策略定义（编码/版本/状态/JSON 定义） |
| 回测运行 | `quantpf_backtest_run` | 回测任务（参数、状态 CREATED/RUNNING/SUCCEEDED/FAILED/CANCELED） |
| 回测指标 | `quantpf_backtest_result` | 回测评测指标（按指标编码） |
| 交易账户 | `quantpf_trading_account` | 模拟资金账户（初始/可用/冻结资金、状态） |
| 资金台账 | `quantpf_cash_ledger` | 资金流水（复式记账，余额后置） |
| 持仓 | `quantpf_position` | 持仓（数量/可用/冻结/均价/已实现盈亏） |
| 模拟委托 | `quantpf_paper_order` | 模拟盘委托订单（状态机 + 冻结资金/数量） |
| 模拟成交 | `quantpf_paper_execution` | 模拟盘成交回报 |
| 风控规则 | `quantpf_risk_rule` | 可配置风控规则（JSON 定义） |
| 风控快照 | `quantpf_risk_snapshot` | 风控状态快照（风险状态/评分/原因） |
| 交易熔断 | `quantpf_trading_halt` | 熔断记录（GLOBAL/ACCOUNT/INSTRUMENT） |
| 任务执行审计 | `quantpf_job_execution_audit` | 调度任务执行审计（JOB/RUN 明细分账） |
| 操作审计 | `quantpf_audit_record` | 任意业务操作审计日志 |
| 跟盘会话 | `quantpf_paper_follow_session` | 模拟跟盘会话（账户+策略+模式唯一活跃槽位） |

### 27.3 关键业务概念

- **账户类型（AccountType）**：PAPER（落地阶段仅此一种）；`quantpf_trading_account.account_type = 'PAPER'`（CHECK 约束）。
- **账户状态（AccountStatus）**：ACTIVE / HALTED / CLOSED。
- **订单方向（OrderSide）**：BUY / SELL（Stage 1 模拟盘形态）。
- **订单类型（OrderType）**：MARKET / LIMIT。
- **订单状态（OrderStatus）**：NEW / ACCEPTED / PARTIALLY_FILLED / FILLED / CANCEL_REQUESTED / CANCELED / REJECTED。
- **成交状态（ExecutionStatus）**：ACCEPTED / REJECTED / FILLED。
- **风控状态（RiskStatus）**：CLEAR / WARNING / HALTED / REJECTED。
- **熔断范围（TradingHaltScope）**：GLOBAL / ACCOUNT / INSTRUMENT。
- **跟盘模式**：PAPER（CHECK 约束仅允许 PAPER）。
- **跟盘会话状态**：RUNNING / STOPPED。

### 27.4 已落地的值对象 / 领域对象

- `Money`：金额（BigDecimal，8 位小数），支持 add / subtract / multiply、正负判断；
- `Quantity`：数量（8 位小数，非负），支持加减、比较；
- `ClientOrderId` / `RequestId` / `OrderIdempotencyKey`：业务标识值对象（非空、长度 ≤ 128）；
- `Instrument`、`TradingAccount`、`Position`、`PaperOrder`、`PaperExecution`：核心聚合 / 实体。

## 28. 数据存储与数据库设计参考

### 28.1 库表分类

| 分类 | 表 |
|:---|:---|
| 基础信息 | quantpf_instrument、quantpf_trading_calendar、quantpf_strategy、quantpf_risk_rule |
| 行情数据 | quantpf_market_bar（设计上可下推 DuckDB/TSDB） |
| 研究数据 | quantpf_research_news、quantpf_financial_statement |
| 交易账务 | quantpf_trading_account、quantpf_cash_ledger、quantpf_position、quantpf_paper_order、quantpf_paper_execution |
| 风控 | quantpf_risk_snapshot、quantpf_trading_halt |
| 回测 | quantpf_backtest_run、quantpf_backtest_result |
| 策略信号 | quantpf_strategy_signal |
| 跟盘 | quantpf_paper_follow_session |
| 审计 | quantpf_audit_record、quantpf_job_execution_audit |

### 28.2 关键表语义（已落地）

- `quantpf_instrument`：标的/合约台账，唯一键 `(instrument_code, exchange_code)`；
- `quantpf_trading_account`：模拟账户，`account_type='PAPER'`、`currency='CNY'`；
- `quantpf_paper_order`：委托表，含冻结资金 `frozen_cash`、冻结数量 `frozen_quantity`，状态由状态机驱动；
- `quantpf_paper_execution`：成交表，关联 `order_id`，含成交价/量/手续费；
- `quantpf_cash_ledger`：台账，`ledger_type`（PAPER_BUY_SETTLEMENT / PAPER_SELL_SETTLEMENT 等）；
- `quantpf_position`：持仓，`available_quantity` / `frozen_quantity` / `average_cost` / `realized_pnl`；
- `quantpf_paper_follow_session`：跟盘会话，生成列 `active_slot` 保证同(账户,策略,模式)唯一 RUNNING；
- `quantpf_audit_record` / `quantpf_job_execution_audit`：审计事实表。

### 28.3 索引与约束

V1_8_0 为全部表补齐查询索引（按 `instrument_id/time`、`account_id/status`、`trade_date` 等）；核心业务表均带 CHECK 约束与唯一键，数据库层保证数据一致性。

### 29.5 LLM 使用边界

允许 LLM：

- 抽取公告和研报中的事实候选；
- 归类事件、行业、商品和影响变量；
- 生成传导链初稿和反方问题；
- 对不同来源进行矛盾摘要；
- 辅助解释财报和产业数据。
- 辅助解释数据质量、来源和量价状态。

不允许 LLM：

- 修改原始数据；
- 伪造缺失数据；
- 把预测写成事实；
- 绕过数据质量或风控状态；
- 直接生成可执行订单；
- 自动将“利空”转换为 `SELL_OPEN`。
- 直接把新闻分析结果写入事实主表、研究事件主表或交易信号表；
- 直接修改量价状态、交易时机状态或触发交易执行。

新闻分析落地链路必须是：

```text
Spring Boot采集并保存新闻原文
→ 创建研究任务
→ Dify返回摘要、重大程度候选、行业/个股关联候选和利多/利空候选
→ Spring Boot校验引用、时间、授权、身份和冲突
→ 保存AI草稿与核验后的研究事件
→ Spring Boot发布研究事件并通知后续流程
```

Dify 数据库或向量库不作为研究事件、事实、行情和量价特征的权威数据源。

### 31.1 认证授权（底座，简要）

### 31.2 资金安全红线

| 项 | 要求 |
|:---|:---|
| Kill Switch | `/risk/halt` 一键熔断，停止所有新订单 + 告警，需授权 |

| 审计日志 | 所有下单/撤单/参数修改记操作日志（who/when/what） |
| 环境隔离 | 生产配置与测试隔离；默认 `account_type=VIRTUAL`，实盘需显式开启 |

### 33.5 已落地的核心业务流程

#### 33.5.1 模拟委托下单（`POST /api/quant/order/paper`）

```text
1. 前置校验：estimatedNotional / fillPrice / quantity 必填且为正；侧(Side)/类型(OrderType)合法
2. 风控闸门 evaluate(RiskContext)：
   - 全局熔断 → 拒（QPF-RISK-002）
   - 账户熔断 → 拒（QPF-RISK-002）
   - 市场未开盘 → 拒（QPF-RISK-003）
   - 行情数据过期（>1分钟）→ 拒（QPF-MARKET-001）
   - 数量/名义金额非法 → 拒（QPF-REQ-001）
3. 持久化提交（独立事务）：
   - SELECT ... FOR UPDATE 锁定账户
   - 幂等/重复检查：按 idempotency_key 或 (account_id, client_order_id)
   - BUY：校验可用资金 → 冻结资金；SELL：校验可用持仓 → 冻结持仓数量
   - 更新账户余额、插入委托（status=NEW）
4. 撮合成交 settle（独立事务）：
   - 生成 execution_id，写成交、写资金台账（复式记账，余额后置）
   - 更新账户资金 / 持仓（买入均摊成本，卖出结算已实现盈亏）
   - 更新委托状态为 FILLED（或 PARTIALLY_FILLED）
```

#### 33.5.2 模拟委托撤单（`POST /api/quant/order/{id}/cancel`）

```text
1. SELECT ... FOR UPDATE 锁定委托
2. 已 CANCELED → 幂等返回；已 FILLED/REJECTED（终态）→ 拒绝（QPF-ORDER-003）
3. 解冻资金（冻结资金 -，可用资金 +）；解冻持仓（冻结数量 -，可用数量 +）
4. 更新账户余额、委托冻结字段清零、状态置 CANCELED
```

#### 33.5.3 风控熔断 / 恢复（`/api/quant/risk`）

- `status`：返回 CLEAR（未熔断）或 HALTED（熔断原因）；
- `halt(reason)`：全局熔断 + 写 `quantpf_trading_halt`（scope=GLOBAL） + 写 `quantpf_risk_snapshot`（status=HALTED，risk_score=1）；
- `resume(reason)`：恢复 + 更新熔断记录（resumed_at/resume_reason） + 写 CLEAR 快照。

#### 33.5.4 模拟跟盘会话（`/api/quant/paper`）

- `follow-start`：校验 mode=PAPER、账户为 PAPER 且 ACTIVE、策略为 ACTIVE → 查重（start_request_id 幂等）→ `NOWAIT` 锁查同槽位运行中会话（冲突则 QPF-FOLLOW-001）→ 插入 RUNNING 会话 + 写审计 `PAPER_FOLLOW_START`；
- `follow-stop`：幂等（stop_request_id）→ 校验会话存在且 RUNNING → 置 STOPPED（stopped_at/stop_reason）+ 写审计 `PAPER_FOLLOW_STOP`；
- 唯一性由生成列 `active_slot = account_id:strategy_id:mode`（仅 RUNNING 非 NULL）+ 唯一键保证。

#### 33.5.5 审计与任务执行记录

- 操作审计：所有模拟盘命令写入 `quantpf_audit_record`（request_id/actor/action/aggregate/result/detail），查询 `/api/quant/audit/page`；
- 任务执行审计：`quantpf_job_execution_audit` 记录每次调度运行（job_name/execution_id/scheduler_type/status/error），查询 `/api/quant/job/execution/page`。

## 35. 术语表与附录

### 35.1 术语表

| 术语 | 含义 |
|:---|:---|
| QuantPF | Quant Portfolio Framework，本系统代号 |
| Paper / SIM | 模拟盘 / 仿真交易，不涉及真实资金与真实券商通道 |
| STOCK / FUTURE / SPOT | 股票 / 期货 / 现货 |
| bar+1 成交模型 | 信号在 K 线 N 收盘生成，N+1 才成交，防前视偏差 |
| 前视偏差（look-ahead bias） | 用“未来才可知”的信息成交，导致回测虚高 |
| Kill Switch | 一键熔断开关，停止所有新订单 |
| Idempotency-Key | 幂等键，保证同笔请求只生效一次 |
| XXL-JOB / SnailJob | 分布式任务调度框架 |
| QMT / CTP | 股票（迅投）与期货（综合交易平台）行情交易通道 |

### 35.2 环境变量清单（敏感项）

`DB_PASSWORD`、`REDIS_PASSWORD`、`TIMESERIES_PASSWORD`、`DIFY_BASE_URL / DIFY_API_KEY` 或具体模型服务凭据、`TUSHARE_TOKEN`、`BROKER_PASSWORD`、`CTP_USER_ID / CTP_PASSWORD`。

### 35.3 风险提示

- 财联社/新浪/雪球等为非官方接口，无 SLA，可能变更或违反 ToS，需数据源可用性监控 + 自动降级；
- 回测收益不代表实盘收益；实盘前必须完成回测 + 模拟盘验证 + 资金安全红线全部落地；
- 本系统 Stage 1 不具备真实交易能力，任何试图启用 LIVE/QMT/CTP 的行为均属边界违规。
