## 1. 系统概述与定位

### 1.1 定位

QuantPF 是面向个人 / 小团队的、中低频和研究驱动的量化交易系统，目标是支撑"研究 → 筛选 → 策略 → 风控 → 交易 → 回测 → 复盘"的完整量化投研闭环。

本系统当前不是高频量化系统，也不是以微秒级速度、超高报撤单频率、盘口抢单或做市为核心的交易系统。当前重点是中长期研究、日线/分钟级量价确认、事件和产业数据跟踪、候选筛选、等待预警以及本地模拟盘交易。系统可以使用盘口摘要、成交量、持仓量和逐笔摘要作为研究与确认数据，但不以低延迟抢先成交作为目标。

**第一阶段品种范围**：股票（STOCK）+ 期货（FUTURE）；现货（SPOT）保留为未来扩展，不属于第一阶段代码与验收范围。

**当前阶段目标**：

1. 单机（4C8G）可稳定运行全市场（A 股约 5000 只）日线级筛选与回测；
2. 交易决策可回测、可复现、可审计（确定性策略 + 确定性风控）；
3. 完成新闻、财报、研报、产业数据、量价和策略适配的研究闭环；
4. 完成本地模拟盘（Paper / SIM / Shadow）闭环；
5. 二期目标包含自动实盘，但在进入二期实盘前必须单独完成合规、数据授权、券商/期货公司接入、系统安全、回测和模拟盘验证；门禁未通过时不得启用真实委托。

### 1.2 非目标（第一阶段明确不做）

- 不做超高频 / 微秒级交易，不以交易所机房、主机托管、低延迟抢单、做市或高报撤单为目标；
- 一期不自动生成或向证券、期货交易所及券商/期货公司提交真实委托；
- 不把公开网页可见性理解为可以任意抓取、复制、再分发或商业化使用；
- 不做多租户 SaaS 化（先单用户 / 单团队）；
- 不自带大模型训练 / 微调（只调用外部 DeepSeek API）。

### 1.3 实盘边界（安全红线）

| 项 | 边界 |
|:---|:---|
| 当前运行模式 | Stage 1 仅允许本地 SIM / PAPER / SHADOW / READ_ONLY；模拟成交不进入真实交易所或经纪商账户 |
| 当前实盘能力 | 不生成、不提交、不撤销真实委托，不连接真实交易账户执行交易 |
| LIVE 路由 | Stage 1 必须不可用；代码、配置、密钥和界面均不应形成可误触发的真实交易路径 |
| QMT / CTP | Stage 1 不生成、不部署、不注册、不启用真实委托 / 撤单能力，仅为未来只读、回放和合规评估预留概念边界 |
| 二期实盘前置条件 | 另行完成法律与监管适用性评估、数据及软件授权、券商/期货公司接入确认、程序化交易报告要求确认、系统测试、异常处置和人工放行机制 |
| 禁止能力 | Stage 1 禁止 LIVE、REAL_BROKER_ORDER、REAL_BROKER_CANCEL 及任何绕过模拟盘的真实委托通道 |

### 1.4 关键架构决策（ADR 摘要）

| 编号 | 决策 | 选择 | 理由 |
|:---|:---|:---|:---|
| ADR-1 | 部署形态 | 单体 + Maven 多模块 | 事务一致、调试链路短、运维成本低，按模块预留拆分点 |
| ADR-2 | 交易主引擎 | 确定性 Java 策略 | 可回测、可复现、可审计 |
| ADR-3 | LLM 角色 | 仅辅助（情绪 / 财报 / 点评） | 避免幻觉直接下单 |
| ADR-4 | 风控 | 确定性硬闸门 | 资金安全不依赖概率模型 |
| ADR-5 | 调度 | XXL-JOB（3.1.0） | 可视化、重试、单节点防重 |
| ADR-6 | 多品种 | `product_type` + 策略 / 适配器模式 | 一套代码覆盖多品种 |
| ADR-7 | 行情存储 | 时序库（DuckDB / TSDB） | 高频数据不适合 MySQL |
| ADR-8 | 执行 | 独立网关进程（CTP JNI 网关、QMT xtquant 网关） | Java 不直接调 C++ / Python 底座 |

### 2.2 后端模块划分与职责

| 模块 | 设计职责 | 当前落地状态 |
|:---|:---|:---|
| `quantpf-common` | 实体、Mapper、枚举、共享 DTO/VO、工具、异常、公共配置、交易日历基础服务 | 空骨架（pom 占位） |
| `quantpf-data` / `marketdata` | 历史 K 线、实时行情（WS）、新闻多源抓取、财报数据源适配、行情缓存 | 空骨架（pom 占位） |
| `quantpf-strategy` | 策略引擎、技术指标、形态识别、标的池筛选 | 空骨架（pom 占位） |
| `quantpf-risk` | 确定性风控闸门、新闻情绪、黑名单、熔断 | **已实现**（PaperRiskGate / 内存 + 持久化） |
| `quantpf-finance` | 财报解读、基本面因子、财报日历、账务 / 台账 | **已实现**（模拟盘账务与台账） |
| `quantpf-execution` | 订单、券商适配、回报、持仓、移仓、模拟盘撮合 | **已实现**（Paper 订单 / 撮合 / 状态机） |
| `quantpf-backtest` | 回测引擎边界 | 仅接口占位（BacktestExecutionBoundary） |

| `quantpf-domain` | 领域模型（实体 / 枚举 / 值对象 / 仓储） | **已实现** |

> 说明：实际代码中 `quantpf-common / marketdata / research / strategy` 仅有 `pom.xml` 而无 `src`，为后续业务施工预留的骨架模块；`domain / execution / finance / risk` 为核心并已落地，`backtest / job` 为接口占位。

### 2.3 数据分层存储架构

```
第 1 层 基础信息（MySQL）   qm_stock_basic / qs_strategy_config / qs_broker_config
第 2 层 行情数据（时序库）   qs_kline_bar / qs_order_book / qs_tick_data
第 3 层 业务数据（MySQL）    qt_trade_order / qt_trade_signal / qt_position / qt_trade_record
第 4 层 分析数据（MySQL）    qn_news_* / qf_financial_* / qs_backtest_* / qs_stock_pool*
缓存层（Redis）             最新盘口 / 最新 K 线 / 最新 Tick / 持仓快照 / 基础信息缓存
```

| 数据类型 | 方向 | 频率 | 方式 |
|:---|:---|:---|:---|
| 基础信息 | 数据源 → MySQL | 日级 | XXL-JOB |
| K 线 | 数据源 → MySQL/DuckDB | 分钟 ~ 日级 | 增量（bar_time 去重） |
| 盘口 | QMT/CTP → Redis → DuckDB | 秒级 | 实时写 Redis，异步落盘 |

| 持仓 | 经纪商 → MySQL | 秒级(盘中)/日级(盘后) | 接口同步 |

## 3. 业务领域模型

### 3.1 产品 / 品种

| 枚举 | 值 | 说明 |
|:---|:---|:---|
| ProductType | STOCK / FUTURE / SPOT | SPOT 为未来扩展，Stage 1 只受理 STOCK 与 FUTURE |

多品种统一通过核心表上的 `product_type` 字段 + 策略 / 适配器模式实现一套代码覆盖。期货特有：保证金、强平、到期、移仓、夜盘、开平仓方向（BUY_OPEN / SELL_OPEN / BUY_CLOSE / SELL_CLOSE）。

### 3.2 核心领域对象总表

| 领域对象 | 表（已落地 Flyway） | 说明 |
|:---|:---|:---|
| 标的 / 合约 | `quantpf_instrument` | 股票 / 期货合约基础信息（代码、品种、交易所、最小变动价位、手数等） |
| 交易日历 | `quantpf_trading_calendar` | 各市场交易日与开收盘时段 |
| 行情 K 线 | `quantpf_market_bar` | 统一 K 线（OHLCV、成交额、复权口径、来源） |
| 新闻 | `quantpf_research_news` | 原始新闻（去重按 external_id+source、content_hash） |
| 财报 | `quantpf_financial_statement` | 三大报表原始数据（按(标的,报告期,报表类型,源)唯一） |
| 策略信号 | `quantpf_strategy_signal` | 策略产生的交易信号 |
| 策略 | `quantpf_strategy` | 策略定义（编码/版本/状态/JSON 定义） |
| 回测运行 | `quantpf_backtest_run` | 回测任务（参数、状态 CREATED/RUNNING/SUCCEEDED/FAILED/CANCELED） |
| 回测指标 | `quantpf_backtest_result` | 回测评测指标（按指标编码） |
| 交易账户 | `quantpf_trading_account` | 模拟资金账户（初始/可用/冻结资金、状态） |
| 资金台账 | `quantpf_cash_ledger` | 资金流水（复式记账，余额后置） |
| 持仓 | `quantpf_position` | 持仓（数量/可用/冻结/均价/已实现盈亏） |
| 模拟委托 | `quantpf_paper_order` | 模拟盘委托订单（状态机 + 冻结资金/数量） |
| 模拟成交 | `quantpf_paper_execution` | 模拟盘成交回报 |
| 风控规则 | `quantpf_risk_rule` | 可配置风控规则（JSON 定义） |
| 风控快照 | `quantpf_risk_snapshot` | 风控状态快照（风险状态/评分/原因） |
| 交易熔断 | `quantpf_trading_halt` | 熔断记录（GLOBAL/ACCOUNT/INSTRUMENT） |
| 任务执行审计 | `quantpf_job_execution_audit` | 调度任务执行审计（JOB/RUN 明细分账） |
| 操作审计 | `quantpf_audit_record` | 任意业务操作审计日志 |
| 跟盘会话 | `quantpf_paper_follow_session` | 模拟跟盘会话（账户+策略+模式唯一活跃槽位） |

### 3.3 关键业务概念

- **账户类型（AccountType）**：PAPER（落地阶段仅此一种）；`quantpf_trading_account.account_type = 'PAPER'`（CHECK 约束）。
- **账户状态（AccountStatus）**：ACTIVE / HALTED / CLOSED。
- **订单方向（OrderSide）**：BUY / SELL（Stage 1 模拟盘形态）。
- **订单类型（OrderType）**：MARKET / LIMIT。
- **订单状态（OrderStatus）**：NEW / ACCEPTED / PARTIALLY_FILLED / FILLED / CANCEL_REQUESTED / CANCELED / REJECTED。
- **成交状态（ExecutionStatus）**：ACCEPTED / REJECTED / FILLED。
- **风控状态（RiskStatus）**：CLEAR / WARNING / HALTED / REJECTED。
- **熔断范围（TradingHaltScope）**：GLOBAL / ACCOUNT / INSTRUMENT。
- **跟盘模式**：PAPER（CHECK 约束仅允许 PAPER）。
- **跟盘会话状态**：RUNNING / STOPPED。

### 3.4 已落地的值对象 / 领域对象

- `Money`：金额（BigDecimal，8 位小数），支持 add / subtract / multiply、正负判断；
- `Quantity`：数量（8 位小数，非负），支持加减、比较；
- `ClientOrderId` / `RequestId` / `OrderIdempotencyKey`：业务标识值对象（非空、长度 ≤ 128）；
- `Instrument`、`TradingAccount`、`Position`、`PaperOrder`、`PaperExecution`：核心聚合 / 实体。

## 5. 核心业务流程（目标态完整业务闭环）

### 5.1 主闭环

```
数据采集 → 标的筛选 → 策略信号 → 风控校验 → 交易执行 → 回测评估 → 绩效监控
```

**铁律**：下单决策必须来自"确定性策略 + 确定性风控闸门"；LLM（DeepSeek）输出只能作为评分项 / 参考（新闻情绪、财报解读、标的池点评），不得直接决定买卖。

### 5.2 数据采集流程

```
WebSocket 实时行情 → MarketDataCacheWriter → Redis(最新) + 时序库(批量落盘)
HTTP 历史 K 线 → 复权处理 → qs_kline_bar
新闻源轮询（财联社/新浪） → 去重 → qn_news_raw → 发布 NewsCrawledEvent
财报源（Tushare/东方财富） → qf_financial_statement
```

- K 线导入模式：FULL（清空重导）/ INCREMENTAL（按 `(symbol, period, bar_time)` 去重）；
- 校验：OHLC 合理性（high≥low、high≥open/close、low≤open/close）、时间连续性；
- 数据源可切换与自动降级（财联社/新浪/雪球为非官方接口，需可用性监控）。

### 5.3 策略引擎流程

- `StrategyEngineService.runAll(data, type)`：运行品种全部策略，返回候选（按置信度降序）；
- `runScreening(kline, type)`：盘后标的池单标的筛选；
- 内置策略：爆点形态 `breakout`（放量突破 20 日高点）、缠论买点 `chanlun`（一/二/三买）、期货趋势跟踪 `futures_trend`（均线金叉做多/死叉做空）；
- 指标层：MA / ATR / RSI / MACD / 成交量均线；
- 策略参数统一读 `qs_strategy_param_config` 激活版本，支持多版本与热更新。

### 5.4 风控流程

风控分层（确定性硬闸门）：

| 层级 | 规则示例 |
|:---|:---|
| 账户级 | 单日最大亏损、最大委托频率、保证金使用率上限 |
| 策略级 | 单信号最大仓位、每日最大交易次数 |
| 标的级 | ST/停牌黑名单、财务健康度黑名单、单票仓位上限 |
| 品种级 | 期货：保证金/强平/到期/夜盘；现货：价差/流动性 |

- `checkRisk`：统一风控入口；`checkBeforeTrade`：下单前同步强一致校验；`emergencyHalt`：紧急熔断；
- 关键熔断（Kill Switch）：`/risk/halt` 一键熔断，停止所有新订单 + 告警，需授权。

### 5.5 交易执行流程

#### 5.5.1 订单生命周期状态机（目标态）

```
PENDING → SUBMITTED → PARTIAL_FILL → FILLED
                  ↘ CANCELLED / REJECTED / EXPIRED
```

Adapter 接口模式：`BrokerAdapter` 对接的是网关进程（CTP JNI 网关 / QMT xtquant 网关 / HTTP 现货），Java 不直接调用 C++/Python。

#### 5.5.2 仓位计算（比例 → 金额 → 数量 → 按手取整）

```text
positionRatio = min(confidence × 0.5, maxPositionRatio)
targetAmount  = totalCapital × positionRatio
rawQty        = targetAmount / price
finalQty      = floor(rawQty / lotSize) × lotSize
```

股票 lotSize=100（1 手）；期货 lotSize=合约最小交易单位。

#### 5.5.3 交易主循环（时段闸门 + 幂等）

```text
1. 交易日/交易时段闸门（股票 9:30-11:30, 13:00-15:00；期货夜盘另配）
2. 拉取最新行情 MarketDataDTO
3. 全局风控 checkRisk（不通过则 return）
4. 遍历 runAll 信号：
   - 当日已执行跳过（幂等去重）
   - checkBeforeTrade 硬闸门
   - executeTrade 执行
   - 执行成功 markExecuted(信号)
```

幂等：`qt_trade_signal` 唯一键 `uk_signal_dedup(symbol, strategy_name, signal_type, trade_date)`，或 Redis `SETNX`。

#### 5.5.4 移仓换月（期货）

`ContractRolloverService.rollover(accountId, oldContract, newContract)`，按 Saga / 补偿事务：创建移仓计划 → 平旧提交 → 确认平旧成交 → 开新提交 → 确认开新成交；外部交易异常进入 `NEEDS_RECONCILIATION`。

### 5.6 回测引擎流程（bar+1 成交模型，防前视偏差）

| 规则 | 说明 |
|:---|:---|
| bar+1 成交 | 信号在 K 线 N 收盘后生成，委托在 K 线 N+1 才允许成交（N+1 开盘价或触及价） |
| 复权口径 | `adjust_flag` 记录，默认前复权 FORWARD |
| 年化折算 | 按 `KlinePeriod.annualFactor()` 折算，不一律 ×√252 |
| 手续费/滑点 | 开平仓分别计手续费；滑点仅开仓计入 |
| 涨跌停约束 | 买入价不高于涨停价、卖出价不低于跌停价（A 股） |

`executeBacktest`（异步提交，写一条 PENDING 并在事务外执行）→ `PerformanceAnalyzer.analyze`（收益率、最大回撤、胜率、盈亏比、夏普、年化波动率）。

### 5.7 模拟盘撮合引擎流程

MVP 简化撮合：

- 成交价：按委托价 / 最新行情价撮合（限制价约束）；

- 做空保证金率：默认全额（1.0）。

#### 6.5.1 模拟委托下单（`POST /api/quant/order/paper`）

```text
1. 前置校验：estimatedNotional / fillPrice / quantity 必填且为正；侧(Side)/类型(OrderType)合法
2. 风控闸门 evaluate(RiskContext)：
   - 全局熔断 → 拒（QPF-RISK-002）
   - 账户熔断 → 拒（QPF-RISK-002）
   - 市场未开盘 → 拒（QPF-RISK-003）
   - 行情数据过期（>1分钟）→ 拒（QPF-MARKET-001）
   - 数量/名义金额非法 → 拒（QPF-REQ-001）
3. 持久化提交（独立事务）：
   - SELECT ... FOR UPDATE 锁定账户
   - 幂等/重复检查：按 idempotency_key 或 (account_id, client_order_id)
   - BUY：校验可用资金 → 冻结资金；SELL：校验可用持仓 → 冻结持仓数量
   - 更新账户余额、插入委托（status=NEW）
4. 撮合成交 settle（独立事务）：
   - 生成 execution_id，写成交、写资金台账（复式记账，余额后置）
   - 更新账户资金 / 持仓（买入均摊成本，卖出结算已实现盈亏）
   - 更新委托状态为 FILLED（或 PARTIALLY_FILLED）
```

#### 6.5.2 模拟委托撤单（`POST /api/quant/order/{id}/cancel`）

```text
1. SELECT ... FOR UPDATE 锁定委托
2. 已 CANCELED → 幂等返回；已 FILLED/REJECTED（终态）→ 拒绝（QPF-ORDER-003）
3. 解冻资金（冻结资金 -，可用资金 +）；解冻持仓（冻结数量 -，可用数量 +）
4. 更新账户余额、委托冻结字段清零、状态置 CANCELED
```

## 7. 核心业务规则与策略

### 7.1 账户与资金冻结/解冻/结算规则

| 操作 | 规则 |
|:---|:---|
| 冻结（freezeCash） | 可用资金 ≥ 冻结金额，否则 `QPF-CASH-001`；可用资金 −，冻结资金 ＋ |
| 解冻（releaseCash） | 冻结资金 ≥ 解冻金额，否则 `QPF-CASH-001`；冻结资金 −，可用资金 ＋ |
| 结算（settleFrozenCash） | 冻结资金 ≥ 成交金额，扣减冻结资金（真实消耗） |
| 持仓冻结（freeze） | 可用数量 ≥ 冻结数量，否则 `QPF-POSITION-001` |
| 持仓释放（release） | 冻结数量 ≥ 释放数量 |
| 卖出结算（settleSell） | 冻结/总数量 ≥ 卖出量；扣减数量，`realizedPnl += (价格 − 均价) × 数量` |
| 买入结算（settleBuy / addBought） | 数量增加，均价按买价均摊 |

资金流水采用复式记账：`quantpf_cash_ledger` 记录 `ledger_type / amount（正负）/ balance_after / reference / idempotency_key`，余额后置可审计。

### 7.2 订单状态机规则（已落地）

```
NEW ──► ACCEPTED ──► PARTIALLY_FILLED ──► FILLED
 │          │              │
 │          ├──► CANCEL_REQUESTED ──► CANCELED
 │          └──► REJECTED
 └──► REJECTED
```

- 终态：FILLED / CANCELED / REJECTED；
- 非法迁移抛 `QPF-ORDER-001`；
- 终态订单不可撤（`QPF-ORDER-003`）；
- 成交数量不得超过剩余可成交数量（`QPF-ORDER-002`）。

### 7.3 风控闸门规则（已落地）

`PaperRiskGate.evaluate(RiskContext)` 按顺序判定：

1. 全局熔断 → 拒 `QPF-RISK-002`；
2. 目标账户熔断 → 拒 `QPF-RISK-002`；
3. 市场未开盘（marketOpen=false）→ 拒 `QPF-RISK-003`；
4. 行情数据为空或超过 stale 窗口（默认 60 秒）→ 拒 `QPF-MARKET-001`；
5. 数量非正 → 拒 `QPF-REQ-001`；
6. 名义金额非正 → 拒 `QPF-REQ-001`；
7. 全部通过 → 接受。

### 7.4 幂等规则

| 场景 | 幂等键 | 唯一约束 |
|:---|:---|:---|
| 委托下单 | Idempotency-Key（请求头）+ client_order_id | `UNIQUE(idempotency_key)`、`UNIQUE(account_id, client_order_id)` |
| 成交 | execution_id + idempotency_key | `UNIQUE(execution_id)`、`UNIQUE(idempotency_key)` |
| 资金流水 | ledger idempotency_key | `UNIQUE(idempotency_key)` |
| 跟盘开始 | start_request_id | `UNIQUE(start_request_id)` |
| 跟盘停止 | stop_request_id | `UNIQUE(stop_request_id)` |

重复请求返回原结果（幂等命中），不重复执行副作用；幂等键与原始参数不一致时抛 `QPF-IDEMP-001`。

### 7.5 交易/手续费规则（模拟盘配置目标）

| 项 | 默认值 |
|:---|:---|
| 佣金率 | 0.00025（万 2.5），最低 5 元 |
| 印花税 | 卖出 0.0005（万 5） |
| 过户费 | 0.00001（万 0.1） |
| T+1 | 启用（A 股） |
| 涨跌停 | 启用（默认 10%） |
| 做空保证金率 | 1.0（全额） |

### 7.6 策略与回测规则（目标态要点）

- 确定性策略为主线，LLM 仅辅助；
- bar+1 成交模型（禁止同根 K 线成交，防前视偏差）；
- 复权口径默认前复权 FORWARD；
- 年化按 `KlinePeriod.annualFactor()` 折算；
- 仓位换算：比例 → 金额 → 数量 → 按手取整。

## 10. 安全、幂等与资金安全

### 10.1 认证授权（底座，简要）

- 量化接口沿用 RuoYi Sa-Token，按权限标识做菜单/按钮级鉴权；
- 量化接口默认全部需要登录态，无匿名访问；
- 权限编码体系见 4.2，菜单事实源见 4.4。

### 10.2 资金安全红线

| 项 | 要求 |
|:---|:---|
| Kill Switch | `/risk/halt` 一键熔断，停止所有新订单 + 告警，需授权 |
| 下单二次确认 | 手动下单（尤其 REAL 账户）需二次确认 + 操作审计 |
| 密钥托管 | AES 密钥不硬编码，用环境变量 / KMS / Vault；`qs_broker_config.password_encrypted` 脱敏 |
| 审计日志 | 所有下单/撤单/参数修改记操作日志（who/when/what） |
| 环境隔离 | 生产配置与测试隔离；默认 `account_type=VIRTUAL`，实盘需显式开启 |
| 熔断阈值 | 连续错误/超时达阈值自动 `emergencyHalt()` |

### 10.3 敏感信息

- API Key、密码走 `${ENV_VAR}`，不硬编码；
- 经纪商密码 AES-256 加密存储，API 返回脱敏（仅后 4 位）。

### 10.4 幂等与一致性（已落地）

- 所有写接口要求 `Idempotency-Key`；下单/成交/台账分别以唯一键防重；
- 每笔命令使用独立显式 MyBatis 事务（`SqlSessionFactory.openSession(false)` + `SELECT ... FOR UPDATE` + commit）；
- 重复/锁冲突走 `resolve*AfterFailure` 兜底，避免重复副作用与脏读；
- 数据库 CHECK/唯一键/外键在存储层再兜底。

## 14. 个人交易方法 V1（新增）

### 14.1 方法定位

本章将个人的中长期交易方式整理为 QuantPF 的一条“事件驱动基本面研究 + 技术策略确认 + 确定性风控执行”流程。它不是新闻追涨系统，也不是单纯的技术指标选股系统，而是先寻找可能改变资产定价的事件，再验证事件是否能够传导到行业和标的的盈利、现金流、库存、供需或估值，最后等待价格行为与已有策略同时确认。

核心原则如下：

1. 新闻只产生研究假设，不直接产生买卖指令；
2. 行业判断必须能够写成可验证的传导链，而不是“新闻利好所以买入”；
3. 基本面决定“买什么、为什么买、持有多久”，技术和盘口决定“什么时候买、在哪里错”；
4. 仓位由可承受的止损金额和相关性预算决定，不由主观信心决定；
5. 股票和期货共用研究框架，但使用不同的估值、合约、期限、保证金和执行规则；
6. 每一个决策必须留下当时可获得的信息、假设、反证、入场条件、退出条件和复盘结果；
7. 在没有回测、纸面交易和足够样本前，任何“成功概率很高”的判断都只能视为未经验证的主观信念。

### 14.2 对原始五步流程的完善

用户提出的流程是一个合理的研究主线：

```text
重大新闻 → 影响行业 → 白马股/期货品种 → 研报和财报 → K线/盘口 → 既有策略交易
```

为了使它能够进入系统并长期复用，建议扩展为以下十步：

```text
0. 市场与账户状态检查
1. 权威信息采集与事件去重
2. 事件分级、可信度和时效判断
3. 事件传导链与多空假设
4. 行业/品种映射及受益顺序排序
5. 标的初筛与信息真实性核验
6. 财报、估值、供需和催化剂研究
7. K线、成交量、盘口与策略匹配
8. 交易计划、仓位和退出条件生成
9. Paper/Shadow 执行、监控和复盘
```

原流程中最需要补强的是第 0、2、3、5、8、9 步。没有市场状态过滤，重大新闻可能发生在系统性风险阶段；没有可信度和时效判断，新闻容易成为滞后信息；没有传导链，行业和个股之间会出现“讲故事式跳跃”；没有真实性核验，研报和自媒体的结论可能被误当成事实；没有预先定义的退出条件，交易会从策略交易退化为临场持有；没有复盘，系统无法知道收益来自方法还是来自偶然行情。

### 14.3 第 0 步：市场、账户和交易权限检查

研究开始前先判断当前系统是否允许建立新风险：

| 检查项 | 股票 | 期货 | 失败处理 |
|:---|:---|:---|:---|
| 全局风控 | 大盘极端波动、重大系统性风险 | 宏观冲击、流动性异常、涨跌停板风险 | 禁止新开仓，必要时减仓 |
| 账户状态 | 账户 ACTIVE、可用资金满足计划 | 保证金率、可用资金、追加保证金空间 | 禁止下单或降低目标仓位 |
| 数据状态 | K线、成交量、财报日期无过期 | 主力/次主力、盘口、结算价、合约规则完整 | 标记数据不可交易 |
| 交易权限 | T+1、涨跌停、停牌、ST 等 | 开平仓权限、夜盘、交割月、强平规则 | 进入人工确认或拒绝 |
| 组合暴露 | 单一行业、风格、因子暴露 | 同一产业链、同一宏观因子暴露 | 合并计算相关性预算 |

若风控状态为 `HALTED`、行情超过 stale 窗口、合约临近交割且移仓方案不存在，后续研究可以继续，但不得生成可执行订单。

### 14.4 第 1 步：权威新闻采集与事件登记

信息源应保存原文、发布时间、抓取时间、来源、作者/机构、原始链接、附件和内容哈希。建议分成四级：

| 级别 | 来源 | 用途 | 交易权限 |
|:---|:---|:---|:---|
| A | 监管机构、交易所、政府部门、公司公告、正式统计部门 | 事实确认、规则变化、重大事件 | 可进入研究候选；仍不能直接下单 |
| B | 权威通讯社、主流财经媒体、行业协会、上市公司正式采访 | 快速发现和交叉验证 | 至少两处独立来源或回到 A 级确认 |
| C | 券商研报、期货公司报告、专业数据库 | 影响分析、估值和供需框架 | 只能作为分析材料，不能当成事实源 |
| D | 自媒体、论坛、社交平台、群聊 | 线索发现、情绪观察 | 不得单独形成交易信号 |

“权威”不等于“正确预测”。A 级来源通常更适合确认已经发生的事实，研报更适合提供分析框架；二者必须在系统中区分 `fact`、`interpretation` 和 `forecast` 三种内容。

同一事件可能被多个网站重复报道。系统应按 `external_id + source`、内容哈希和语义事件键去重，形成一个 `ResearchEvent`：

```text
event_id / event_type / first_published_at / source_level
source_count / fact_summary / affected_industry / affected_commodity
expected_horizon / confidence / novelty
status = NEW / VERIFIED / DISMISSED / EXPIRED / REVIEWED
```

事件登记必须使用“当时可知”的时间戳。回测和复盘不能把事后修订、后续报道或最终结果回填到最初的决策时点，否则会造成信息前视偏差。

### 14.5 第 2 步：事件分级、可信度和时效

重大新闻不应只按“利好/利空”二元处理，至少同时评价五个维度：

| 维度 | 说明 | 取值建议 |
|:---|:---|:---|
| 事实确定性 | 是否有正式文件、明确数据或公司公告 | 0~5 |
| 新颖性 | 市场是否已经充分预期或定价 | 0~5 |
| 影响强度 | 对收入、成本、库存、现金流或估值的潜在影响 | 0~5 |
| 影响持续期 | 分钟、日、周、季度或多年 | 0~5 |
| 可交易性 | 是否存在流动性足够、成本可接受、可执行的标的 | 0~5 |

```text
event_score = 0.25*certainty + 0.20*novelty + 0.25*impact
            + 0.15*horizon + 0.15*tradability
```

当 `certainty < 3` 或 `tradability < 3` 时，事件只能观察，不能生成交易计划；当 `novelty = 0~1` 时，必须重点检查价格是否已经提前反应；当方向不明确时，状态应为 `NEUTRAL/RESEARCH_ONLY`，而不是强行归类为利多或利空。

### 14.6 第 3 步：从新闻到交易的传导链

每个事件必须写成至少一条可证伪的传导链：

```text
事件事实
  → 影响变量
  → 行业供需/成本/政策/竞争格局变化
  → 公司或合约的收入、成本、利润、现金流、库存或基差变化
  → 市场预期与估值变化
  → 价格行为和策略信号
```

模板：

```text
事实：某项政策/事故/供给变化被正式确认。
变量：产量、库存、运费、能源成本、需求量、利率或汇率中的哪一项发生变化？
行业：供给曲线、需求曲线、成本曲线或竞争格局如何改变？
标的：该公司/合约对变量的敏感度是多少？是否直接暴露？
预期：市场此前预期是什么？新闻带来的增量信息是什么？
证伪：出现什么数据或价格行为时，说明假设失效？
```

禁止只写“利好某行业”“龙头受益”。必须说明受益机制、受益顺序、受益期限和可能的反向受益者。原材料涨价可能利多上游生产商、利空下游加工企业；同一商品上涨，对库存持有者、远期采购者和现货缺口企业的影响也可能相反。

### 14.7 第 4 步：行业、品种和标的映射

建议按“直接暴露优先、盈利弹性优先、可验证优先、流动性优先”排序：

1. 直接受政策、产量、库存或价格影响的行业；
2. 对关键变量具有较高利润弹性或成本弹性的公司/合约；
3. 有正式披露、数据覆盖和清晰业务边界的标的；
4. 交易量、盘口深度和执行成本满足中长期计划的标的；
5. 最后才考虑概念扩散、题材映射和市场关注度。

股票的“白马”不能只等同于大市值或知名品牌。至少核验主营业务、收入分部、毛利来源、实际产能、经营现金流、应收账款、存货、资本开支、负债、商誉、治理风险、估值和交易属性。

用户提出的“排除重组后热点经营项不在公司注册经营范围内”是有价值的风险意识，但“经营范围”本身不足以证明业务真实存在。应升级为“业务实质核验”：以年报/半年报、审计报告、交易所公告、项目披露、产能和收入分部交叉验证。工商经营范围只能作为异常提示，不能替代财务和监管披露。

铁矿石、玻璃、纯碱等期货不能简单套用股票“白马股”概念，应关注现货价格、期货价格、基差、库存、产量、开工率、检修复产、下游需求、进口利润、运费、汇率、期限结构、主力切换、移仓、合约乘数、保证金、涨跌停、夜盘、流动性和滑点。期货研究对象是商品供需和风险溢价，合约只是表达观点的工具。

### 14.8 第 5 步：候选池和真实性核验

建议先形成约 8 个候选标的，但必须有明确淘汰规则：

```text
NEW → FACT_CHECK → RESEARCHED → TECHNICAL_REVIEW → APPROVED
                                             ↘ REJECTED
```

以下任一项成立，直接淘汰或冻结：来源无法回溯；标的与事件的经济传导链无法解释；财报、公告、研报重大矛盾且无法核验；盈利主要依赖一次性收益或不可持续价格；估值已反映乐观情景且没有预期差；流动性和交易成本不合格；价格与假设明显相反；期货临近交割、移仓、涨跌停或保证金风险不可控。

候选池必须保留“被淘汰原因”。被淘汰记录是研究资产，不能只保留最后选中的成功案例。

### 14.9 第 6 步：财报、研报和基本面研究

| 材料 | 适合回答的问题 | 不适合承担的作用 |
|:---|:---|:---|
| 公司公告/财报 | 发生了什么、资产负债和现金流如何 | 直接预测股价 |
| 监管/统计数据 | 宏观或产业事实如何变化 | 直接决定买卖 |
| 券商研报 | 变量、估值方法、情景分析 | 作为无条件目标价 |
| 新闻报道 | 及时发现事件、补充背景 | 代替正式披露 |
| LLM 摘要 | 提高阅读效率、列出矛盾和问题 | 代替原文核验、直接下单 |

研究结论分三层：事实层（有来源、有时间、有原文证据）、推理层（从事实到行业和公司影响的逻辑）、预测层（未来盈利、价格、估值和策略结果的假设）。三层不能混写；事实更新时，必须标记哪些推理和预测需要重算。

### 14.10 第 7 步：K线、盘口和策略匹配

技术分析的角色是确认“市场是否正在接受这个观点”，不是替基本面证明观点正确：

| 研究结论 | 优先策略 | 必要确认 | 不适用情形 |
|:---|:---|:---|:---|
| 新信息导致长期趋势可能重估 | `futures_trend` 或趋势跟踪 | 周期趋势、波动率、回撤空间、期限结构 | 仅凭一根长阳追高 |
| 事件后整理并突破关键区间 | `breakout`/爆点 | 20日高点、成交量、收盘位置、次日可执行性 | 缩量假突破、消息已充分反映 |
| 趋势中的回调与结构修复 | `chanlun`/禅道 | 级别、结构完整、止损明确 | 把主观画线当唯一证据 |
| 盘口显示买卖力量变化 | 盘口确认项 | 深度、主动成交、价量配合、持续性 | 用单个快照预测中长期趋势 |

“禅道/爆点”等策略必须有机器可读的信号合同：`strategy_code`、`strategy_version`、`signal_time`、`instrument_id`、`direction`、`entry_condition`、`stop_condition`、`take_profit_or_trailing_condition`、`holding_horizon`、`required_data_timestamp`、`confidence_components`、`invalidating_conditions`。

盘口只作为短周期执行和信号确认，不得用秒级噪声推翻中长期退出规则，除非触发预先定义的硬风险事件。

#### 14.10.1 多空双向价格确认矩阵

价格确认层不应只服务于多头。对股票、期货和商品行业，必须同时判断“基本面方向”和“价格方向”：

| 基本面/事件判断 | 技术与价格确认 | 决策结果 | 可执行表达 |
|:---|:---|:---|:---|
| 看多 | 看多 | 多头候选 | 股票买入；期货 `BUY_OPEN` |
| 看多 | 中性 | 继续观察 | 不追价，等待突破、回调确认或预期上修 |
| 看多 | 看空 | 禁止新多 | 可能是逻辑错误、信息未被接受或趋势尚未反转；已有多头按风险规则处理 |
| 看空 | 看空 | 空头候选 | 期货 `SELL_OPEN`；具备合法、可借、可执行条件时才考虑股票卖空 |
| 看空 | 中性 | 观察或减多 | 不直接开空，等待破位、反弹失败或供需数据继续恶化 |
| 看空 | 看多 | 禁止新空 | 可能出现预期抢跑、逼空或利空出尽；先等待价格重新确认 |
| 方向不确定 | 任意 | 不建立方向性仓位 | 仅允许观察、减仓，或使用已定义的套利/对冲策略 |

做空必须具备与做多同等完整的交易假设：为什么下跌、下跌的传导变量是什么、市场此前是否已经预期、何时失效、反弹风险如何控制。不能因为“行业利空”就直接卖出，也不能把没有卖空通道的现货观点伪装成可执行空头。

#### 14.10.2 行业看空的交易表达

“现货行业看空”首先是研究结论，是否能够交易取决于工具和权限：

- 商品期货：通常用对应合约 `SELL_OPEN` 表达看空，之后以 `BUY_CLOSE` 平仓；必须检查合约流动性、保证金、涨跌停、夜盘、交割月和移仓规则；
- 股票：只有在账户具备相应融券、借券或其他合规交易权限、且借券成本和可用券源可确认时，才允许建立空头；否则只能减持多头、回避多头或使用可交易的替代工具；
- 现货：现货本身通常不是可以随意无券卖空的标准化工具。没有库存、贸易合同、远期/掉期或套保安排时，系统应把“现货看空”映射为期货空头、相关资产减仓或观察信号，而不是生成虚构的现货空单；
- 产业链：若看空下游利润、看多上游或相反，只有在价差、基差或跨品种套利规则已定义时，才允许建立组合空头。

对于铁矿石、纯碱、玻璃等品种，行业看空应至少得到以下两类确认：

```text
基本面确认：库存上升、供应恢复、需求走弱、基差转弱或期限结构恶化
价格确认：趋势破位、反弹失败、空头成交量/持仓配合、弱势相对强度
```

只有一类确认时，状态为 `RESEARCH_ONLY` 或 `WATCH_SHORT`，不得直接开空。

#### 14.10.3 看空技术信号

看空信号不是“价格下跌”四个字，而是需要定义可回测的结构：

| 类型 | 看空确认示例 | 主要风险 |
|:---|:---|:---|
| 趋势 | 跌破关键均线/区间低点，均线空头排列，波动率标准化后仍有空间 | 震荡假破位 |
| 爆点反向 | 跌破整理区间并放量，反抽无法收复破位位 | 恐慌性下跌后的快速反弹 |
| 禅道/结构 | 高级别反弹结束、结构破坏、反弹背驰或卖点确认 | 主观画线和级别错配 |
| 盘口 | 下跌持续、主动卖成交占优、反弹承接弱、持仓变化与价格方向一致 | 短期逼空或流动性冲击 |
| 期限结构/基差 | 现货走弱、基差转弱、远月贴水或结构恶化 | 交割和季节性造成的假信号 |

看空策略同样使用 `bar+1` 成交模型，禁止在确认破位的同一根 K 线用收盘价回填成交。对于期货空头，涨停板、流动性枯竭和隔夜跳空上行可能造成无法按计划止损，因此空头仓位应比单纯按保证金占用计算更保守。

### 14.11 第 8 步：交易计划与仓位

下单前生成不可事后修改的交易计划：交易假设、方向、预期持有期、入场区间、失效条件、止损位置、目标/跟踪退出、计划风险金额、相关性调整后仓位、成本假设。

推荐采用风险预算而非“信心仓位”：

```text
单笔风险金额 = 账户净值 × 单笔风险比例
多头每股/每单位风险 = 止损价 - 入场价
空头每股/每单位风险 = 入场价 - 止损价
股票数量 = floor(单笔风险金额 / abs(入场价 - 止损价) / lotSize) × lotSize
期货手数 = floor(单笔风险金额 / (止损跳数 × 每跳价值 + 手续费/滑点))
最终仓位 = min(风险换算仓位, 标的上限, 行业上限, 流动性上限, 账户保证金上限)
```

建议的初始 Paper 参数只是风险上限的起点：单笔账户风险可从 0.25%~0.50% 试验，单行业总风险不超过 1.0%~1.5%，期货保证金使用率保留安全空间，严禁因“重大新闻”一次性满仓。具体数值必须通过账户规模、波动率、成本和回测校准。

### 14.12 第 9 步：执行、监控和复盘

交易后区分三类退出：假设失效退出、价格风险退出、目标兑现退出。不能把“暂时下跌但我仍然看好”作为第四种退出规则，也不能因亏损自动扩大止损。股票 T+1、涨跌停和期货夜盘等约束必须在计划阶段模拟。

复盘至少回答：信息是否真实及时；传导链哪一环正确；市场是否提前定价；标的是否优于替代标的；策略是否按规则执行；成本和延迟损失多少；盈亏来自研究、执行、风控还是偶然；删除新闻标签后技术策略是否仍有增量。

## 15. 交易流程状态机与决策规则（新增）

### 15.1 研究与交易状态机

```text
EVENT_NEW
  → EVENT_VERIFIED
  → THESIS_DRAFTED
  → INDUSTRY_MAPPED
  → CANDIDATES_SCREENED
  → FUNDAMENTALS_CHECKED
  → TECHNICAL_CONFIRMED
  → PLAN_APPROVED
  → PAPER_EXECUTED
  → MONITORED
  → EXITED
  → REVIEWED
```

任何节点均可以转为 `REJECTED`、`EXPIRED` 或 `HALTED`。状态转换必须保存操作者、时间、数据版本和理由。未经 `EVENT_VERIFIED` 的新闻不得生成 `PLAN_APPROVED`；缺少交易计划的信号不得进入模拟下单。

### 15.2 硬否决规则

以下规则不参与加权平均，任何一项触发即拒绝新仓位：

- 全局或账户熔断；
- 行情、财报、合约规则或交易日历数据过期；
- 事件仅有低可信度单一来源；
- 无法解释标的与事件之间的经济暴露；
- 预估成本使盈亏比不足；
- 止损不明确，或止损金额超过账户风险预算；
- 股票停牌、ST、涨跌停不可执行，或期货交割/强平风险不可控；
- 组合已有高度相关的同方向暴露；
- 交易计划依赖未来才能知道的信息。

### 15.3 候选评分卡

通过硬否决后，再使用 100 分评分卡排序。初始权重是待验证参数，不应永久固定：

| 维度 | 权重 | 评分要点 |
|:---|---:|:---|
| 事件可信度与新颖性 | 15 | 正式来源、独立交叉验证、未充分定价 |
| 行业传导链 | 20 | 直接暴露、影响强度、持续期、可证伪 |
| 标的质量/供需质量 | 20 | 股票财务质量，或商品供需和基差结构 |
| 估值/预期差 | 15 | 估值分位、一致预期、盈利弹性、库存周期 |
| 策略匹配 | 15 | 与爆点、禅道、趋势策略的规则匹配程度 |
| 执行和流动性 | 5 | 深度、滑点、交易时段、T+1/夜盘 |
| 风险收益比 | 10 | 预期收益、止损距离、相关性和尾部风险 |

建议初始门槛为 70 分进入观察、80 分以上才允许生成 Paper 交易计划；但任何分数都不能覆盖硬否决规则。系统应保存各维度的证据和理由，防止事后为达到分数而补写论据。评分不是收益预测。

### 15.4 新闻冲击和多头平仓规则

“重大利空直接多头平仓”应细化为分级处置，避免把不同事件一概而论：

| 等级 | 典型情形 | 建议动作 |
|:---|:---|:---|
| L0 | 普通噪声、重复报道、短期观点 | 不改变仓位 |
| L1 | 基本面轻微恶化、影响可证伪 | 暂停加仓，等待确认 |
| L2 | 事实确认并影响利润或供需，但非生存性 | 按规则减仓，重算止损和风险预算 |
| L3 | 重大监管、信用、战争升级、流动性或强平风险 | 停止新开仓，按组合计划快速去风险 |
| L4 | 账户、市场或交易通道失控 | 触发 Kill Switch，停止新订单并人工处置 |

L3 不等于无条件市价清空。股票可能涨跌停无法成交，期货可能连续涨跌停或流动性枯竭。系统应优先执行可行的减风险动作，同步记录未成交部分及后续处理。是否全平应结合事件类型、持仓方向、可执行性、保证金和组合相关性决定。

### 15.5 反确认偏误机制

每份交易计划必须增加：至少两个反方观点；一项出现即必须承认假设错误的关键反证；替代标的比较；新闻与价格方向不一致时的处理规则；在不知道最终结果时重新阅读原始材料的盲测复核。

LLM 可辅助生成反方问题和矛盾清单，但事实来源、评分、交易规则和风控结论必须由结构化规则和人工确认共同完成。

## 16. 股票与期货的差异化规则（新增）

### 16.1 股票规则

股票中长期交易主要研究盈利、现金流、估值、行业景气和风险偏好：

- 以日线和周线为主，盘口用于入场质量和流动性判断；
- 使用明确的复权口径，财务数据按报告期和真实披露时间管理；
- 财报发布日期、业绩预告和公告使用真实可见时间，不能用报告期结束时间代替发布时间；
- 将 T+1、涨跌停、停牌、ST、减持和流动性折价纳入回测；
- 不能因为“白马”而忽略估值过高、盈利下修和行业集中风险；
- 同一行业 2~3 只股票应作为一个风险簇合并计算，不能假定彼此独立。

### 16.2 期货规则

期货研究和执行至少增加以下字段：

```text
underlying / contract / exchange
contract_multiplier / tick_size / tick_value / margin_rate
trading_session / delivery_month / roll_rule
position_direction / open_close_flag / settlement_price
```

期货必须区分：方向判断正确但合约选择错误；现货逻辑正确但基差和期限结构不支持；杠杆、保证金和波动率导致提前止损；主力收益与连续合约回测收益不一致；研究周期与合约生命周期不匹配。

趋势策略建议加入 ATR 或波动率标准化，以便比较不同商品每手风险。移仓应记录旧合约平仓、新合约开仓、价差、手续费、滑点和保证金变化；不得用简单连续价格拼接代替可交易合约收益。临近交割且没有交割计划时，必须禁止继续持有。

### 16.3 共同框架与主要差异

共同框架是“事实 → 变量 → 传导 → 预期差 → 价格确认 → 风险预算”。

| 项目 | 股票 | 期货 |
|:---|:---|:---|
| 核心锚 | 盈利、现金流、估值 | 现货供需、库存、基差、期限结构 |
| 持有风险 | 公司治理、财报、停牌 | 保证金、强平、交割、移仓 |
| 价格表达 | 股价和成交量 | 合约价格、基差和期限结构 |
| 仓位单位 | 股数/金额 | 手数/保证金/每跳价值 |
| 退出约束 | T+1、涨跌停 | 夜盘、涨跌停、交割月、追加保证金 |
| 主要错误 | 把题材当盈利 | 把方向判断当成完整交易 |

## 17. 成功概率评估与验证方案（新增）

### 17.1 对当前方法的客观判断

在没有按规则完成历史回测、样本外测试、Paper 和成本模拟之前，无法可靠给出“挣钱概率为多少”。只能做条件性判断。

有利因素：先研究事件和行业，再选择标的，经济解释通常比单一指标更完整；从候选池精选有利于集中研究资源；已有爆点、禅道和期货趋势策略可把判断转为可回测规则；关注信息真实性和重大风险，为建立组合风控提供了基础。

主要削弱因素：权威新闻传播时可能已被市场定价；事件到行业、再到公司或合约之间有多层不确定性；先看新闻再找标的容易产生确认偏误；2~3 个标的可能高度相关；盘口不足以证明中长期基本面判断；期货杠杆、保证金、移仓和基差会使方向正确仍然亏损；若策略没有精确定义和版本管理，绩效无法归因和复制。

因此，**当前未经验证的成功概率不能称为“大”**。更准确地说，这是一套具备形成正期望值潜力、但仍依赖研究质量、执行纪律和风险控制的半系统化方法。第一目标不是证明每次判断都正确，而是验证扣除成本、相关性和尾部风险后，长期平均每单位风险是否为正。

### 17.2 用期望值而不是胜率评估

```text
单笔期望值 = 胜率 × 平均盈利
           - 败率 × 平均亏损
           - 手续费 - 滑点 - 冲击成本 - 延迟成本
```

低胜率策略可能因盈亏比高而有正期望；高胜率策略也可能因少数尾部亏损而长期亏损。系统至少应分别统计新闻触发/非新闻交易、股票/期货、不同策略、多空方向、市场状态、事件等级、来源级别和持有期。还要区分“研究正确但执行失败”与“研究错误但偶然盈利”。

### 17.3 分阶段验证

| 阶段 | 最小内容 | 通过条件 |
|:---|:---|:---|
| 规则测试 | 事件、评分、候选池、信号、仓位、退出单元测试 | 无前视、无未来数据泄漏、边界正确 |
| 历史回放 | 覆盖趋势、震荡和极端阶段 | 可复现，成本和滑点已计入 |
| 样本外测试 | 时间切分或滚动窗口 | 样本外表现未明显坍塌 |
| 纸面/模拟盘 | 建议至少 3~6 个月，并积累足够独立信号 | 纪律、延迟、成交和风控稳定 |
| 小规模实盘门槛 | 仅在安全权限另行批准后 | 多周期正期望，回撤可承受 |

这些是建议的验证门槛，不是盈利保证。不能只用最近一年收益验收，还应观察最大回撤及持续时间、盈亏比、收益集中度、换手、成本、容量、相关性和尾部亏损。

### 17.4 必须防止的回测偏差

- 未来新闻、未来财报或修订后数据泄漏到过去；
- 使用事后确定的成分股名单，忽略退市和样本存活偏差；
- 同一事件被重复计数；
- 用收盘价生成信号又用同一收盘价成交；
- 忽略涨跌停、停牌、T+1、夜盘、保证金和交割；
- 只回测最终入选的标的，忽略被淘汰候选和选择偏差；
- 多次试验参数后只报告最优版本；
- 把研报目标价或未来财务修订当作当时可知信息；
- 把连续期货价格当成可交易合约价格，不计移仓和期限结构；
- 用同一段数据调参和验收。

### 17.5 收益贡献归因

```text
总收益 = 市场方向收益 + 事件选择收益 + 行业/标的选择收益
       + 策略择时收益 + 仓位配置收益 + 执行收益
       - 交易成本 - 风险事件损失
```

只有当事件选择、行业映射或策略择时在多个独立样本中产生稳定增量，才能说明新闻研究提供了优势。若删除新闻输入后技术策略结果相近，新闻流程可能只是叙事装饰；若加入新闻后收益提高但回撤和换手显著恶化，也不能简单视为成功。

## 19. 结论与实施优先级（新增）

### 19.1 方法总结

```text
以权威信息发现机会
以事件传导链确认经济逻辑
以财报/供需和真实性核验排除伪逻辑
以候选池和评分卡控制选择偏误
以K线、盘口和既有策略寻找可执行时点
以风险预算、相关性和硬闸门控制损失
以回测、Paper 和复盘验证是否存在正期望
```

最有价值的部分不是“找到重大新闻后买白马”，而是把新闻转化为可证伪的研究假设，并让每一步留下证据和失败条件。最危险的部分是新闻已经定价、行业逻辑正确但标的弹性不足、候选集中且高度相关，或期货杠杆放大错误判断。

### 19.2 当前成功概率判断

在没有实证绩效样本的前提下，结论是：

> 这套方法有机会形成正期望，但目前不能认为挣钱概率大，也不能承诺稳定盈利。它是值得系统化验证的研究框架，不是已经被证明有效的交易系统。

最终结果取决于是否找到未被充分定价的增量信息，是否选中最有弹性且可验证的标的，是否执行预定义策略、止损和仓位，以及扣除成本、相关性和尾部风险后长期期望是否仍为正。

### 19.3 实施优先级

| 优先级 | 工作项 | 目的 |
|:---:|:---|:---|
| P0 | 实现研究事件、传导链、候选池、交易计划和复盘对象 | 主观流程可记录、可审计 |
| P0 | 为爆点、禅道和期货趋势策略补齐信号合同与版本 | 策略可回测、可复现 |
| P0 | 建立数据过期、集中度、止损、保证金、交割和流动性硬闸门 | 降低账户级损失风险 |
| P1 | 建立事件/行业/标的评分卡和淘汰原因记录 | 降低确认偏误和选择偏差 |
| P1 | 使用 bar+1、真实发布时间、成本、移仓规则进行回测 | 防止虚假回测收益 |
| P1 | 分别统计新闻、股票、期货、策略和市场状态绩效 | 识别有效子策略 |
| P2 | 加入反方观点、矛盾检测和研报摘要 | 提高研究效率，不转移风控权 |
| P2 | 建立 Paper/Shadow 跟盘和异常告警 | 验证执行链和交易纪律 |

### 19.4 最终执行纪律

- 没有事实来源和传导链，不交易；
- 没有止损、失效条件和风险金额，不交易；
- 数据过期、流动性不足或合约规则不明，不交易；
- 只有重大新闻、没有价格确认，不追单；
- 只因“白马”标签而忽略估值和集中风险，不放宽规则；
- 亏损后不扩大止损，不用加仓证明判断正确；
- 策略版本变更必须回测、Paper 和复盘验证；
- QuantPF Stage 1 继续只允许 SIM/PAPER/SHADOW/READ_ONLY，真实交易能力关闭。

> 本轮新增章节描述个人交易方法的 V1 业务规则和验证方案，属于目标态设计，不能误认为现有代码已经全部实现。后续开发按第 19.3 节 P0→P1→P2 顺序推进，并保持“LLM 仅辅助、确定性策略主导、确定性风控拦截、实盘边界关闭”的安全红线。

## 20. V2 业务需求总览（新增）

### 20.1 业务目标

V2 将 QuantPF 从“新闻研究 + 股票多头候选”扩展为“事件驱动的多资产、多空研究与模拟交易系统”。系统必须支持：

1. 股票以买多为主，重点研究业务真实性、盈利质量、事件敏感度和估值/预期差；
2. 商品期货支持做多和做空，使用供需、库存、基差、期限结构、波动率和趋势信号；
3. 现货研究支持多空观点，但只有存在可执行的期货、套保、库存或贸易工具时，才能转换为交易计划；
4. 新闻、公告、财报、行情、产业数据必须经过来源分级、时间可见性和质量检查后才能进入策略；
5. 股票多头、期货多头、期货空头、现货套保和跨品种价差必须使用不同的业务规则与风控参数；
6. 全部研究结论、评分、信号、订单、成交、风控和复盘记录必须可追溯、可回测、可解释。

### 20.2 产品方向定义

系统统一使用 `position_direction` 表达方向：

| 方向 | 适用产品 | 含义 | 典型开仓/平仓 |
|:---|:---|:---|:---|
| `LONG` | 股票、期货、现货库存 | 预期价格或净资产上涨 | 股票买入；期货 `BUY_OPEN` |
| `SHORT` | 期货、具备合规融券能力的股票 | 预期价格下跌 | 期货 `SELL_OPEN` |
| `HEDGE_LONG` | 现货企业/库存 | 对冲价格上涨风险 | 买入期货或远期 |
| `HEDGE_SHORT` | 现货库存/生产商 | 对冲价格下跌风险 | 卖出期货或远期 |
| `SPREAD` | 期货跨月、跨品种、期现 | 交易价差而非单边方向 | 同时建立多腿仓位 |
| `FLAT` | 全部产品 | 不建立方向性暴露 | 观察、减仓或退出 |

`LONG` 和 `SHORT` 是研究方向；`BUY_OPEN`、`SELL_OPEN`、`BUY_CLOSE`、`SELL_CLOSE` 是期货订单动作。研究结论不能直接替代订单动作，必须经过工具权限、合约规则、保证金和风控校验。

### 20.3 业务原则

- **事实优先**：原始公告、财报和交易所数据优先于二次解读；
- **时间可见**：所有数据按投资者实际可见时间进入研究和回测；
- **多空对称**：看空必须具备和看多同等的证据、价格确认和退出规则；
- **工具约束**：研究方向必须能够映射到真实可执行的产品和交易权限；
- **风险先行**：先计算止损、保证金、流动性和相关性，再决定是否交易；
- **可否定**：所有研究假设必须有明确的失效条件；
- **LLM 限权**：LLM 只能提取、分类、摘要和提出反方问题，不能绕过确定性风控直接下单。

### 20.4 关键用户角色

| 角色 | 主要职责 |
|:---|:---|
| 研究员/投资者 | 登记事件、维护假设、审核标的和交易计划 |
| 数据管理员 | 配置数据源、处理异常、核对数据版本和来源 |
| 风控管理员 | 配置风险规则、熔断、恢复和交易权限 |
| 策略管理员 | 发布策略版本、管理参数和回测结果 |
| 审计查看者 | 查看研究证据、订单链路和复盘记录 |

### 20.5 非目标

V2 仍不包含以下能力：

- 不允许未经额外审批直接连接真实券商或期货经纪商进行实盘下单；
- 不把现货研究系统伪装成无库存、无合同的现货卖空系统；
- 不将模型预测、研报目标价或 LLM 输出作为确定性交易信号；
- 不以简单连续合约价格代替真实期货合约的移仓收益；
- 不用单一收益率或单一胜率作为系统验收标准。

## 21. 数据来源、分层与质量治理（新增）

### 21.1 数据源分级

| 等级 | 数据源类型 | 典型来源 | 主要用途 | 允许直接生成事实 |
|:---|:---|:---|:---|:---:|
| A | 监管、交易所、政府、公司正式披露 | 证监会、沪深北交易所、巨潮资讯、公司公告、统计部门、期货交易所 | 事实确认、规则、财报、合约和结算数据 | 是 |
| B | 正规媒体、行业协会、专业机构 | 主流财经媒体、行业协会、权威通讯社、期货公司产业报告 | 事件发现、行业解释、交叉验证 | 需交叉确认 |
| C | 商业数据库和行情服务 | Wind、CSMAR、Choice、iFinD、Tushare、AkShare、行情供应商 | 批量计算、因子、历史行情、研究便利 | 需保存原始引用 |
| D | 研报、论坛、自媒体、社交平台 | 券商研报、产业访谈、公开讨论 | 观点、线索、情绪和反方材料 | 否 |

系统必须保存数据源等级，不允许将 C/D 级内容自动提升为 A 级事实。研报的预测、管理层的指引和媒体的解释必须分别标记为 `FORECAST`、`GUIDANCE` 和 `INTERPRETATION`，不能混入 `FACT`。

### 21.2 股票数据目录

| 数据域 | 主要字段 | 首选来源 | 用途 |
|:---|:---|:---|:---|
| 标的基础信息 | 代码、交易所、上市状态、板块、ST、停牌 | 交易所、公司公告、结构化数据库 | 交易权限和标的过滤 |
| 公司业务 | 主营、分部收入、分部毛利、产品、地区、客户 | 年报、半年报、临时公告 | 业务真实性和事件暴露 |
| 三大报表 | 资产负债表、利润表、现金流量表 | 正式财报、结构化财务库 | 盈利质量、估值和财务风险 |
| 财务附注 | 应收、存货、商誉、关联交易、减值 | 年报附注、审计报告 | 异常识别和质量评分 |
| 公司治理 | 审计意见、问询函、处罚、诉讼、减持 | 交易所和公司公告 | 硬否决和风险标签 |
| 业绩预期 | 业绩预告、快报、指引、盈利预测 | 公司公告、机构数据 | 预期差和盈利修正 |
| 市场行情 | OHLCV、复权、成交额、涨跌停 | 交易所/行情服务 | 动量、突破、回测和执行 |
| 资金与交易 | 融资融券、股东变化、机构持仓 | 交易所、披露文件、结构化数据库 | 拥挤度和空头权限检查 |

### 21.3 期货数据目录

| 数据域 | 主要字段 | 首选来源 | 用途 |
|:---|:---|:---|:---|
| 合约规则 | 合约乘数、最小变动、交割月、交易时段、保证金、涨跌停 | 期货交易所 | 仓位、下单和风控 |
| 行情 | OHLCV、Tick、盘口、结算价、持仓量 | 交易所/授权行情源 | 趋势、波动率和执行 |
| 合约关系 | 主力、次主力、近月、远月、移仓价差 | 交易所和行情服务 | 连续合约、移仓和期限结构 |
| 现货价格 | 地区、品级、交割品、报价时间 | 行业协会、产业机构、授权数据商 | 基差和现货验证 |
| 库存 | 交易所库存、港口库存、社会库存、厂库库存 | 交易所、行业机构、统计数据 | 供需和周期判断 |
| 供应 | 产量、进口、开工率、检修、复产 | 统计部门、海关、产业机构 | 供给冲击和趋势判断 |
| 需求 | 表观消费、订单、下游开工、季节性 | 统计部门、行业机构、产业数据 | 需求强弱和反转判断 |
| 成本 | 原料、能源、运费、汇率、进口利润 | 产业数据、公开报价、行情源 | 利润和产能行为分析 |
| 持仓 | 多空持仓、成交、仓单、交割数据 | 交易所/授权源 | 拥挤度、逼仓和交割风险 |

### 21.4 现货数据的特殊规则

现货研究必须明确：

- 报价是挂牌价、成交价、估价还是询价；
- 报价地区、品级、交割地点和含税口径；
- 数据是日频、周频还是实时；
- 是否存在报价滞后、样本稀疏或人为平滑；
- 是否可以实际交易、交割或套保；
- 现货与期货之间是否存在稳定的基差关系。

现货价格不能因为被记录在数据库里就自动视为可交易价格。系统应将 `spot_observation` 与 `tradable_instrument` 分开建模。

### 21.5 数据字段标准

每个可用于研究或交易的数据字段必须具备以下元数据：

```text
data_id
instrument_id / industry_id / commodity_id
data_type
value / unit / currency
period_start / period_end
available_at
published_at
effective_at
source_id / source_level
source_reference
revision_no
quality_status
is_point_in_time
```

时间含义必须区分：

| 时间字段 | 含义 |
|:---|:---|
| `period_end` | 数据对应的报告期或统计期结束时间 |
| `published_at` | 发布方公开发布的时间 |
| `available_at` | 系统实际可以读取并使用的时间 |
| `effective_at` | 数据或规则真正生效的时间 |
| `updated_at` | 系统最后更新该记录的时间 |

回测只允许使用 `available_at <= signal_time` 的数据。财报报告期结束日早于实际披露日时，不得把报告期结束日当作可见日。

### 21.6 数据质量规则

#### 21.6.1 行情校验

- `high >= max(open, close, low)`；
- `low <= min(open, close, high)`；
- 成交量和成交额不得出现无法解释的负值；
- 交易日、交易时段和夜盘时间必须符合交易日历；
- 复权行情与原始行情不能混用；
- 期货主力切换必须保留原合约映射和移仓记录；
- 盘口快照必须记录采样时间和数据延迟。

#### 21.6.2 财务校验

- 资产负债表借贷平衡；
- 期初余额与上期已披露数据可对接；
- 合并口径、母公司口径和扣非口径分开保存；
- 业绩预告、业绩快报和正式年报不能覆盖成同一条记录；
- 更正公告产生新版本，不覆盖历史原始版本；
- 财务指标必须保留计算口径和原始字段。

#### 21.6.3 产业数据校验

- 单位、地区、品级和统计口径一致；
- 同一指标的不同来源差异超过阈值时生成异常任务；
- 库存、产量和价格的发布时间必须可追溯；
- 不同来源不能未经标记直接平均；
- 估算数据、调查数据和正式统计数据分别标注置信等级。

### 21.7 数据降级与禁用规则

数据源不可用时，系统按以下顺序处理：

```text
主源正常 → 使用主源
主源延迟 → 使用已验证备源并降低置信度
主源和备源冲突 → 进入 DATA_CONFLICT，不生成新信号
所有来源失效 → DATA_UNAVAILABLE，禁止新开仓
```

数据降级不能只在日志中记录，必须传递到研究事件、交易计划和风控快照：

```text
data_quality = NORMAL / DEGRADED / CONFLICT / STALE / UNAVAILABLE
```

当关键数据为 `CONFLICT`、`STALE` 或 `UNAVAILABLE` 时，已持仓可按照既有退出规则管理，但禁止新增方向性风险。

## 22. 股票多头业务需求（新增）

### 22.1 股票多头业务定位

股票业务默认只支持买多，不把股票融券卖空纳入 Stage 1 的自动执行范围。股票多头交易的研究顺序为：

```text
事件/行业发现
→ 业务真实性核验
→ 盈利质量分析
→ 事件敏感度计算
→ 估值/预期差分析
→ 行业和价格确认
→ 股票买入交易计划
→ Paper 执行与复盘
```

### 22.2 业务真实性指标

系统应从年报、半年报、公告和产业数据提取或计算：

```text
core_revenue_ratio
core_profit_ratio
segment_gross_margin
capacity_or_project_evidence
customer_concentration
supplier_concentration
related_party_risk
audit_opinion_flag
regulatory_risk_flag
business_evidence_score
```

基本规则：

| 条件 | 处理 |
|:---|:---|
| 相关业务存在实际收入和利润 | 允许进入基本面研究 |
| 只有概念、没有收入或产能证据 | 标记 `CONCEPT_ONLY`，不得进入交易候选 |
| 收入存在但利润贡献无法确认 | 降低真实性和事件敏感度评分 |
| 重大关联交易或客户集中且无法解释 | 进入人工复核 |
| 审计意见、监管处罚或公告矛盾 | 触发硬风险或直接淘汰 |

### 22.3 盈利质量指标

系统至少计算以下指标，并保留指标版本：

```text
revenue_growth_1y / revenue_growth_3y
net_profit_growth_1y / net_profit_growth_3y
non_recurring_profit_ratio
operating_cashflow_to_net_income
receivable_growth_minus_revenue_growth
inventory_days
gross_margin_stability
roic / roe
net_debt_to_ebitda
goodwill_to_equity
cash_conversion_score
profit_quality_score
```

指标不能机械地单独决定交易。例如 `operating_cashflow_to_net_income` 偏低时，系统应进一步检查行业账期、项目周期、应收账款和存货，而不是自动认定为财务造假。

### 22.4 事件敏感度计算

股票事件敏感度以“事件变量变化对利润或 EPS 的影响”为核心：

```text
business_exposure = event_related_revenue_or_cost / total_revenue_or_cost
profit_elasticity = profit_change_rate / event_variable_change_rate
eps_sensitivity = estimated_eps_change / event_variable_change_rate
event_sensitivity_score = exposure × elasticity × duration × confidence
```

系统支持三种计算方式：

1. 公司披露的敏感性数据；
2. 分部收入、成本和历史价格数据的情景测算；
3. 行业可比公司和历史样本的回归或横截面估算。

每个敏感度结果必须标记 `MODELLED`、`DISCLOSED` 或 `INFERRED`，模型推导结果不能冒充公司正式披露。

### 22.5 估值与预期差指标

系统应保存点时估值和预期：

```text
pe_ttm / pe_forward / pb / ev_ebitda / fcf_yield
valuation_percentile_3y / valuation_percentile_5y
eps_estimate_current / eps_estimate_30d_ago / eps_estimate_90d_ago
earnings_revision_7d / earnings_revision_30d / earnings_revision_90d
guidance_vs_consensus
scenario_fair_value
expected_return_after_cost
```

建议使用三种情景估值：

```text
weighted_fair_value = bear_value × bear_probability
                   + base_value × base_probability
                   + bull_value × bull_probability
expected_return = weighted_fair_value / current_price - 1 - expected_cost
```

估值指标只用于判断预期差，不直接生成买入信号。即使预期收益为正，如果技术价格确认失败、行业趋势转弱或组合风险超限，也不得下单。

### 22.6 股票候选评分和买入条件

建议初始权重：

| 维度 | 权重 |
|:---|---:|
| 业务真实性 | 20 |
| 盈利质量 | 25 |
| 事件敏感度 | 30 |
| 估值/预期差 | 25 |

股票多头进入交易计划必须同时满足：

```text
硬否决规则全部通过
基本面总分达到门槛
事件方向明确或存在可验证的盈利变化
行业相对强度不明显走弱
breakout/chanlun/趋势条件至少一个触发
单笔风险、行业风险和组合风险通过
```

### 22.7 股票退出规则

股票多头必须区分：

- 基本面失效：事件没有兑现、盈利预测下修、业务真实性被证伪；
- 技术失效：结构破坏、趋势反转、突破失败；
- 风险退出：停牌、ST、重大监管、流动性枯竭、组合熔断；
- 目标兑现：估值达到目标、事件充分定价、移动止损触发。

股票不能因为“仍然看好”而无限期推迟止损，也不能用同一套退出阈值处理短期事件交易和中长期价值交易。

## 23. 期货/现货多空业务需求（新增）

### 23.1 期货和现货业务定位

期货/现货业务以商品产业链为研究对象，以期货、现货、远期、套保或价差工具表达观点。系统必须把以下三件事分开：

```text
产业判断：商品供需和利润方向
价格判断：期货、现货、基差和期限结构方向
交易表达：具体合约、方向、开平仓、保证金和移仓
```

### 23.2 商品研究数据到交易结论

| 研究数据 | 看多含义 | 看空含义 |
|:---|:---|:---|
| 库存 | 去库、库存低于季节性、库存拐点向下 | 累库、库存高于季节性、去库失败 |
| 供应 | 检修、减产、进口收缩、供应受限 | 复产、产量上升、进口增加、供应宽松 |
| 需求 | 开工率上升、订单改善、消费旺季 | 开工率下降、订单走弱、淡季延长 |
| 现货价格 | 现货强、成交改善、涨价传导 | 现货弱、降价、成交清淡 |
| 基差 | 基差走强或高于历史中枢 | 基差走弱或低于历史中枢 |
| 期限结构 | 近月强、正向紧张结构或结构改善 | 远月升水扩大、结构转弱或库存压力延长 |
| 生产利润 | 利润改善推动价格和产能行为 | 利润压缩、减产或产业链亏损 |
| 持仓结构 | 增仓上涨且趋势持续 | 增仓下跌且趋势持续，但要防拥挤 |

单项数据不能直接作为开仓条件。系统至少要求一项供需确认和一项价格确认共同成立。

### 23.3 期货多头规则

期货多头候选必须满足：

```text
供需或成本变量偏多
库存/基差/期限结构至少一项支持
期货价格趋势或突破确认
主力合约和流动性合格
距离交割和移仓窗口可控
保证金使用率和极端波动压力测试通过
```

交易动作：

```text
研究方向 = LONG
订单动作 = BUY_OPEN
退出动作 = SELL_CLOSE
```

### 23.4 期货空头规则

期货空头候选必须满足：

```text
供应恢复、库存上升、需求走弱、利润恶化或现货转弱中的至少一项
基差或期限结构没有与看空逻辑明显冲突
价格跌破关键结构或反弹失败
空头拥挤度、涨停风险和逼空风险可接受
合约流动性、保证金和止损可执行
```

交易动作：

```text
研究方向 = SHORT
订单动作 = SELL_OPEN
退出动作 = BUY_CLOSE
```

期货空头不能只因为价格已经下跌就开仓。价格快速下跌可能意味着利空已经充分反映，也可能存在技术性反弹、空头回补或逼仓风险。

### 23.5 现货看多和看空规则

现货方向研究结果定义如下：

| 现货观点 | 有库存/贸易敞口 | 无库存/贸易敞口 |
|:---|:---|:---|
| 看多 | 可研究买入、补库、期货多头或买入套保 | 只能通过期货/远期等可执行工具表达 |
| 看空 | 可研究去库、销售库存、期货空头或卖出套保 | 不生成无券现货空单，转为期货空头观察或回避 |
| 价差观点 | 可研究期现套利、跨品种或跨月组合 | 必须先确认双腿流动性、资金和交割条件 |

现货研究必须记录：

- 是否持有现货；
- 是否有采购或销售合同；
- 现货价格是否可成交；
- 期货合约是否可用于对冲；
- 基差风险是否可承受；
- 交割、仓储、运输和资金成本如何处理。

### 23.6 期货仓位和压力测试

期货仓位以止损金额、每跳价值和极端跳空为核心：

```text
per_contract_risk = stop_ticks × tick_value
                  + expected_slippage
                  + commission
                  + overnight_gap_buffer
contracts = floor(account_risk_budget / per_contract_risk)
```

还必须执行压力测试：

| 场景 | 测试内容 |
|:---|:---|
| 正常波动 | 近一年或近三年历史 ATR |
| 高波动 | 历史极端日、涨跌停附近波动 |
| 流动性下降 | 成交量下降、盘口变薄、滑点扩大 |
| 隔夜跳空 | 下一交易时段不利方向跳空 |
| 连续涨跌停 | 止损无法成交的连续日 |
| 移仓 | 旧合约和新合约价差、手续费、保证金变化 |
| 相关性冲击 | 同产业链多个合约同时同向波动 |

压力测试未通过时，系统不得因为保证金余额仍然充足而放行开仓。

### 23.7 期货合约生命周期

每个期货交易计划必须明确：

```text
主交易合约
备用合约
最后交易日
交割月规则
移仓触发日期或条件
移仓价差上限
连续合约回测映射方法
```

连续合约只用于分析和筛选，真实交易和回测执行必须回到具体合约。移仓动作应拆成两笔或多笔真实订单，分别记录成交价、成交量、手续费、滑点和价差。

## 24. 研究到交易的完整业务流程（新增）

### 24.1 端到端流程

```text
数据源配置
  → 数据采集
  → 去重、清洗、时间对齐
  → 数据质量评级
  → 事件/行业/商品研究
  → 多空假设
  → 候选标的/合约池
  → 基本面/供需评分
  → 价格和策略确认
  → 工具权限检查
  → 交易计划
  → 组合风险检查
  → Paper/Shadow 下单
  → 撮合、成交、持仓和保证金
  → 监控、退出和复盘
```

### 24.2 研究事件状态

```text
NEW
→ VERIFIED
→ VARIABLE_MAPPED
→ THESIS_LONG / THESIS_SHORT / THESIS_NEUTRAL
→ CANDIDATE_READY
→ EXPIRED / DISMISSED / REVIEWED
```

事件进入 `THESIS_SHORT` 不代表已经允许开空，仍需经过价格确认和工具权限检查。

### 24.3 交易计划状态

```text
DRAFT
→ FUNDAMENTAL_APPROVED
→ PRICE_CONFIRMED
→ INSTRUMENT_VALIDATED
→ RISK_APPROVED
→ PAPER_PENDING
→ PAPER_OPENED
→ MONITORED
→ PARTIAL_CLOSED / CLOSED
→ REVIEW_PENDING
→ REVIEWED
```

失败状态包括：

```text
REJECTED_DATA
REJECTED_FUNDAMENTAL
REJECTED_PRICE
REJECTED_TOOL
REJECTED_RISK
EXPIRED
HALTED
```

### 24.4 下单前检查顺序

```text
1. 交易日和交易时段
2. 数据质量和最新行情
3. 产品和合约状态
4. 方向与订单动作一致性
5. 股票买入/期货开平仓权限
6. 价格、数量和最小变动单位
7. 止损距离和单笔风险金额
8. 组合相关性和行业/商品簇暴露
9. 保证金、可用资金和压力测试
10. Kill Switch、账户熔断和幂等键
11. Paper/Shadow 模拟撮合
12. 写入订单、审计和信号执行记录
```

### 24.5 交易方向与订单动作校验

| 研究方向 | 订单动作 | 允许条件 |
|:---|:---|:---|
| `LONG` | `BUY_OPEN` | 期货合约可交易、风险通过 |
| `LONG` | 股票买入 | 股票状态正常、资金和涨跌停检查通过 |
| `SHORT` | `SELL_OPEN` | 期货可交易，或股票具备合规空头权限 |
| `LONG` 期货持仓退出 | `SELL_CLOSE` | 存在可用多头持仓 |
| `SHORT` 期货持仓退出 | `BUY_CLOSE` | 存在可用空头持仓 |
| `HEDGE_SHORT` | `SELL_OPEN` | 存在现货风险、套保比例和基差规则 |
| `SPREAD` | 多腿组合订单 | 所有腿均通过流动性和保证金检查 |

任何“开仓方向”和“开平仓标志”不一致的请求必须拒绝，并写入审计日志。

### 27.2 监控指标

#### 数据层

- 数据源成功率、延迟、缺失率和冲突率；
- 原始快照数量和解析失败率；
- 点时数据覆盖率；
- 行情断流、盘口延迟和合约映射错误；
- 财务数据修订和回填次数。

#### 研究层

- 事件验证耗时；
- 事件到候选的转化率；
- 候选淘汰原因分布；
- 多空方向比例；
- 事实、推理和预测混用告警；
- 评分缺少证据的比例。

#### 交易层

- 股票多头信号数量和执行率；
- 期货多头/空头信号数量；
- SELL_OPEN 与 BUY_CLOSE 配对完整性；
- 开平仓方向错误数；
- 滑点、手续费、成交延迟和拒单率；
- 保证金使用率和强平压力测试；
- 同一风险簇的集中度。

#### 绩效层

- 多头、空头、套保和价差分别统计收益；
- 事件研究正确率和价格确认正确率；
- 胜率、平均盈利、平均亏损、期望值；
- 最大回撤、尾部损失和回撤持续时间；
- 基准、行业指数和替代标的对比；
- 研究收益、择时收益、仓位收益和执行收益归因。

### 27.3 验收标准

#### 数据验收

- 任意财报、公告和产业数据能够追溯到原始来源；
- 回测只使用 `available_at <= signal_time` 的数据；
- 修订数据不会覆盖历史版本；
- 主源失效时能够切换备源并降低置信度；
- 关键数据冲突时不会生成新开仓信号。

#### 股票验收

- 能够为股票生成四维评分；
- 没有真实业务证据的概念标的自动进入禁用或人工复核；
- 业务、财务、事件和估值字段可查看来源；
- 股票只生成买入方向，卖出仅用于退出多头；
- T+1、涨跌停、停牌和 ST 规则进入回测和 Paper 撮合。

#### 期货/现货验收

- 能够生成期货多头和空头信号；
- `BUY_OPEN`、`SELL_OPEN`、`BUY_CLOSE`、`SELL_CLOSE` 状态机正确；
- 每个合约关联乘数、最小变动、保证金、交易时段和交割规则；
- 基差和期限结构有明确的品级、地区和时间口径；
- 能够模拟保证金、移仓、涨跌停无法止损和隔夜跳空；
- 没有现货敞口时不会自动生成无依据的现货空单。

#### 策略验收

- 多空策略均采用 `bar+1` 成交模型；
- 技术信号可复现、可版本化、可解释；
- 看多和看空分别统计，不允许混合掩盖亏损；
- 参数变化会生成新策略版本；
- 结果可回放到原始行情和研究数据。

#### 风控验收

- 数据过期、冲突、账户熔断和 Kill Switch 能阻止新开仓；
- 期货保证金和压力测试失败会拒绝交易；
- 同一风险簇暴露超过上限会拒绝交易；
- 所有订单具有幂等键和审计记录；
- 方向与开平仓动作不一致时拒绝请求。

### 28.2 未决业务问题

以下问题在真正实现前必须由用户确认并固化为配置或规则：

1. 股票范围是 A 股全市场，还是只覆盖沪深主板/特定行业？
2. 期货范围是否先限定铁矿石、纯碱、玻璃，再扩展其他品种？
3. 现货数据采用哪些商业数据商，是否具备合法授权和历史数据回溯？
4. 期货空头单笔风险、保证金使用率和最大连续亏损上限是多少？
5. 是否支持现货库存、贸易合同和套保账户建模？
6. 是否只做单腿期货，还是同时实现跨月、跨品种和期现套利？
7. 事件评分和商品供需评分的初始权重如何通过历史数据校准？
8. 哪些市场状态触发全局停止开仓？
9. Paper 通过多少时间和多少独立信号后，才能进入下一阶段？
10. 实盘能力是否永久关闭，或未来设置独立审批和隔离网关？

### 28.3 V2 最终定义

V2 的业务系统定义为：

> 一个以官方和可追溯数据为基础，以事件、财报、供需、基差、期限结构和价格行为为研究输入，以股票多头、期货多空、现货套保/价差为交易表达，以确定性策略、组合风险和 Paper/Shadow 验证为执行边界的事件驱动多资产交易系统。

V2 的核心不是让系统预测所有上涨和下跌，而是确保：

```text
数据来源清楚
数据时间正确
研究逻辑可证伪
多空工具可执行
仓位风险可计算
交易链路可审计
绩效结果可归因
```

> 本 V2 文档是在 V1 基础上新增的完整业务需求设计，新增章节属于目标态，不能视为当前 QuantPF 代码已经全部实现。Stage 1 仍只允许 SIM/PAPER/SHADOW/READ_ONLY，任何真实股票、期货或现货交易能力都必须经过独立审批、隔离和安全验收。

## 29. V3 背景、目的与最终定位（最终总纲）

### 29.1 背景

当前市场上的量化选股和交易工具通常只解决其中一部分问题：

```text
新闻阅读
财报/研报阅读
行业研究
商品供需研究
量价分析
盘口观察
技术策略
回测
预警
复盘
组合风控
```

用户如果想独立完成完整交易流程，通常需要同时具备财务分析、行业研究、市场交易、技术分析、期货规则和风险管理能力。信息数量多、专业门槛高、时间要求高，而且人工判断容易产生确认偏误、追涨杀跌、事后解释和策略临时改变。

本系统参考观潮公开展示的“筛选、策略验证、预警、盘中研究、盘后复盘”工作流，也参考 HOLDLE 公开展示的“选好、等好、管好”方法论；同时结合股票基本面、新闻事件、商品供需、基差、期限结构、量价和期货多空交易需求，形成面向个人用户的多源信息交易研究系统。

参考对象只用于借鉴业务思想，不直接复制其指标、阈值、结论或未公开算法：

- 观潮：<https://guanchaotv.com/app/chart>；
- HOLDLE AI Assistant：<https://www.holdle.com/ai-assistant>。

### 29.1.1 国内市场背景与本系统的监管边界

本系统所处的国内市场环境具有以下特点：

1. 股票、期货、现货的交易制度、可交易方向、交易时间、涨跌停/保证金、交割和数据口径不同，不能用一套无差别规则处理所有资产；
2. 国内程序化交易监管已经覆盖证券市场和期货市场，监管关注点不仅是高频交易，也包括通过计算机程序自动生成或下达交易指令的中低频程序化交易；
3. 证券市场《证券市场程序化交易管理规定（试行）》自 2024 年 10 月 8 日起施行，强调报告管理、先报告后交易、交易监测、信息系统管理和高频交易差异化管理；
4. 沪深北证券交易所已进一步细化程序化交易管理规则，相关实施细则均自 2025 年 7 月 7 日起施行；各交易所的具体报告、接入、监控和异常管理要求应以现行交易所规则为准；
5. 期货市场《期货市场程序化交易管理规定（试行）》自 2025 年 10 月 9 日起施行，明确了程序化交易报告、系统接入、风险管理、监测监控和期货公司核查等要求；
6. 证券和期货规则、交易所细则、数据授权条款和券商/期货公司接入要求可能继续调整，因此本总纲只记录当前阶段边界，不把某一日期的规则写成永久结论。

上述背景并不意味着本系统一期已经属于交易所程序化交易主体。当前系统只在本地完成数据研究、候选发现、条件筛选、机会提示、策略适配和模拟盘交易，不向真实证券或期货账户自动生成、提交或撤销委托；本地模拟成交也不进入交易所撮合系统。是否构成某项监管规则下的程序化交易，应以二期实际接入方式、委托链路、券商/期货公司安排和届时有效规则为准，必要时进行专业法律和合规评估。

二期如果从“研究与模拟”进入“自动实盘”，系统定位将发生实质变化：除交易策略本身外，还必须纳入交易账户接入、程序化交易报告/确认、系统测试、异常处置、日志留存、权限控制、数据和软件授权、券商/期货公司协议以及人工放行等要求。二期不是简单打开一个 LIVE 开关，而是一个需要单独立项、合规审查和安全验收的阶段。

参考依据（仅作背景索引，实际使用时以最新有效规则为准）：

- 中国证监会《证券市场程序化交易管理规定（试行）》：<https://www.csrc.gov.cn/csrc/c100028/c7480577/content.shtml>；
- 中国证监会《期货市场程序化交易管理规定（试行）》：<https://www.csrc.gov.cn/csrc/c100028/c7564353/content.shtml>；
- 深圳证券交易所《程序化交易管理实施细则》发布通知：<https://www.szse.cn/lawrules/rule/trade/current/t20250403_612770.html>；
- 上海证券交易所《程序化交易管理实施细则》：<https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml>；
- 北京证券交易所《程序化交易管理实施细则》：<https://www.bse.cn/jygl_list/200025383.html>；
- 沪深北交易所后续发布的程序化交易报告、实施细则和业务指引。

### 29.1.2 本系统的阶段性目标定义

一期：研究辅助 + 候选筛选 + 机会提示 + 策略适配 + 本地模拟盘 + 复盘验证

二期：在完成独立合规、安全、数据授权、接入、回测和模拟盘验证后，建设并启用自动实盘；前置条件未完成前不启用真实委托

一期的成功标准不是“自动赚到钱”或“自动完成交易”，而是：用户可以在可追溯的信息和量价证据基础上，较低成本地发现候选、理解理由、等待触发、模拟执行、观察结果并复盘规则。系统应优先减少无依据交易、追涨杀跌、信息过时和策略临时改变，而不是追求交易频率。

### 29.2 系统目的

系统不预测未来，不承诺必涨或必跌，不把 AI 输出当作买卖建议。系统的目标是：

> 在当时可获得的新闻、公告、财报、研报、行业数据、商品供需、现货、基差、期限结构、行情、成交量、持仓量和风险数据基础上，经过事实核验、机会分析、量价确认、策略适配、等待验证和组合筛选，找出未来某个预先定义周期内具有相对较高条件优势、风险可计算、交易工具可执行的股票或期货候选。

### 29.3 “高概率”的准确含义

系统输出的不是绝对预测，而是条件概率和相对优势：

```text
在指定市场状态、指定资产、指定方向、指定策略和指定周期下，
满足一组历史可复现条件的标的，未来达到目标或出现方向性结果的历史比例。
```

概率必须同时显示：

```text
预测周期
成功定义
样本数量
样本外结果
置信区间
平均盈利/亏损
最大不利波动
交易成本和滑点
```

### 29.4 最终定位

QuantPF V3 定位为：

> **面向个人用户的、多源信息驱动的、多资产候选筛选与交易研究系统。**

系统核心不是自动替用户预测市场，而是把复杂、分散、专业的研究流程结构化，降低用户参与成本，并让每一次候选筛选、等待、预警、交易和复盘都可解释、可验证、可追溯。

### 29.5 最终原则

```text
研究决定方向
筛选决定是否进入候选池
量价决定市场是否正在验证
K线和成交量决定适配哪种策略
策略决定进出场方式
等待机制决定是否现在交易
组合机制决定是否加入当前账户
风险管理决定交易多少
复盘和统计决定规则是否保留
```

## 30. V3 总体业务模块与模块目标（最终总纲）

### 30.1 总体业务闭环

```text
数据监听与获取
  → 数据质量和时间可见性检查
  → 多入口候选发现
  → 事实—解释—预测研究链
  → 资产方向判断
  → 质量/机会/量价/风险筛选
  → 候选研究决策卡
  → 市场状态与策略适配
  → 等待、预警与重新检查
  → 概率验证
  → 组合选择与风险预算
  → Paper/Shadow 交易
  → 持仓管理、止损、止盈、移仓
  → 复盘、归因、概率校准和规则迭代
```

### 30.2 业务模块总表

| 模块 | 目标 | 主要输出 |
|:---|:---|:---|
| 数据监听与来源管理 | 自动获取多源信息，并记录来源、时间、版本和质量 | 可追溯的事实数据 |
| 数据质量与时间治理 | 防止过期、冲突、修订和未来数据进入决策 | 数据质量状态 |
| 新闻与事件研究 | 从新闻/公告中发现可能改变定价的事件 | 事件和影响变量 |
| 股票基本面研究 | 判断公司业务真实性、盈利质量和预期差 | 股票质量与机会结果 |
| 商品供需研究 | 判断铁矿石、原油、纯碱、玻璃、尿素、鸡蛋、生猪、纸浆等品种的供需方向 | 商品多空研究结果 |
| 现货、基差和期限结构 | 把现货和期货关系转化为方向、套利或套保研究 | 基差/期限结构状态 |
| 量价分析 | 判断交易参与是否真正推动价格，以及趋势是否得到确认 | 量价状态和量价信号 |
| 候选筛选 | 将大量对象压缩为少量高质量候选 | 候选池和淘汰原因 |
| 市场状态识别 | 判断趋势、震荡、高波动和风险偏好 | 当前市场状态 |
| 策略适配 | 根据已选标的的形态选择适合的交易方式 | 适配策略和等待条件 |
| 筛选与观察池 | 管理候选、等待、触发、过期和失效 | 观察池状态 |
| 预警 | 在条件发生时提醒重新检查 | 预警事件 |
| 概率验证 | 用历史和前瞻样本验证条件优势 | 概率、区间、期望值 |
| 组合选择 | 处理相关性、风险簇和最佳表达工具 | Paper 组合 |
| 交易计划与执行 | 将研究结论转换成可执行的方向、仓位和退出计划 | 交易计划、订单和成交 |
| 持仓管理 | 持续判断假设、策略、风险和退出条件 | 持仓动作 |
| 复盘与归因 | 判断研究、量价、策略、执行和组合哪里有效 | 复盘结论和规则改进 |

### 30.3 模块之间的职责边界

各模块不得越权：

```text
新闻模块不能直接下单
基本面模块不能决定具体入场价格
量价模块不能替代财报和供需事实
策略模块不能决定标的是否有基本面价值
概率模块不能覆盖硬风控
组合模块不能改变研究方向，只能决定是否纳入和分配风险
AI 模块不能修改事实或绕过风控
```

### 30.4 用户参与压缩目标

系统自动承担：

```text
监听、抓取、去重、分类、提取、翻译、计算、初筛、排序、预警、复盘草稿
```

用户主要参与：

```text
设置资产范围和风险偏好
审核重大事件和研究方向
确认交易计划是否进入 Paper
处理数据冲突和重大异常
查看复盘并确认规则变更
```

## 31. V3 数据监听、获取与用户辅助体系（最终总纲）

### 31.1 数据源优先级

#### A 级：事实确认来源

股票：监管机构、交易所、巨潮资讯、上市公司公告、年报、半年报、业绩预告、问询函和回复、审计报告。

期货：各期货交易所的合约规则、行情、结算价、持仓量、仓单、交割和交易日历。

宏观产业：政府统计部门、海关、行业协会、正式统计和公开产业数据。

#### B 级：行业和事件来源

主流财经媒体、权威通讯社、行业协会、期货公司产业报告、正式产业调研。

#### C 级：结构化计算来源

Wind、CSMAR、Choice、iFinD、Tushare、AkShare、授权行情和产业数据库。C 级数据用于批量计算，但必须保留原始引用和质量标记。

#### D 级：线索和观点来源

券商研报、论坛、自媒体、社交媒体、公开讨论。D 级内容可用于发现线索、情绪和反方观点，不能单独产生事实或交易信号。

### 31.2 用户不懂金融时的使用方式

系统不要求用户自己阅读和计算全部专业指标。每个结论必须提供三层展示：

```text
普通语言结论
→ 专业指标解释
→ 原始数据、来源、时间和计算公式
```

示例：

```text
普通语言：公司与该事件的直接业务关系较弱，不建议因为概念买入。
专业依据：相关业务收入占比 4%，利润贡献无法确认，没有对应产能或订单证据。
证据：年报分部收入、公告、项目披露，均附可见时间和来源。
```

### 31.3 信息监听流程

```text
来源配置
→ 定时/实时采集
→ 原文保存
→ 内容哈希与事件去重
→ 发布时间和可见时间识别
→ 事实/观点/预测分类
→ 资产和行业映射
→ 数据质量评级
→ 进入研究队列
```

### 31.4 新闻、财报和研报的用户辅助

系统自动回答：

```text
发生了什么？
信息是否正式确认？
市场此前可能预期什么？
新增信息是什么？
影响哪一个变量？
可能影响哪些行业、股票或商品？
影响方向和周期是什么？
信息是否已经被价格反映？
需要哪些后续数据确认？
有哪些反方证据？
```

### 31.5 数据缺失时的业务动作

| 数据状态 | 研究动作 | 新开仓动作 |
|:---|:---|:---|
| 正常 | 正常研究 | 允许进入后续流程 |
| 延迟 | 降低置信度并等待更新 | 原则上不生成新信号 |
| 冲突 | 展示冲突来源和差异 | 禁止方向性新开仓 |
| 过期 | 仅允许查看历史 | 禁止使用过期数据生成信号 |
| 不可用 | 记录异常并转人工 | 禁止新开仓，持仓按退出规则管理 |

### 31.6 数据获取的总原则：可见、可获取、可存储、可使用不是一回事

本系统必须把数据使用拆成四个层次，不得因为某条信息可以在网页上看到，就默认它可以被系统批量抓取、长期保存、用于回测、对外展示或商业化使用：

~~~text
网页可见
  ≠ 可以自动抓取
  ≠ 可以长期保存原文
  ≠ 可以批量计算和再分发
  ≠ 可以用于商业产品或交易服务
~~~

系统的数据来源和使用规则遵循以下原则：

1. 优先使用监管机构、交易所、上市公司、政府统计部门、海关、行业协会和有明确授权的结构化数据服务；
2. 使用第三方网站、接口、研报或行情服务前，确认服务条款、授权范围、调用频率、历史数据权限、保存期限、衍生数据使用权和商业/个人使用限制；
3. 不绕过登录、验证码、访问控制、付费墙、技术限制或反爬措施，不把搜索引擎摘要当作原始事实；
4. 每份数据记录来源、原始链接或来源标识、采集时间、公布时间、可见时间、有效时间、版本、授权状态和允许用途；
5. 原始数据、结构化指标、AI 摘要、研究结论和交易决策必须分层保存，不能把 AI 生成内容伪装成数据源原文；
6. 不能确认授权范围时，数据可以作为人工研究线索，但不得进入自动排序、回测、模拟交易或对外展示链路，直至完成确认。

### 31.7 数据类别、来源、回溯和使用边界

| 数据类别 | 优先获取来源 | 历史回溯目标 | 稳定接口情况 | 一期允许的系统用途 | 人工查看/备注要求 |
|:---|:---|:---|:---|:---|:---|
| 新闻与政策信息 | 政府网站、监管机构、交易所、主流媒体和有授权的新闻服务 | 保存原文元数据、发布时间、可见时间和版本；原文是否可长期保存以授权为准 | 官方 RSS/API、授权接口较稳定；智能体搜索不等于稳定接口 | 事件发现、事实抽取、影响变量和过时检查 | 重大事件、来源冲突、方向性结论必须人工确认并备注 |
| 公司公告与财报 | 监管机构、交易所、上市公司公告、巨潮等正式披露渠道 | 财报期次、公告版本、修订记录和可见时间必须可回溯 | 官方披露页面和授权财务接口优先；页面搜索不作为唯一接口 | 基本面、业务真实性、盈利质量、预期差和事件研究 | 重大会计判断、重组、问询回复和异常经营事项需人工阅读/备注 |
| 券商研报与行业报告 | 券商、期货公司、行业协会和合法授权报告服务 | 记录报告标题、机构、发布日期、版本、观点和引用位置；是否存全文以许可为准 | 授权数据库可能稳定；免费网页和搜索结果不保证稳定 | 观点对比、预期差、反方证据和研究线索 | 研报属于观点材料，重要结论需人工查看原文并记录，不可只用 AI 摘要 |
| 股票 K 线、成交量、成交额 | 交易所、券商、授权行情服务、合规第三方数据服务 | 日线/分钟线按授权范围保存；必须支持复权口径、停牌、除权除息和修订回溯 | 授权行情 API、Tushare 等第三方服务视具体套餐和条款而定 | 量价分析、回测、策略适配、模拟成交 | 关键突破、异常成交和数据缺口需人工查看并备注 |
| 资金流向、盘口、逐笔摘要 | 券商/交易所/授权行情服务 | 历史深度、逐笔和盘口保存期限取决于数据产品；不可默认全部可回溯 | 稳定性和权限差异最大，免费接口可能限频、延迟或缺字段 | 量价确认、流动性检查、模拟执行和预警 | 盘中关键异常需人工确认；不能把盘口摘要当作唯一建仓理由 |
| 期货行情、成交量、持仓量 | 各期货交易所、期货公司、授权行情服务 | 主力连续、具体合约、结算价、持仓量和交易日历必须区分保存 | 交易所/期货公司/授权服务优先；接口覆盖和历史长度需逐项核实 | 期货多空、合约选择、移仓、流动性和风险研究 | 合约切换、交割月、夜盘和异常行情需人工确认 |
| 商品供需、库存、现货和基差 | 政府统计、海关、交易所、行业协会、产业机构和授权数据库 | 记录统计口径、发布日期、修订、样本范围和可见时间 | 部分数据有公开接口，部分需要授权或人工整理 | 供需判断、基差/期限结构研究、方向与价差候选 | 口径变化、估算数据、区域差异和数据冲突必须人工备注 |
| AI 分析结果 | 系统基于已保存来源调用 Dify/模型生成 | 保存输入数据版本、提示词版本、模型版本、生成时间和人工修订 | 不作为原始数据接口 | 摘要、解释、反方问题、研究卡草稿和复盘辅助 | AI 结果只能人工审核后进入研究结论，不能替代原始来源 |

这里的“历史回溯目标”不是承诺所有数据天然可获得，而是要求系统对实际取得且被授权保存的数据建立点时归档。若某来源只提供当前快照、没有历史接口或禁止保存原文，系统必须标记为“不可完整回溯”，不得在回测中假装拥有完整历史数据。

### 31.8 新闻、财报、研报与行情的获取方式边界

用户不懂金融和财务时，系统可以使用智能体搜索、网页检索和来源聚合降低阅读门槛，但职责应分为三层：

~~~text
智能体搜索：发现来源、定位材料、提取摘要和待核问题
权威/授权来源：确认事实、保存可引用的时间和版本
用户人工查看：确认重大结论、冲突信息和是否接受进入研究链
~~~

因此：

- 新闻、财报和研报可以由智能体帮助发现和整理，但最终事实必须回到可核验的原始或授权来源；
- K 线、成交量、资金流向和盘口数据应优先通过交易所、券商或授权第三方结构化接口获取；免费网页或第三方量化网站可以作为补充，但必须显示数据源、延迟、覆盖范围和许可状态；
- Tushare、AkShare 等工具只能作为具体数据产品和授权条款允许范围内的数据服务，不应在总纲中承诺某个接口永久免费、完整、无延迟或允许商业再分发；
- AI 对新闻、财报、研报和行情的解释必须保留“原文/原始数据 → AI 分析 → 用户备注”的链路，用户确认前只属于研究草稿；
- “人工查看”是重大结论的审核要求，不等于所有数据都必须由用户手工录入。系统仍应尽量自动采集和计算，以降低用户负担。

### 31.9 个人系统与商业系统的数据使用区别

本总纲默认一期是单用户或小团队的个人研究与本地模拟盘系统，但“个人使用”不等于自动拥有免费、无限制的数据权利；商业使用也不只是“是否收费”这么简单。最终应以数据提供商、交易所、券商、媒体和报告服务的合同及有效条款为准。

| 场景 | 典型范围 | 主要数据要求 | 典型限制 |
|:---|:---|:---|:---|
| 个人研究系统 | 用户为自己研究，在个人设备或受控环境中使用 | 可使用明确允许个人研究、非公开展示和非商业用途的数据 | 不得转售、公开广播、为他人提供数据服务、共享账号或绕过调用限制 |
| 个人模拟交易 | 用户本人使用 Paper/Shadow 账户，不提交真实订单 | 模拟行情和研究数据仍需遵守来源授权；模拟不改变数据版权和接口条款 | 不得因为是模拟盘，就把禁止商用或禁止存储的数据用于公开产品 |
| 小团队内部研究 | 同一组织内部有限用户使用 | 需要确认并发用户、内部共享、存储和历史回溯权限 | 个人许可通常不能自然扩展为团队或公司许可 |
| 商业系统 | 收费软件、SaaS、投顾/研究服务、面向客户的应用或对外提供数据/信号 | 通常需要商业数据许可、再分发/衍生数据许可、服务级别和合规审查 | 原始数据展示、接口代理、研报全文、行情转发和客户化信号通常需要明确授权 |
| 商业机构内部系统 | 公司自身投研、风控、交易或运营使用 | 可能需要企业/机构许可，即使不直接向客户收费 | 不能把个人账号、免费额度或个人授权当作机构授权 |

系统应为每个数据源记录 usage_scope，至少区分 PERSONAL_RESEARCH、TEAM_INTERNAL、COMMERCIAL_SERVICE、NO_REDISTRIBUTION 等状态。授权不明确时，默认按最严格限制处理，不进入对外展示、自动交易或商业服务链路。上述分类是业务边界，不构成对具体数据合同或法律责任的判断。

### 31.10 数据延迟、过时和有效性的分层处理

不同数据的“延迟”来源不同，系统不能只记录一个更新时间：

| 延迟类型 | 例子 | 业务含义 | 总纲级处理原则 |
|:---|:---|:---|:---|
| 发布延迟 | 财报、库存、政策和产业数据在统计期结束后才公布 | 数据描述的是过去，市场可能已经提前交易 | 明确 published_at、effective_at，检查价格是否已反映 |
| 传输延迟 | 新闻源、行情接口或搜索服务晚于原始发布 | 系统看到的时间晚于市场可见时间 | 记录 available_at 和来源延迟，不能把晚到信息当作新信息 |
| 处理延迟 | 采集、清洗、指标计算或 AI 分析尚未完成 | 系统内部结论落后于原始数据 | 显示数据新鲜度，未完成处理不生成新候选信号 |
| 行情延迟 | 免费行情、盘口或资金流接口为实时、准实时或盘后 | 价格和交易行为可能已经变化 | 显示实时/准实时/盘后标签，延迟不明时只作观察 |
| 修订延迟 | 统计数据、财报口径或历史行情后续修订 | 事后数据可能改变历史结论 | 保存版本，回测必须使用当时可见版本，不能静默覆盖 |
| 市场反应延迟 | 新闻发布后个股/期货已经快速上涨或下跌 | 信息本身可能仍有效，但交易机会的赔率已改变 | 将“事实有效”与“是否仍可交易”分开判断，必要时仅用于解释或复盘 |

系统至少需要维护以下时间字段：published_at、available_at、effective_at、observed_at、revised_at。当新闻、财报或研报发布后标的已经运行一轮，系统不应简单认为信息无效，也不应自动追买；应把“事件仍然成立”和“价格是否已经充分反映”分别显示，并重新执行量价、估值、风险和等待条件检查。

### 31.11 数据授权和历史回溯的目标状态

一期目标不是建立一个对外出售行情的数据库，而是建立个人研究和本地模拟盘所需的、来源清晰且在授权范围内的历史档案：

~~~text
可获得的数据 → 记录来源和授权 → 保存点时版本 → 生成指标和研究结论
→ 进入候选/回测/模拟盘 → 保留当时可见快照 → 支持复盘和审计
~~~

对于新闻、财报、研报、K 线、成交量、盘口摘要、资金流向、持仓量、库存、基差和期限结构，系统都应尽量支持历史回看；但回溯完整性必须显示为“完整、部分、不可用”三种状态。任何缺少历史、延迟不明、版本丢失或授权不明的数据，不得被包装成完整样本并用于证明策略概率。

## 32. V3 多入口候选发现流程（最终总纲）

### 32.1 入口 A：新闻/公告事件驱动

```text
新闻/公告
→ 事实核验
→ 影响变量
→ 行业/商品映射
→ 多空假设
→ 直接暴露标的
→ 预期差和价格已反应检查
→ 候选池
```

### 32.2 入口 B：股票基本面和预期差

```text
全市场股票
→ ST/停牌/流动性/数据硬过滤
→ 行业内质量排名
→ 同行比较
→ 五年财务趋势
→ 盈利预期修正
→ 估值分位
→ 事件敏感度
→ 量价确认
→ 股票买多候选
```

### 32.3 入口 C：商品供需和产业链

```text
品种池
→ 供应/需求/库存/利润
→ 现货强弱
→ 基差
→ 期限结构
→ 宏观和季节性
→ 量价和持仓量
→ 期货多头/空头候选
```

适用品种包括但不限于：

```text
铁矿石、原油、纯碱、玻璃、尿素、鸡蛋、生猪、纸浆
```

### 32.4 入口 D：价格、量价和策略形态

```text
全市场行情
→ 趋势/动量/波动率
→ 量价结构
→ 股票或期货相对强弱
→ 基本面/供需复核
→ 候选池
```

该入口用于发现没有明显新闻，但价格和交易参与已经出现结构变化的对象。

### 32.5 初筛与深筛

初筛目标是“不漏掉明显机会”，允许较宽；深筛目标是“减少错误候选”，使用更严格的事实、机会、量价、风险和组合规则。

```text
全市场/全品种
→ 初筛候选
→ 研究候选
→ 观察候选
→ 交易就绪候选
```

每次淘汰必须记录原因：

```text
数据不足、业务不真实、预期已反映、供需矛盾、量价失败、风险过高、流动性不足、组合重复、策略无匹配
```

## 33. V3 事实—解释—预测研究链（最终总纲）

### 33.1 事实层

事实层只描述已经发生并且能够追溯到来源的内容：

```text
某交易所库存本周增加 8%
某公司公告预计净利润增长 30%
某品种开工率从 75% 上升至 82%
某股票相关业务收入占比 72%
某期货合约价格跌破过去60日低点
```

事实层不允许直接写成：

```text
所以股价一定上涨
所以期货一定下跌
所以应该立即买入/卖出
```

### 33.2 解释层

解释层将事实连接到经济变量：

```text
库存上升
→ 供应暂时大于需求
→ 现货压力增加
→ 基差可能走弱
→ 期货远月压力增加
```

或者：

```text
产品价格上涨
→ 销售单价提高
→ 成本没有同比上升
→ 毛利率改善
→ 盈利预期可能上修
```

解释必须写明：

```text
影响变量
传导方向
影响强度
影响期限
直接受益者和受损者
可能的反向传导
需要验证的后续数据
```

### 33.3 预测层

预测层才允许输出方向和概率，但必须是条件式：

```text
预测方向：SHORT
预测周期：未来20个交易日
成立条件：库存继续增加、基差不转强、价格反弹失败
失效条件：库存连续下降、现货重新上涨、价格收复关键阻力
历史相似样本：86
条件下跌概率：62%
扣成本后期望值：正/负/不足
```

### 33.4 反方研究

每个研究对象必须同时生成：

```text
支持证据
反方证据
最重要的未知信息
最可能的错误环节
关键证伪条件
替代标的或替代工具
```

### 33.5 事实、解释和预测的版本要求

后续事实更新时，系统必须标记哪些解释和预测需要重新计算。历史研究不能被最新数据静默覆盖，必须保留当时可见版本。

## 34. V3 量价分析业务模块（最终总纲）

### 34.1 模块目标

量价分析模块的目标不是用成交量单独预测涨跌，而是回答：

```text
交易参与是否增加？
参与是否真正推动了价格？
价格运动是否获得后续确认？
当前是趋势启动、趋势延续、趋势衰竭、吸收、派发还是流动性冲击？
量价结构是否支持基本面/供需研究方向？
```

量价模块作为：

```text
候选发现工具
方向确认工具
策略适配工具
风险预警工具
执行质量工具
复盘归因工具
```

不作为唯一的基本面判断工具。

### 34.2 量价分析理论组合

V3 采用组合式量价框架：

```text
市场阶段和供需结构：借鉴威科夫思想
K线、成交量和收盘位置：借鉴 VSA 类分析
批量计算：RVOL、成交量Z分数、OBV、VWAP、MFI、CMF、量价背离
期货参与结构：成交量 + 持仓量
产业验证：库存、现货、基差、期限结构和利润
短周期执行：盘口和逐笔成交
```

任何理论必须转成可计算、可回测的条件，不能只保存“疑似吸筹”“主力派发”等不可验证标签。

### 34.3 量价数据字段

#### 股票

```text
open / high / low / close
volume / turnover
turnover_rate
adjusted_price
relative_volume
volume_zscore
atr
close_location_value
body_ratio / upper_shadow_ratio / lower_shadow_ratio
obv / vwap / mfi / cmf
price_position_percentile
industry_relative_strength
index_relative_strength
bid_ask_spread / market_depth
```

#### 期货

```text
open / high / low / close / settlement
volume / open_interest
volume_change / open_interest_change
relative_volume / volume_zscore
atr / volatility
close_location_value
basis / basis_change
term_structure / calendar_spread
bid_ask_spread / market_depth
contract_remaining_days
limit_distance
```

### 34.4 量价状态

```text
ACCUMULATION_CANDIDATE：低位承接候选
BREAKOUT_CONFIRM：突破确认
BREAKOUT_WEAK：突破但参与不足
TREND_FOLLOW：趋势延续
PULLBACK_HEALTHY：回调健康
DISTRIBUTION_CANDIDATE：高位派发候选
BREAKDOWN_CONFIRM：破位确认
SELLING_EXHAUSTION：下跌衰竭候选
DIVERGENCE：量价背离
LIQUIDITY_RISK：流动性风险
NO_SIGNAL：无明确状态
```

这些状态不是直接订单信号，必须与研究方向、市场状态和策略适配共同使用。

### 34.5 股票量价规则

#### 低位承接候选

```text
价格位于过去120日低位区域
波动率下降
成交量逐步收缩
下跌幅度缩小
低点不再明显下移
出现强势收盘或放量上涨
```

输出：进入看多研究对象的观察池，不直接买入。

#### 上涨放量、回调缩量

```text
上涨阶段成交量增加
回调阶段成交量下降
回调不破关键结构
再次上涨时成交量重新放大
```

适合匹配趋势回调或低位整理突破策略。

#### 放量突破

```text
收盘价突破过去N日高点
relative_volume 达到阈值
收盘位置偏强
突破幅度不过度极端
行业相对强度不弱
后续没有快速跌回突破位
```

#### 高位放量滞涨

```text
价格处于阶段高位
成交量明显增加
价格涨幅有限
收盘位置转弱
后续无法继续创新高
```

输出：提高风险等级或进入多头退出观察，不直接认定为顶部。

#### 放量下跌

股票一期主要用于：

```text
禁止新买入
减仓候选
止损候选
提高风险等级
```

### 34.6 期货量价持仓规则

| 价格 | 成交量 | 持仓量 | 业务解释 |
|:---|:---|:---|:---|
| 上涨 | 增加 | 增加 | 新参与增加，趋势可能延续 |
| 上涨 | 增加 | 减少 | 可能是空头回补，持续性需谨慎 |
| 下跌 | 增加 | 增加 | 空头参与可能增加，需检查拥挤度 |
| 下跌 | 增加 | 减少 | 可能是多头平仓，趋势未必延续 |
| 横盘 | 减少 | 减少 | 参与者退出，等待方向 |
| 横盘 | 增加 | 增加 | 多空分歧扩大，等待突破 |
| 上涨 | 减少 | 增加 | 价格推进但参与不足，趋势质量偏弱 |
| 下跌 | 减少 | 增加 | 价格走弱但参与不足，需要谨慎 |

成交量和持仓量只能提供结构解释，不能单独证明多头开仓或空头开仓。

### 34.7 期货多空量价组合

#### 多头候选

```text
基本面/供需偏多
价格趋势向上
成交量相对放大
持仓量配合
基差不走弱
期限结构不冲突
未出现极端拥挤
```

#### 空头候选

```text
基本面/供需偏空
价格趋势向下或反弹失败
破位时成交量放大
持仓量配合
基差走弱
期限结构偏空
没有明显逼空或交割风险
```

### 34.8 盘口和逐笔的阶段边界

一期使用盘口/逐笔数据的目标是：

```text
流动性过滤
价差检查
盘口深度检查
成交延迟检查
策略触发时执行质量确认
止损无法成交风险提示
```

完整订单流、撤单行为、成交速度和深度图属于后续增强能力，主要用于盘中执行和预警，不作为一期中长期选股的唯一依据。

### 34.9 量价验证规则

每个量价规则必须先定义：

```text
信号条件
成交时点
观察周期
目标和止损
成功/失败定义
交易成本
基准策略
市场状态分组
```

必须比较：

```text
只用价格
价格 + 成交量
价格 + 成交量 + 基本面/供需
完整研究流程
```

如果加入成交量没有改善样本外期望、回撤或稳定性，则该量价字段不应获得更高业务权重。

### 35.1 股票买多

## 36. V3 候选决策卡与策略适配机制（最终总纲）

### 36.1 策略职责原则

策略不是建仓筛选条件，不参与决定“什么资产值得研究”。策略只负责：

```text
已选标的当前适合什么交易方式
什么条件下进场
止损和退出如何设置
```

错误逻辑：

```text
爆点看多 + 缠论看空 + 趋势看多
→ 2票对1票
→ 买入
```

正确逻辑：

```text
研究决定方向
→ 候选筛选通过
→ 分析K线、成交量、持仓量和价格位置
→ 匹配适用策略
→ 等待策略触发
```

### 36.2 策略适配状态

```text
MATCHED：已匹配策略但尚未触发
TRIGGERED：策略条件已触发
WAITING：方向成立但形态未完成
NO_MATCH：当前没有合适的交易方式
EXPIRED：策略等待超时
INVALIDATED：策略前提失效
```

`NO_MATCH` 不代表研究方向错误，只表示当前没有合适的交易方式。

### 36.3 策略适用范围卡

每种策略必须附带：

```text
策略名称
适用资产
适用方向
适用周期
适用市场状态
适用价格位置
适用K线形态
适用成交量/持仓量形态
必要确认条件
禁止使用条件
入场条件
止损条件
退出条件
历史样本与期望值
策略有效期
```

### 36.4 核心策略适用范围

| 策略 | 适用形态 | 方向 | 禁用情形 |
|:---|:---|:---|:---|
| 低位横盘突破 | 低位整理、波动收缩、卖压减弱、放量上破 | 多头 | 无量突破、基本面恶化、快速跌回区间 |
| 高位震荡反弹失败 | 高位震荡、高点降低、反弹缩量、跌破后反抽失败 | 空头 | 持续创新高、强承接、逼空风险 |
| 趋势回调 | 明确趋势、回调/反弹不破主结构、量能收缩 | 顺趋势 | 趋势不明、震荡中部、结构破坏 |
| 放量突破/破位 | 关键区间突破或破位并获得后续确认 | 双向 | 单日异常量、消息最后冲高、恐慌性假破位 |
| 区间边界 | 趋势弱、上下边界多次验证 | 边界双向 | 重大事件、单边趋势、波动率突变 |
| 基差/期限结构 | 现货、基差、期限结构和合约价格协调 | 双向/价差 | 数据口径不一致、交割风险、双腿流动性不足 |

### 36.5 候选研究决策卡

```text
标的/合约
资产类型
研究方向
预测周期
核心事实及来源
市场原有预期
新增信息
影响变量
传导链
股票质量/商品供需结果
估值/预期差或基差/期限结构
量价状态
市场状态
支持证据
反方证据
候选策略
策略适用条件
当前已满足条件
尚未满足条件
触发条件
止损条件
退出条件
历史相似样本
条件概率和置信区间
预期净收益
最大不利波动
组合边际风险
最终状态
```

## 37. V3 筛选、等待、预警与复盘闭环（最终总纲）

### 37.1 筛选模块目标

筛选模块的目标是把全市场/全品种压缩为少量可研究对象，并说明为什么入选、为什么淘汰。筛选结果不是买卖指令。

筛选任务必须保存：

```text
筛选入口
筛选范围
筛选条件
数据时间
规则版本
候选结果
淘汰结果
淘汰原因
```

### 37.2 等待模块目标

等待模块的目标是防止“研究正确但交易时点错误”。每个观察对象必须明确缺少什么条件。

等待卡：

```text
观察原因
已满足条件
尚未满足条件
触发条件
触发后复核项
失效条件
最长等待时间
下次复核时间
```

状态流转：

```text
CANDIDATE
→ WATCHLIST
→ WAITING_TRIGGER
→ NEAR_TRIGGER
→ TRADE_READY
→ PAPER_ACTIVE
```

异常流转：

```text
DATA_CONFLICT
THESIS_CONFLICT
EXPIRED
INVALIDATED
BLOCKED
```

### 37.3 预警模块目标

预警的目标是提醒系统或用户重新检查，而不是自动把提醒转换成订单。

预警类型：

```text
价格预警
技术结构预警
量价异动预警
新闻/公告预警
财报和盈利预期预警
库存/供需预警
基差预警
期限结构预警
策略触发预警
风险簇集中度预警
```

每个预警必须包含：

```text
对象
条件
有效期
触发时间
触发时数据快照
触发后的复核问题
允许动作
```

### 37.4 预警触发后的重新检查

触发后必须重新检查：

```text
新闻是否更新
财报/供需是否有新数据
市场是否已经过度反应
量价结构是否继续确认
策略是否仍然适配
止损和风险收益比是否仍然合理
组合是否仍然允许加入
```

### 37.5 复盘模块目标

复盘的目标不是记录盈亏，而是区分：

```text
研究错误
数据错误
传导错误
量价判断错误
策略适配错误
执行错误
仓位错误
组合错误
偶然结果
```

复盘必须同时记录已交易和未交易信号：

```text
实际交易对象
达到条件但未交易对象
进入观察池但未触发对象
被淘汰但后来大幅上涨/下跌对象
替代标的表现
```

### 37.6 复盘输出

```text
原研究方向是否正确
事实是否真实和及时
传导链哪一环正确/错误
量价状态是否正确
策略是否适配
是否按等待条件交易
执行偏差和成本
组合边际风险是否合理
需要修改的唯一规则
```

## 38. V3 概率验证机制（最终总纲）

### 38.1 概率定义

系统至少分别计算：

```text
P_up(H)：未来周期 H 上涨概率
P_down(H)：未来周期 H 下跌概率
P_target_before_stop：先达到目标而不是先达到止损的概率
```

股票、期货多头、期货空头、套保和价差不能混合统计。

### 38.2 成功标签

每类信号必须提前定义成功和失败：

```text
入场规则
成交价格
观察周期
目标收益
止损幅度
交易成本
滑点
移仓成本
超时结算规则
```

示例：

```text
期货空头
观察期：20个交易日
成功：先达到扣成本后+6%的目标
失败：先达到扣成本后-3%的止损
超时：按20日结束价格结算
```

### 38.3 验证阶段

```text
冻结信号规则
→ 历史回放
→ 成本和滑点模拟
→ 时间样本外
→ 滚动验证
→ 纸面/Shadow 前瞻
→ 概率校准
→ 规则版本发布
```

### 38.4 概率必须与基准比较

股票至少比较：

```text
市场指数
行业指数
行业中位数
简单动量
简单趋势
随机同行样本
```

期货至少比较：

```text
对应品种基准
简单均线趋势
简单突破
买入/卖出并持有基准
不含供需数据的价格策略
```

### 38.5 概率校准

系统显示的 60% 概率，长期实际结果应接近 60%。每个概率结果必须显示：

```text
概率值
有效样本数
置信区间
样本外概率
最近样本表现
最大不利波动
```

样本不足时不显示伪精确概率，而显示：

```text
样本不足，无法验证
```

### 38.6 消融实验

必须比较：

```text
价格-only
价格 + 成交量
价格 + 基本面
价格 + 新闻
价格 + 商品供需
完整系统
```

如果增加某类信息没有改善样本外期望、回撤或稳定性，则不应继续增加该信息的业务权重。

### 38.7 策略和概率漂移

按最近20次、50次、100次以及滚动年度监测：

```text
胜率
期望收益
盈亏比
最大回撤
滑点
信号数量
概率校准误差
```

状态：

```text
NORMAL
DOWNWEIGHT
REVIEW
PAUSED
REVALIDATION_REQUIRED
```

## 39. V3 组合选择与风险预算机制（最终总纲）

### 39.1 组合选择目标

组合模块的目标不是选择分数最高的几个对象，而是选择加入当前组合后能够改善整体风险收益结构的表达工具。

### 39.2 个体硬过滤

以下任一项不通过，不能进入组合：

```text
数据质量不合格
研究逻辑无法解释
没有清晰触发和失效条件
概率样本严重不足
预期净收益不足
止损不可执行
流动性不合格
期货交割/移仓风险不可控
保证金压力测试失败
风险簇已经超限
```

### 39.3 风险簇

每个候选必须标记：

```text
行业
产业链
商品因子
宏观因子
政策因子
利率/汇率暴露
多头/空头方向
共同事件
```

铁矿石多头、钢铁股多头、焦煤多头可能都属于同一黑色产业链风险簇，不能简单视为三个独立机会。

### 39.4 最佳表达工具

同一个研究观点需要比较不同表达：

```text
预期净收益
单位风险收益
流动性
交易成本
波动率
最大回撤
保证金压力
相关性
执行难度
```

输出：

```text
主表达工具
备选表达工具
不采用的表达工具
不采用理由
```

### 39.5 组合选择流程

```text
个体硬过滤
→ 预期净收益排序
→ 风险簇标记
→ 合并共同暴露
→ 删除重复表达
→ 压力测试
→ 计算加入组合后的边际风险
→ 分配风险预算
→ 生成 Paper 组合
```

### 39.6 风险预算初始原则

初始 Paper 阶段可使用保守起点：

```text
单笔账户风险：0.25%~0.50%
单一风险簇：设置总风险上限
期货保证金：保留安全缓冲
单一方向：设置总风险上限
日/周/月：设置最大损失上限
```

具体数值必须通过回测、样本外和 Paper 验证，不作为永久参数。

### 39.7 组合再平衡

```text
每日：退出、止损、数据和风险检查
每周：观察池、候选和风险簇重算
事件后：重新评估方向和组合暴露
财报/库存发布后：更新质量和机会评分
月度：复核概率、策略和风险预算
```

### 39.8 组合级停止新增风险

系统必须区分：

```text
禁止开新仓
允许减仓
允许平仓
允许移仓
允许套保
```

重大风险事件不应简单地把所有持仓动作全部锁死。

## 40. V3 人机协同、用户体验与二期边界（最终总纲）

### 40.1 一期用户体验目标

用户不懂财务、行业和量价专业术语时，系统仍应能够使用。每个候选以“结论—证据—风险—下一步”展示：

```text
解释盈利质量
```

```text
识别数据冲突和风险
```

#### 量价助手

```text
翻译量价状态
```

```text
直接生成真实订单
自动把利空转换为 SELL_OPEN
```

### 40.3 一期刚需功能

```text
数据监听和解释
股票/期货/现货候选筛选
```

### 40.4 二期功能：完整看图工作台

```text
完整多周期图表工作台

多图联动
图表内 AI 操作
```

一期仍然需要计算和保存行情、K线、成交量、盘口摘要和技术结构，但通过结构化结果、预警和候选决策卡提供服务。

### 40.5 筛选、预警和复盘刚需

这三项必须作为一期正式业务模块：

```text
筛选：发现和压缩候选，不直接下单
预警：条件触发后提醒重新检查，不等于交易
复盘：评价研究、量价、策略、执行和组合，不只记录盈亏
```

---

### 40.6 当前阶段的人工确认与二期实盘边界

一期坚持“系统自动整理，用户在关键节点确认”的人机协同方式。用户不需要手工阅读和计算所有数据，但以下事项不得仅凭 AI 摘要或自动评分直接推进：

- 重大新闻、战争、政策、监管处罚、重大重组、财报异常和来源冲突；
- 新闻、财报或研报发布后，价格已经明显运行，仍然需要判断是否已经反映；
- 股票进入最终候选、期货确定多空方向、现货数据用于表达交易观点；
- 候选从观察池进入 Paper/Shadow 交易计划；
- 数据授权不清、数据延迟不明、历史回溯不完整或 AI 与原始来源不一致；
- 研究规则、概率口径、策略适用范围和风险参数的修改。

人工确认的结果必须保留为研究备注或决策记录，并与当时可见的数据版本关联。普通的日常数据刷新、指标计算、候选排序和重复性预警可以自动完成，但自动化不应绕过上述关键确认点。

一期本地模拟盘的本质是研究验证工具：订单、成交、资金、持仓和盈亏均在本地模拟环境中闭环，不代表真实成交能力，不代表未来实盘收益，也不等于取得了真实交易数据或软件的商业授权。

未来二期自动实盘是独立阶段，至少需要重新确认：

~~~text
实际接入链路与交易权限
→ 证券/期货公司和交易所适用规则
→ 程序化交易报告及账户要求
→ 行情、研报、新闻和软件授权
→ 密钥、权限、审计、异常处置和人工熔断
→ 模拟盘前瞻验证和小规模灰度
→ 独立合规与安全放行
~~~

在上述条件完成前，系统不得把一期的 Paper 信号、模拟订单或本地策略适配结果直接转换为真实委托。

## 41. V3 业务验收、绩效评价与迭代路线（最终总纲）

### 41.1 数据业务验收

```text
所有事实可追溯到来源
所有数据有可见时间
修订数据不会覆盖历史版本
所有数据记录来源、授权状态、允许用途和数据延迟
历史数据标记完整、部分或不可用，不把缺失历史伪装成完整样本
智能体搜索结果能回到原始/授权来源，重大结论有人工确认记录
个人使用、团队内部使用和商业使用的边界不混用
数据冲突能阻止新开仓
现货数据区分观察价格和可交易工具
量价字段口径一致
期货持仓量、基差和期限结构可回放
```

### 41.2 候选筛选验收

```text
股票可生成业务真实性、盈利质量、事件敏感度和估值/预期差结果
期货可生成供应、需求、库存、现货、基差和期限结构结果
量价可生成明确状态
每个候选有支持证据和反方证据
每个淘汰对象有淘汰原因
候选不直接等于交易指令
```

### 41.3 策略适配验收

```text
策略不参与第一阶段标的价值筛选
每个策略有适用范围和禁用条件
策略匹配基于K线、成交量、持仓量、波动率和市场状态
没有匹配策略时进入观察而不是强行交易
策略触发前必须重新检查研究假设
```

### 41.4 概率验收

```text
信号成功定义提前冻结
历史回放不使用未来数据
有样本外和滚动验证
概率显示样本数和置信区间
概率和实际结果可校准
有价格-only和完整流程对照
有未交易信号记录
```

### 41.5 组合验收

```text
候选具备风险簇标签
同一观点的不同表达可比较
加入组合后的边际风险可计算
期货有保证金、跳空、涨跌停和移仓压力测试
组合可禁止新增风险但允许减仓和平仓
```

### 41.6 绩效评价

不只看收益率和胜率，还要看：

```text
净期望收益
最大回撤
回撤持续时间
平均盈利/亏损
最大不利波动
样本外表现
概率校准
滑点和手续费
收益集中度
风险簇贡献
基准超额收益
未交易候选对照
```

### 41.7 实施路线

```text
V3-P0：数据来源、事实链和时间可见性
V3-P1：四条候选发现通道
V3-P2：股票基本面和期货供需判断
V3-P3：量价分析模块
V3-P4：观察池、等待和预警
V3-P5：概率验证和基准/消融实验
V3-P6：策略适配和Paper交易
V3-P7：组合选择、压力测试和复盘归因
V3-P8：二期完整看图和高级订单流
V3-P9：二期自动实盘上线前的合规、数据授权、接入安全和人工放行门禁（当前不实施）
```

### 41.8 V3 最终业务定义

> QuantPF 是一个以多源、可追溯、点时数据为基础，以新闻、财报、研报、商品供需、现货、基差、期限结构、量价和市场状态为研究输入，以股票买多、期货多空、现货套保/价差为交易表达，以候选筛选、策略适配、等待预警、条件概率、组合选择、Paper/Shadow 和复盘归因为核心闭环的个人多资产交易研究系统。

> 系统不预测未来，不承诺必涨或必跌；系统只在当时可见信息基础上，筛选具有相对条件优势、明确触发条件、可执行交易工具和可计算风险的候选对象。任何真实交易能力仍须独立审批和安全验收，Stage 1 继续只允许 SIM/PAPER/SHADOW/READ_ONLY。
